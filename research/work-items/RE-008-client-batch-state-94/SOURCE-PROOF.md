# Authored source correspondence and qualification plan

The new module completes one batch/buffer operation in the existing MIT
`node94-consensus-admission` package. The original 53-file pre-Rust freeze remains
unchanged. `SOURCE-FREEZE.json` identifies the actual source and input client
before compilation; this document records a source argument, not build results.
Later receipts must state actual outcomes, including failed commands or surviving
mutants. A source/build gate precedes any compilation of this new code.

## Actual dependency and value boundary

The two real manifests are copied at their original relative paths. The baseline
is `56c0ec672bd8fdcfaa80f2db700a61e6240b3663`: 22 of the 26 prerequisites remain
byte-identical; four integration files change and two source/test files are new.
`Cargo.lock` was generated by pinned Cargo 1.94.1 offline, with metadata confirming
exactly admission and the existing MIT `node94-action-signable` path dependency.
`LOCK-AND-FORMAT.json` records that non-compiling step and parser-only rustfmt.
There is no synthetic workspace, registry dependency, build script or dependency
on pending block, QC or bincode contributions. Existing source APIs are preserved.

`ClientBlockTime` retains the three raw u32 words absent from baseline
`SignedBlock`. `TimedSignedBlock` is a typed wrapper, not a native layout or wire
claim. Required `ClientBatchAuthenticator` methods take the complete time-bearing
input. A private `TimedAdapter` routes actual baseline `verify_block` recovery to
that required method; membership, quorum and certificate rules still run through
the real existing verifier. Proposer choice, recovery and full block digest remain
external algorithms under the original proof's normal-return, stability and frame
premises. The test authenticator is explicitly a fixture boundary, not a native
cryptographic algorithm or a caller-selected QC-validity result.

The baseline TC implementation uses a deterministic safe-source failure policy.
Native correspondence excludes competing failing TC children and cancellation
races; the frozen cases use successful or single-child TC paths. Neither source
execution nor another reviewer proves excluded parallel error precedence.

## Gate and state mapping

`verify_client_batch` first admits all nested spans. Its internal routine follows
P-batch in `PROOF.md`: empty; early proof; QC round; prior hash except the first;
actual timed block verification; every transaction byte digest; count and ordered
hashes; all three time words; round and digest update. It does not invent a first
parent anchor or consecutive rounds within the batch. The final proof path repeats
the last digest, verifies child then proof QC, checks both links and the saturating
child successor. The mismatch-only second child digest remains observable.
The opaque native lazy getter is covered by the native frame premise, not modeled
as an additional source callback. Only active typed error fields are exposed.

`push` checks input spans and outer QC round, reserves before semantic mutation,
then advances `last_received` and appends. Unproved batches retain all rows,
including the 101st-row error. Proof verification failures also retain the appended
row and advanced counter. Successful verification sets `confirmed`, takes the
whole pending vector, and only then calls the sink in order. The sink accepts
ownership with `None`, or returns the same item with `Some` on closure; the latter
item and remaining iterator are dropped. Already accepted rows remain owned by the
sink. `ClientBufferView` makes the persisted state visible to this safe adapter;
it establishes no native channel ABI, linearization point or downstream delivery.
The direct two-call empty-stake counterexample remains tag28 then tag1a, with no
authenticator calls. Outer poll reset/reconnection reachability stays unresolved.

Count products for native widths 1, 32, 40, 96 and 184 must fit `isize::MAX`.
Typed span errors and fallible reserve refusal are safe admission policies before
semantic mutation, separate from recovered ordinary native errors. Dependency
allocations, callback panics, destructor behavior and host allocation failure are
not made equivalent to native unwinding. One unit test probes arithmetic limits
without giant allocations. Ten handwritten integration tests exercise the state
witness, time-bearing authentication, ordering, repeated calls and partial handoff;
they supplement, not replace, the independently frozen 221-case corpus.

## Input-only qualification

`driver.rs` receives only opaque sequential IDs and CB1 input frames on stdin.
It cannot read an expected file or semantic case label. It decodes every field,
rejects malformed options, unsorted/duplicate map keys and trailing bytes, and
bounds each vector against remaining bytes before constructing it. Output uses
active error fields, pending/accepted item fingerprints, sink observations and
authenticator traces. Fixture recovery validates an input-derived signature
relation, then the real verifier performs its ordinary membership/quorum rules.
The parent alone reads frozen expected bytes and compares every complete output.
No captured instruction, binary, old evaluator or reference implementation runs.

`build.py` admits the source freeze, all 53 original files and the exact real Cargo
graph before execution. It verifies all 97 pinned toolchain bin/lib files before
and after; records cargo/rustc -vV/rustdoc/rustfmt/clippy and selected linker/SDK
identities; uses a fresh Cargo home, allowlisted environment and offline/locked
commands; and rejects lexical/canonical ancestor Cargo configs or workspaces.
Both `/tmp` and `/private/tmp` build prefixes are remapped. The full host OS/dyld
and SDK are not hermetic. Source ancestors are reported as excluded context:
compilation occurs only in fresh copies of the actual two-package graph.

Planned qualification is debug and release, exact 221-row comparison, eight parent
comparator corruptions, seven malformed frames plus extra-argument rejection and
empty-stream admission, and 20 source mutations compiled in both profiles.
Mutations cover timed authentication, early proof, both directions of QC round,
first-parent/consecutive-round inventions, transaction digest width/count/order,
time width, repeated digests, saturated successor, retained failure state,
100/101 boundaries, proof flush, confirmation/take order, sink closure and child/QC
verification order. A compile failure or crash is not a detected behavioral mutant.
Every actual stdout/stderr is retained as a content-addressed gzip with raw hash.
Only command/cwd/environment metadata uses public logical paths; comparison bytes
are never normalized. A fresh repeat at the same physical build path must reproduce
both profile artifacts; a coordinator's different-directory replay is separately
reported without presuming raw binary identity.

The focused commands run `cargo test --lib --test client_batch` in both profiles
and clippy over actual targets. The old `evidence_contract` runtime test needs its
own retained evidence/artifact setup and is not run by this focused harness; this
is not a complete repository test-suite claim. The dependency's existing Keccak
implementation is credited, not reimplemented or newly proved here. Native
transaction digest correspondence retains the conditional permutation identity
and full initialization/absorption/finalization premises in the frozen proof.
