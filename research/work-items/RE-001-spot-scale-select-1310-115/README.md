# RE-001 — spot scale select 0x5a01310

## User action / basis / harm / nearest work

- **Action that reaches it:** every spot path in the node that needs the
  display scale for a (pair, reference-value) combination reaches this
  selection routine: 15 direct call sites in 13 caller FDEs of the shipped
  binary, including the wrapper immediately in front of the perp pow10
  routine (its call site is at 0x5a010a3, inside FDE 0x5a00fc0).
- **Expected behaviour basis:** the routine's own embedded source locations
  (`l1/src/spot_meta.rs:590:25`, `:119:33`, `:1055:9`) and panic messages are
  the binary's contract for this selection. A reconstruction must reproduce
  the cap `10^max(0, digits-5)`, the table-byte difference factor `10^d`, the
  entry override, and the three panic exits exactly.
- **Loss when wrong:** if the reconstruction guesses the rule — for example
  by copying the perp pow10 routine next door, which has neither the entry
  override nor the table-byte factor — spot quantities are scaled by the
  wrong power of ten exactly on the inputs where the two rules differ, and
  the unwrap / subtract-overflow panic boundaries move.
- **Nearest existing work (repro-case judgement):** merged
  RE-001-pow10-scale-01110-115 (#3315) pins the *perp* selection routine
  0x5a01110 — a different question (no entry helper, no pair/table lookup).
  Merged RE-001-spot-decimal-divisibility pins the divisibility guard at
  FDE 0x29aea00 and open #2832 reimplements that same guard in Rust; open
  #2868 pins the spot iterator. None answers this routine's question
  (override + cap + table-byte factor). No open PR or merged work-item
  cites 0x5a01310, 0x3d1a200 or this packet's question (658 open PRs and
  563 merged work-items swept 2026-11-05).

## What the routine computes (proven from the binary)

1. **Entry override.** The subject first calls the helper through slot
   `0x64e6a78` with `(object, index)`. A nonzero helper result is the
   function's result, returned before anything else happens.
2. **The helper returns only 0 or 1000.** It bounds-checks the index
   against `[obj+0x10]` (panic at `spot_meta.rs:590:25`), loads
   `pair.first = [obj+0x8 + index*32]`, and branches on the tag
   `[obj+0x58]`:
   - tag 0 → 0.
   - tag 1 → 1000 iff `pair.first == [[obj+0x50]+0x8]`, else 0.
   - tag ≥ 2 → derive a key via sub-call 0x47172c0 (arguments
     `[obj+0x80]`, `[obj+0x88]`), look it up via sub-call 0x3ed2180
     (arguments `obj+0x48`, the key, and a pointer to the saved
     `pair.first`): not found → 0; found value ≥ tag → bounds panic at
     `indexmap/src/map.rs:762:26`; found value < tag → 1000.
3. **Cap.** With no override, the subject computes
   `cascade = 10^max(0, decimal digits of the reference value − 5)` by a
   transcribed threshold cascade (direct compares, shift bands, and
   `(10^k − 1) + 1` edges), checked against the closed form on every band
   boundary and 4,000 random u64 values.
4. **Table-byte factor.** The subject re-checks the index against the
   same count (same 590:25 location — shadowed by the helper's identical
   earlier check), loads the 32-byte pair entry, and requires both
   entries to be below the table count `[obj+0x28]`; a violation takes
   the unwrap-on-None panic (`spot_meta.rs:119:33`, message
   ``called `Option::unwrap()` on a `None` value``). From the
   344-byte-stride record table at `[obj+0x20]` it reads
   `d = byte[pair.second*344 + 0x49] − byte[pair.first*344 + 0x48]`;
   a borrow takes the subtract-with-overflow panic
   (`spot_meta.rs:1055:9`).
5. **Result.** `min(cascade, 10^d)`, where `10^d` is built by binary
   decomposition (×10, ×100, ×10^4, ×10^8, ×10^16 with overflow checks);
   leftover exponent bits or a multiply overflow saturate the result to
   the cascade.

## Honest limits

- The bodies of the helper's two sub-calls (0x47172c0 key extraction,
  0x3ed2180 map lookup) are not measured; only their call sites, argument
  setup, and the use of their returns are pinned.
- Object fields are described structurally (offsets, widths, the tag
  dispatch), not named from source; which spot-metadata concept each
  field is remains inference.
- The helper passes a pointer to the saved `pair.first` into the lookup
  sub-call; why the lookup needs it is not observable from these FDEs.
- The subject's own index bounds exit is shadowed by the helper's
  identical earlier check at the same source location; it is pinned as
  present, not as independently reachable.
- Some caller excerpts show only part of the argument setup (the window
  is the smallest clean decode ending in the call); `records.json`
  carries the provenance visible in each chosen window.
- No Unicorn differential run for this packet; the model rests on the
  full-anchor transcriptions, the closed-form agreements, and record
  regeneration.
- The repository-wide `verify_packets` currently fails on two
  pre-existing packets whose LFS `.gz` payloads are not materialized in
  this checkout; that gap predates and is unrelated to this packet.
