# 독립 정적 추적: node #115

## 범위와 표기

- 분석 대상 `hl-node`의 SHA-256은 `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`. ELF64 x86-64 PIE이며 주소는 바이너리의 가상 주소다. 실행하거나 에뮬레이션하지 않았다. 디스어셈블러가 가장 가까운 공개 동적 심볼에서 만들어 붙인 이름은 대상 함수의 이름이 아니므로 사용하지 않는다.
- System V AMD64 ABI 기준이다. `out`은 구조체 반환용 숨은 `rdi`, `V`는 검증기 `rsi`, `P`는 검증기 `rdx`, `K`는 공급자가 반환한 stake set, `S`는 서명자 집합이다. 바이트/워드 크기를 명시하지 않은 필드는 64비트다. 의미 이름은 데이터 흐름에서 추론했으며 원본 타입명은 확인할 수 없다.
- 컬렉션의 첫 64비트가 정확히 `0x8000000000000000`이면 트리 표현, 그 외에는 링/연속 배열 표현이다. `neg` 뒤 `jno`는 음수 일반이 아니라 이 정확한 값의 부호 오버플로를 검사한다. 예를 들어 서명 컬렉션의 배열 항목 크기는 `0x60`, 첫 20바이트가 주소, `+0x18`부터 65바이트가 서명이다 (`0x4e00174`–`0x4e00222`, `0x595fb44`–`0x595fb54`). 트리와 링의 내부 노드 순회는 논리적인 항목 순회로 아래에 요약한다.
- `0x57e8d40` 다이제스트 빌더와 `0x64e0ad8` 간접 호출 슬롯은 경계로만 기록한다. 호출 대상 내부의 암호학적 구현을 가정하지 않는다. `readelf -rW`의 `R_X86_64_RELATIVE`로 다음 슬롯을 확인했다: `0x64e64b0 → 0x595e5c0`, `0x64e8780 → 0x595bc40`, `0x64e6a98 → 0x4d3e1a0`, `0x64e64b8 → 0x57e8bd0`. `0x64dfb50`은 `memcmp`다.

## 호출 순서와 검증기 `0x595f880`–`0x595fd17`

입력은 `rdi=out`, `rsi=V`, `rdx=P`. `V+0x40`은 공급자 질의값 `h`이며, `V+0x00..+0x1f`는 서명 컬렉션이다 (`0x595f891`–`0x595f8a7`). 정상 반환은 `out[0]` 태그로 판단해야 한다. 공통 에필로그는 `rax=out`을 보장하는 명령을 두지 않는다.

1. `provider(out_tmp, P, h)` (`0x595f89a`–`0x595f8a7`). 태그가 `0x2e`가 아니면 그 태그와 payload를 `out`에 그대로 전달하고 끝낸다 (`0x595f8ad`–`0x595f8b3`, `0x595f947`–`0x595f984`). 이 공급자는 실패 시 `0x28`과 `h`를 쓴다. 성공이면 `tmp+8`의 포인터가 `K`다.
2. `collect(out_tmp, K, V)` (`0x595f8b9`–`0x595f8c7`). 태그가 `0x2e`가 아니면 그대로 전달하고 끝낸다 (`0x595f8cc`–`0x595f8d2`, `0x595f989`–`0x595f9d8`). 실패 태그는 `0x2c`, payload는 해당 20바이트 주소다. 성공 payload `+8..+0x1f`가 `S`다.
3. `quorum(P,K,&S)` (`0x595f8f8`–`0x595f909`). 거짓이면 `out[0]=0x07` (`0x595f90b`, `0x595f9dd`). 이후 집합 메모리를 정리한다.
4. 정족수 성공 후에만 `V`의 서명 항목을 순회하며 각각 `sig_check(message, address, signature, K)`를 호출한다 (`0x595faf0`–`0x595fbf4`). 첫 거짓은 `out[0]=0x02` (`0x595fbfa`–`0x595fc02`, `0x595fc53`), 모두 참이고 반복이 끝나면 `out[0]=0x2e` (`0x595fc04`–`0x595fc0b`). 성공/실패 후 집합 메모리를 정리한다. 메시지 프레임의 `+0x00..0x1f ← V+0x48..0x67`, `+0x20..0x2f ← V+0x20..0x2f`, `+0x30 ← V+0x30`, `+0x38 ← V+0x38`, `+0x40 ← V+0x40`, `+0x48..+0x5b ← 항목 주소` (`0x595f8ec`, `0x595fad6`–`0x595fae7`, `0x595fb8b`–`0x595fbc5`). 호출의 `rdi`는 이 프레임 자체가 아니라 `{variant=1, frame 포인터}`다 (`0x595fbca`–`0x595fbe8`). 링에서는 주소가 행 `+0..+0x13`, 서명은 행 `+0x18`이다. 트리에서는 주소와 서명이 별도 슬롯이므로 아래 2단계 정정을 참조한다.

따라서 이 공급자와 수집기를 통한 **정상 반환 태그 집합은 `{0x28, 0x2c, 0x07, 0x02, 0x2e}`**다. 패닉/언와인드/할당 실패는 별도의 정상 태그가 아니다. 오류 복사 시 의미가 확인된 payload 이외의 바이트는 정의되었다고 가정하지 않는다.

## 동등성 helper `0x4e08870`–`0x4e08a19`

`rdi=A`, `rsi=B`. 우선 `A+0x18 != B+0x18`이면 `al=0`으로 즉시 반환한다 (`0x4e08870`–`0x4e088bd`). 길이가 같으면 각각의 `+0` 표현 구분자, `+8` 포인터, `+0x10`, `+0x18`을 사용해 두 논리적 반복자를 만들고 `0x4e550e0`에 `rdi=&iterA`, `rsi=&iterB`로 전달한 결과를 그대로 반환한다 (`0x4e08882`–`0x4e08a10`). 트리와 링 표현이 다르다는 사실만으로 불일치가 되지는 않는다. 이 helper는 위 검증기의 직접 호출 순서에 들어가지 않는 별도 비교다.

### callee `0x4e550e0`–`0x4e55813`

입력 반복자들의 표현 태그는 `+0`, 반복 위치는 `+8..+0x20`, 트리 잔여량은 `+0x40`이다 (`0x4e550ee`–`0x4e55125`). 두 항목을 차례로 꺼내 비교하고 불일치 또는 한쪽만 종료하면 `al=0`; 양쪽이 같이 끝나면 `al=1`이다 (`0x4e55130`–`0x4e551c6`, `0x4e556b6`–`0x4e55730`). 항목 주소의 20바이트 (`0x4e555d7`–`0x4e55601`)와 서명 65바이트, 즉 값 `+0x40`의 1바이트 및 `+0..+0x3f`의 64바이트 (`0x4e55607`–`0x4e55675`)를 모두 비교한다. 링 항목은 주소 `+0`, 서명 `+0x18`, 다음 항목 `+0x60`; 트리 항목은 주소 `node+0x320+20*i`, 서명 `node+8+72*i`다 (`0x4e551b2`, `0x4e5542f`–`0x4e55446`). 잘못된 반복자 상태의 패닉 경로도 있다 (`0x4e557d3`–`0x4e5580b`).

## 서명자 수집 `0x4e00160`–`0x4e00690`

`rdi=out`, `rsi=K`, `rdx=V`다 (`0x4e00171`–`0x4e0018a`). `V`의 서명 컬렉션을 트리 또는 0x60바이트 배열로 반복하고 (`0x4e00192`–`0x4e00225`), 각 항목의 첫 20바이트를 `K`의 주소→stake 맵에서 찾는다. 트리 검색은 `memcmp(...,0x14)`와 20바이트 키, 노드의 키 개수 `+0x13e`, 자식 `+0x140`을 이용한다 (`0x4e00268`–`0x4e003ca`). 배열 표현은 `0x57f54e0`에서 20바이트 키를 검색하며 반환 `0`이 발견, 그 외가 부재다 (`0x4e00424`–`0x4e00432`, `0x57f55de`–`0x57f5605`).

첫 부재 주소는 `out[1..0x14]`에 복사하고 `out[0]=0x2c`, `rax=out`으로 반환한다 (`0x4e00516`–`0x4e00573`). 모든 주소가 있으면 주소들을 집합으로 수집해 `out+8`에 쓰고 `out[0]=0x2e`, `rax=out` (`0x4e00578`–`0x4e0067b`, 수집 호출 `0x4e00673`; 주소 추출과 정렬/트리 구성은 `0x5acc3dd`–`0x5acc3e7`, `0x534932a`–`0x53493bc`). 항목이 0개면 빈 집합을 만들어 성공한다 (`0x4e00520`–`0x4e00578`, `0x53493d4`–`0x53493e3`). 이 단계는 서명 바이트의 유효성을 검사하지 않는다.

## 서명 1건 검사 `0x57e8bd0`–`0x57e8d3a`

`rdi=message`(variant와 프레임 포인터), `rsi=20바이트 기대 주소`, `rdx=서명`, `rcx=K`. 우선 `K`에 기대 주소가 존재하는지 확인한다. 트리 표현은 `0x57e8be3`의 `0-[rcx]`에서 overflow인 sentinel 분기, 루트 `K+8`, 깊이 `K+0x10`, 20바이트 `memcmp` 검색 (`0x57e8bec`–`0x57e8c98`); 배열 표현은 `0x57f54e0`의 반환 `0` 여부 (`0x57e8c9d`–`0x57e8cb5`). 루트가 없거나 키가 없으면 `al=0` (`0x57e8bf0`, `0x57e8c85`–`0x57e8c89`, `0x57e8ced`).

키가 있으면 `0x57e8d40(out_digest, message)`를 호출한 다음 `0x64e0ad8(out_recovery, signature, digest)`를 호출한다 (`0x57e8cb7`–`0x57e8cd6`). 이 두 구현은 경계다. 회수 결과의 태그 바이트가 0이 아니면 에러 객체를 정리하고 `al=0` (`0x57e8cdc`–`0x57e8ced`); 0이면 결과의 `+1..+0x14` 20바이트가 기대 주소와 전부 같은 때만 `al=1`, 그 외 0이다 (`0x57e8cf1`–`0x57e8d28`).

## 정족수 `0x4d3e1a0`와 `0x595bc40`

### 가중 선행 조건 `0x4d3e1a0`–`0x4d3e30d`

`rdi=K`, `rsi=S`; 반환은 `al`이다. `0x4e44c00`은 `S`의 주소를 순회해 `K`에서 찾은 각 stake를 더한다. 없는 키는 건너뛰며 각 덧셈이 carry이면 `UINT64_MAX`로 **포화**한다 (`0x4d3e1af`–`0x4d3e21c`, `0x4e44c60`–`0x4e44c77`, `0x4e44d46`–`0x4e44d5c`, `0x4e44da0`–`0x4e44de3`). 결과를 `signed_stake`라 한다. `0x4e406f0`은 `K`의 모든 stake를 순회하여 같은 방식으로 포화 합산한다 (`0x4d3e21f`–`0x4d3e2e4`, `0x4e40720`–`0x4e40738`, `0x4e40787`–`0x4e40796`); 결과를 `total_stake`라 한다.

결과는 **부호 없는 전체 128비트 정수로 `2 * total_stake < 3 * signed_stake`**일 때만 참이다. `mul 3`은 상·하위 64비트를 보존하고 `total_stake >> 63`과 두 배 하위 워드, `cmp`/`sbb`/`setb`로 비교한다 (`0x4d3e2e4`–`0x4d3e302`). 곱을 64비트로 래핑하거나 포화하지 않는다. 정확히 2/3일 때는 거짓이다.

### 추가 개수 조건 `0x595bc40`–`0x595c268`

`rdi=P`, `rsi=K`, `rdx=S`. 먼저 `0x4d3e1a0(K,S)`가 거짓이면 바로 `al=0` (`0x595bc57`–`0x595bc65`, `0x595bca1`). 참일 때만 `P+0x88`의 f64 값을 읽는다. 유한한 값이면 `t = min(0.7, max(0.0, value))`; 비유한값(NaN 및 양·음의 무한대)이면 `t=1.0`이다 (`0x595bc67`–`0x595bcc2`; 상수의 실제 비트는 `0x459a10=0.7`, `0x4592b0=1.0`). 유한한 값의 `t=0`은 가중 선행 조건이 참인 경우 곧바로 `al=1`이다 (`0x595bcc8`–`0x595bcce`).

그 외에는 `S`의 주소를 `K+0x20` 트리에서 검색해 일치하는 키 개수 `matched`를 센다 (`0x595bcd4`–`0x595bd48`, `0x595bf0b`–`0x595bf89`). `K+0x30`의 64비트 값을 분모 `N`으로 읽어 각각 f64로 변환하고 **`f64(matched) > t * f64(N)`**일 때 참이다 (`0x595bff0`–`0x595c040`). 비교는 엄격한 `>`이며 부호 없는 정수→배정밀도 변환의 반올림이 적용된다. 카운터 덧셈 overflow는 래핑 후 계속하는 것이 아니라 별도 패닉 경로로 간다 (`0x595bd32`–`0x595bd3e`, `0x595c259`–`0x595c266`). 트리 상태 오류도 패닉이다 (`0x595c23d`–`0x595c253`).

**서명 0개:** 공급자 성공 후 수집기는 성공과 빈 `S`를 반환한다. `signed_stake=0`이므로 `2*total_stake < 0`은 `total_stake=0`이어도 거짓이다. 따라서 정족수는 `P+0x88` 값과 상관없이 거짓, 검증기 태그는 `0x07`, 개별 서명 검사는 호출되지 않는다. 단 공급자가 먼저 실패하면 `0x28`이다.

## stake set provider `0x595e5c0`–`0x595e80a`

`rdi=out`, `rsi=P`, `rdx=h` (`0x595e5ca`–`0x595e5d0`). `base=P+0x20`, `last=P+0x60`을 unsigned 64비트로 읽는다. `sat(x)`는 `UINT64_MAX`에서 포화하는 덧셈이라고 하자. 진단 로그의 기준은 `h >= max(sat(base+2000), sat(last+201))`다 (`0x595e5f0`–`0x595e64e`); 이것은 반환 실패 조건이 아니다. 진단 이후에도 같은 선택을 계속한다.

실제 탐색 경계 `q`는 `h < sat(base+2000)`이면 `base`, 그렇지 않으면 `max(base, h-200)`이다 (`0x595e759`–`0x595e78d`). 덧셈은 포화, 비교는 unsigned다. `0x4dce480(P,q)`로 정렬된 이력의 `key <= q` 범위를 만들고 마지막 항목을 선택한다 (`0x595e791`–`0x595e7df`; 배열 upper-bound의 `<=`는 `0x57f35eb`–`0x57f35f1`, `0x57f3654`–`0x57f3663`, 트리 검색은 `0x4d391e0`–`0x4d39228`). 배열 항목은 64바이트다 (`0x4dce527`–`0x4dce54c`, `0x595e7c3`); 트리의 역방향 iterator는 `0x51f5620`이다. 비어 있지 않으면 선택 항목의 값 포인터를 `out+8`, `out[0]=0x2e`, `rax=out` (`0x595e7e1`–`0x595e7e8`, `0x595e7fc`); 선택 가능한 항목이 없으면 `out[0]=0x28`, `out+8=h`, `rax=out` (`0x595e7ea`–`0x595e7ff`).

주소의 도메인상 의미(높이 등)와 구조체 원본 타입명은 추론이므로 낮은 확신으로 남기며, 위 수치·분기·읽고 쓰는 바이트는 명령에 근거한다.

## 2단계에서 발견한 1단계 기록 정정

1단계 원문은 메시지 프레임을 `context`라고 불러 variant 래퍼를 생략했고, 서명이 `항목+0x18`이라는 링 전용 오프셋을 트리에도 일반화했다. 비교 중 `0x513b200`을 추가 추적해 위 본문을 바로잡았다. 트리 반복기는 `0x513b3c1`–`0x513b3d3`에서 `rax=node+0x320+20*i`(주소), `rdx=node+8+72*i`(서명)를 각각 내놓는다. 검증기는 `0x595fb68`에서 이를 호출하여 `rdx`를 유지한 채 `0x595fbf4`에 넘긴다. 링에서만 `0x595fb50`이 `rdx=행+0x18`을 계산한다. `0x595fbcd`–`0x595fbe8`의 메시지 래퍼와 프레임도 별개다.
