# RE-001: pin node #115 the complete Logger and AutoRollLogger vtable maps

Task: RE-001. Bounded question: for node #115, what C++ method is behind
every slot of the Logger and AutoRollLogger vtables, what does each slot
do, and what object layout do the slots read and write?

Artifact: `work/hl-node-115.bin`, node #115, SHA-256
`a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
(matching `provenance/artifacts.json` entry `artifacts/node/115/hl-node`).

## What this resolves

PR #4315 named the C++ methods behind the Dump's vtable slot calls, but
left Logger slots 4/6/7/10 and AutoRollLogger slots 3/4/6/7/9/10 named by
header position or body shape only, the Logger slots-11+ tail unresolved,
the +0x98/+0x130 size fields unexplained, and one live discrepancy: the
shared slot-5 leveled Logv gate reads the AutoRollLogger's OWN +0x11,
while slot 8 was thought to return the wrapped logger's level. This
packet pins all of it:

- Both full 11-slot maps (EnvLogger vtable `0x64cda68`, AutoRollLogger
  vtable `0x64d1f00`), read from the `.rela.dyn` entries (`vtables.tsv`).
  Slots 2 (Close) and 5 (leveled Logv) are the same function in both
  vtables; every other slot has its own body.
- The discrepancy is resolved: AutoRollLogger slot 8 (`0x60552e0`) locks
  the mutex at +0x268 and returns the WRAPPED logger's slot-8 level when
  a wrapped logger is present, else the own +0x11 -- while the shared
  slot-5 gate (`0x5fcd400`) reads the AutoRollLogger's OWN +0x11. The two
  can disagree by design: `SetInfoLogLevel` (slot 9, `0x6055280`) sets
  both, but a direct level change on the wrapped logger alone desyncs
  them.
- The EnvLogger write path end to end: Logv (`0x5fce280`) saves the perf
  level, samples `NowMicros` only when perf_level > 2, formats
  `"%04d/%02d/%02d-%02d:%02d:%02d.%06d %llu "` (at `0x968038`) into a
  0x1f4-byte stack buffer (0x10000-byte heap buffer when the message does
  not fit), ensures a trailing `\n`, sets perf_level = 1 and the TLS byte
  at (fs:0-0x3f8)+0x98 = 1 for the write, locks the mutex at +0x108,
  appends via the writer at +0x28, sets the dirty flag +0x138 = 1, and
  refreshes the cached size at +0x130 iff (size - last) > 0x4c4b3f
  (4,999,999).
- Flush (`0x5fce130`): clears the dirty flag and calls the writer
  Flush/Sync `0x6051a20` only when the flag was set, then refreshes
  +0x130 from the file slot 0x98.
- Close (`0x5fcc410`) is idempotent via closed_ +0x10 and delegates to
  CloseImpl (`0x5fceae0`), which forwards to the worker `0x5fce770`: on a
  writer-Close failure it builds kIOError (code 5) with
  `"Close of log file failed with error:"` (`0x966d00`) + the writer's
  error string.
- The rollover path: AutoRollLogger Logv (`0x6058770`) rolls via
  `0x6058110` when the time check `0x6057310` says so (time-to-roll
  +0xe0 != 0) or when log_max_size (+0xd8) is non-zero and the wrapped
  size is >= +0xd8; after a roll it re-logs the queued headers
  (`0x60572a0`) into the new file. LogHeader (`0x6057000`) queues each
  header into the list at +0xf0 (count at +0x100) before forwarding.
- Construction and destruction: the EnvLogger factory (`0x5fd0de0`)
  allocates the 0x150-byte `_Sp_counted_ptr_inplace<EnvLogger>` control
  block and hardcodes WORD 0x300 at EnvLogger+0x10 (closed_ = 0,
  log_level_ = 3, ERROR_LEVEL); the AutoRollLogger ctor (`0x605a210`)
  takes its level from a stack argument. D0 closes first when closed_
  is clear, then tears down; D1 is the same teardown without operator
  delete.

## Evidence format

- `records.json`: semantic records only -- slot bindings, layouts,
  gate and delegation rules, literal records, guard records, caller
  counts. There is NO per-instruction mnemonic list in the JSON.
  Instruction-level detail lives only in the verbatim whole-function
  excerpts in `excerpts/`.
- `excerpts/`: 41 whole-function objdump excerpts, regenerated by
  `export_excerpts.py` with
  `objdump -d --start-address=<start> --stop-address=<stop> work/hl-node-115.bin`
  run from the repo root (the FDE range for each function is in
  `frames.txt`, from `readelf --debug-dump=frames-interp`). The excerpts
  are the raw objdump text exactly as emitted: instruction mnemonics
  such as `endbr64` are genuine instructions present in the target
  binary, not placeholders.
- Ten excerpts are re-shipped byte-identical from PR #4315's packet
  (`research/work-items/RE-001-dump-slot-method-names-115/`): EnvLogger
  LogHeader, leveled Logv, Logv core, GetInfoLogLevel, SetInfoLogLevel,
  Close, CloseImpl, Logv, and AutoRollLogger LogHeader and
  GetInfoLogLevel. They regenerate to the same bytes from the same
  binary; the remaining 31 are new to this packet.
- `census.py` reproduces `vtables.tsv` (slot values from `.rela.dyn`;
  the file bytes of `.data.rel.ro` are ZERO, so the relocation addends
  are the only source), `callers.tsv` (every direct E8 rel32 call site
  of the slot functions, the rollover path, the writer methods and the
  construction entry points, from a single byte-level scan of `.text`),
  `guards.tsv` (the three devirtualization guards), and `frames.txt`.
- `verify.py` re-checks everything and prints ALL CHECKS PASSED,
  including 3 seeded random gate spots verified byte-for-byte against a
  fresh objdump run AND the raw binary bytes.
- `tools/logger_vtable_115.py` + `tests/test_logger_vtable_115.py`
  model the slot maps, level gates, write path, rollover triggers,
  writer contract and layouts (29 tests).

## The two layouts

EnvLogger, object size 0x140 (inside a 0x150-byte
`_Sp_counted_ptr_inplace<EnvLogger>` control block, EnvLogger at
control+0x10): +0x00 vtable; +0x08 u64 (-1, identity open); +0x10
closed_ (byte); +0x11 log_level_ (byte); +0x18 Env*; +0x20 file object
(size via slot 0x98); +0x28 writer object start AND std::string fname_
(SSO buffer at +0x38); +0x50 shared_ptr control-block release site;
+0x58 pointer to a 0x70-byte heap object; +0x70 heap buffer; +0x98
cached log file size; +0x108 pthread_mutex_t (40 bytes); +0x130
last-refreshed file size; +0x138 dirty flag; +0xd8 vector<shared_ptr>;
+0xf0 heap object deleted via D1.

AutoRollLogger, object size 0x290: +0x00 vtable; +0x08 u64 (-1); +0x10
closed_; +0x11 log_level_ (own copy); +0x18 self-pointer; +0x38/+0x58/
+0x78 three std::string fname parts; +0x98/+0xa8 two shared_ptr
members (roles open); +0xb8 shared_ptr<Logger> logger_ (wrapped
logger); +0xd8 log_max_size (0 = no size roll); +0xe0 time-to-roll
(0 = no time roll); +0xf0 std::list<std::string> of queued header
lines (count at +0x100); +0x108 container (exact type open); +0x158
FileOptions-like struct; +0x268 pthread_mutex_t.

## Open unknowns (not claimed)

- Logger+0x28: the writer object starting at +0x28 vs the fname_
  std::string also at +0x28 (callees address it as writer@+0x28; D0
  disposes a string at +0x28/+0x38) -- the exact object boundary needs
  the writer's own dissection; the writer's internal layout (buffer
  +0x50/+0x58/+0x68, flags +0x88/+0x89) is only partially pinned.
- Identity of the object at Logger+0xf0 and of the 0x70-byte object at
  +0x58; the factory arg3 type and [arg3+0x38] -> Logger+0x20.
- TLS perf-context byte at +0x98 and u64 counter at +0x50: exact field
  names (the timing counter is the log-write-time metric, gated on
  perf_level > 2 -- the name is not verified from the binary).
- EnvLogger+0x08 (-1) and AutoRollLogger+0x08 (-1) field identities;
  AutoRollLogger +0x98/+0xa8 shared_ptr members' roles; the +0x108
  container's exact type; the +0x190/+0x1d0/+0x200 list/string members'
  roles; the roll `0x6058110` full mechanics (rename/open sequence)
  beyond the characterized head.
- Logger vtable slots 11+ tail (EnvLogger slots 11/13/14 have no
  relocation and read as zero; slot 12 points at data 0x64cd8d0; the
  tail holds the shared Configurable GetOption/AreEquivalent
  0x609d760/0x609dc40 at 0x78/0x80; the AutoRollLogger tail holds
  0x6055240 bare ret, 0x6055260/0x6055270 deleting dtors for 0x18-byte
  objects, 0x6057d20 dtor-shaped calling D0) -- unresolved whether
  Logger carries additional virtuals past CloseImpl.
- The two ColumnFamilyData ctor callers 0x5d96cf8 / 0x5d972ab C++ names
  (from #4315, still open).
