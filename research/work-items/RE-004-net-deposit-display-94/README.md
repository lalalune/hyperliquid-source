# RE-004: DEX net-deposit display conversion in node 94

This packet establishes that the DEX net-deposit display path converts the signed raw word to binary64 before dividing by one million, so a reconstruction can preserve the resulting double rounding and forward lookup failures unchanged.

- Component ID: RE-004, quantities and rounding.
- Target release and full SHA-256: node #94, `3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`.

- Claim status: observations for file bytes, FDEs, call, relocation and local branches; inference for the DEX field name and economic unit; the float environment and field provenance are unresolved.
- Scope included and excluded: four selected FDE ranges: the lookup, conversion and copy path, and a separately identified response-dispatch and keyed-object path. The already studied lookup body, the async caller, allocator, clock, logging and error-helper bodies, external effects, target execution and node #115 are excluded. FDEs describe unwind extents and are not by themselves a complete function census.

## Evidence

Coordinates are linked ELF virtual addresses. The wrapper is `[0x2588fa0, 0x258915b)`, file offset `0x2587fa0`, FDE `0x10ce1a0`; its direct call at `0x2588fe5` targets `[0x27d6040, 0x27d645f)`, file offset `0x27d5040`, FDE `0x10fa574`. The wrapper passes a 24-byte input record and a context pointer, and returns the first 96 bytes of the callee's result. The callee also returns two floating timing values to the wrapper; they are not included in those 96 bytes. This description assumes valid memory and normally returning external calls.

The callee invokes the slot at `0x5774708` at `0x27d6159`; its unique relative relocation points to `0x3332270`. Prior packet `fees-growth-modes-94` identifies that external edge as a DEX-name lookup and describes its behavior; it is not reanalysed here. The result tag at stack offset `+0x20` is compared to `0x186` at `0x27d615f`.

| Local decision | Observed consequence |
| --- | --- |
| Lookup returns `0x186` | Read signed 64-bit word at returned pointer `+0x238`, convert it with `cvtsi2sd`, divide by binary64 1,000,000, and store the float at result `+8` with tag `0x186`. |
| Lookup returns another tag | Copy the 96-byte lookup record into the result; the conversion and `+0x238` read are skipped. The error's exact contents and production are the external lookup's contract. |
| Input allocation length zero / nonzero | Skip / call the deallocation slot, respectively, before the ordinary return. |
| Sum of the two timing values is greater than 3.0 | The wrapper may enter logging based on additional logging state. On a normally returning path it still copies the same 96-byte result. |
| Timing sum is at most 3.0, or unordered | The wrapper skips that logging branch and copies the result. |

The complete error-copy and return bytes, including cleanup and unwind paths, are retained. The packet does not assume unused bytes of a successful result have meaningful initialized contents. At `0x27d6170`, the conversion instruction uses the signed 64-bit form; the divisor load at `0x27d6179` resolves to `0x20ae60`, whose file bytes are binary64 1,000,000. The separate binary64 3.0 timing threshold is at `0x20aab8` and is not the quantity divisor.

### Separately observed response format

An independent dispatcher at `0x2a33860..0x2a341df`, FDE `0xda94d0`, uses an i32-relative table at `0x41fdb4`. For input tag 41 its entry at `0x41fe50` targets `0x2a34033`, which loads a binary64 from input `+8` and directly calls `0x2a2e340`. That FDE is `0x2a2e340..0x2a2e47c`, file offset `0x2a2d340`, FDE `0x1122a88`. It passes the key bytes `totalNetDeposit` at `0x42000f`, length 15, and a pointer to the float to an object-field helper. A nonzero helper result takes the tagged error and cleanup branch; zero passes the temporary object to a separate finalization helper. A null initial allocation reaches a failure call. The helper internals and representation of nonfinite floats are not resolved. The generator checks the selected table entry and direct call, not a complete dispatch table or all tags.

The dispatcher's tag 41 and float payload are consistent with an externally named response for the earlier conversion, but **no producer-to-dispatcher data flow is established here**. The two address-disjoint paths must not be treated as a proven end-to-end API path solely because their names and floating layouts agree.

The name `total_net_deposit` is an inference from the shared row layout, not a typed symbol: `fees-perp-settlement-94/serde-names.tsv` binds that key to offset `+0x238`, and the new lookup result is used at the same offset. The key bytes at `0x598c55` are retained. The existing `RE-004-usd-class-transfer-94` packet associates the word with a raw transfer amount. Neither a common live object instance nor the currency of every possible row is proven here.

Assuming round-to-nearest ties-to-even, let `RN` round an exact rational to binary64. For every signed 64-bit input `x`, the observed arithmetic is `RN(RN(x) / 1000000)`. The first rounding is exact for every `|x| <= 2^53`; larger integers can lose low bits before division. For every nonzero input the exact quotient after the first conversion is greater than `2^-20` in magnitude and less than `2^44`; consequently normal finite binary64 values suffice for both operations. Those are integer bounds checked by the generator, not evidence of a particular MXCSR setting.

For example, input `9007199254740993` first rounds to `9007199254740992`. The staged model produces bits `4200c6f7a0b5ed8d`; rounding the exact rational input divided by one million only once gives `4200c6f7a0b5ed8e`. Four of the 49 modeled boundary inputs differ in this way. No claim is made that any of them occurs in a reachable node state.
