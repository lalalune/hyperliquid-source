# Additive supplied-book premium pre-code phase

This phase connects the existing complete impact walk to both exact premium
formulas and one selected producer record. The supplied state has **two ordered
entry slices over one shared slab/count**, a raw oracle/selected target, scale,
mode and selected membership. The result is absence or an active finite premium
tuple, plus the corresponding raw record. Native correspondence is conditional;
safe refusals for invalid scale, zero target and reached cycles are separate
policy outside the native ordinary theorem.

Review [CONTRACT.md](CONTRACT.md), then [PROOF.md](PROOF.md), the compact
[corpus report](corpus/report.json), [PROTOCOL.md](PROTOCOL.md) and
[SOURCE-PLAN.md](SOURCE-PLAN.md). The original published20 files remain unchanged
and are authenticated by [ORIGINAL-DISTRIBUTION.json](ORIGINAL-DISTRIBUTION.json).
This is an additive phase of [PR1422](https://github.com/lalalune/hyperliquid-source/pull/1422),
with original impact discovery credited there, premium context credited to
[PR860](https://github.com/lalalune/hyperliquid-source/pull/860), and selected
producer/storage context to [PR1502](https://github.com/lalalune/hyperliquid-source/pull/1502).
The active row/hash work in draft1460 is excluded. No new PR/count is proposed.

The pre-code evidence covers three complete FDEs,3,355 bytes/811 native rows,
175 structural blocks,141 transfers and22 calls. It separately retains eight
LSDA callsite rows for impact/producer; premium has no LSDA. Both native exports
and FDE/CIE/index links agree with the authenticated target. Fifteen numeric
spans have no overlap with any of80,300 RELA records. The collector rejects
unrecognized relocation widths, binds16 required symbol-zero RELATIVE records,
and records eight opaque callee identities without inferring their behavior.

The independent pre-source corpus has6,034 cases:5,281 active,733 absent and20
explicit safe-policy refusals. Every impact value is derived from actual
logical entry/shared-slab inputs. Twenty ordinary mathematical false models
and two policy-only models have concrete first-difference witnesses. They
are not compiled mutants. The oracle uses unbounded prefix arithmetic and
exact Fraction bisection/adjacent-distance rounding, with no host float,
production imports, captured execution or instruction evaluator.

An early unfrozen draft used separate slab bounds. Before any pre-code gate,
this was corrected to the actual common slab and two cross-tree shared-slot
cases were added. [DRAFT-REVISION.json](DRAFT-REVISION.json) records that
chronology and the retained superseded draft receipt. The final qualification
is a separate run; the earlier draft is not claimed as a gate for this state.

From the repository root, after the additive directory is integrated beside
the actual published original20:

```sh
python3 -B research/work-items/RE-007-impact-notional-walk-94/pre-rust/verify.py
```

Before integration, the author checkout has the older19-file distribution;
pass `--prior /path/to/published/RE-007-impact-notional-walk-94` explicitly.
The checker requires its exact published manifest and ROOT_REVIEW.md. It never
rewrites them. `--gnu` and `--llvm` select existing native providers. The retained
text was generated by GNU Binutils2.47.20260726 and Apple LLVM21.0.0; exact
regeneration compares text, records and tool versions, so different provider
versions can fail text identity without establishing a semantic discrepancy.

The verifier checks198 corruption controls including33 operative native-byte
changes below the SHA gate, both-provider partitions, an independently parsed
PT_LOAD mapping, prior-distribution corruption, numeric relocation overlap,
and mismatched corpus output. It regenerates the complete native tree twice
and the complete corpus twice with normal/optimized Python, varied hash seeds
and time zones. [verification.json](verification.json) and
[VALIDATION.json](VALIDATION.json) retain the actual result and invocation.
Each decoder reads the same authenticated private read-only target snapshot,
checked in full before/after export; no target process is started.

GNU exports, proof and tables are plain text. The second native provider and
large input/answer streams use deterministic gzip with raw/stored identities:

```sh
gzip -dc research/work-items/RE-007-impact-notional-walk-94/pre-rust/native/premium_context.llvm.txt.gz
gzip -dc research/work-items/RE-007-impact-notional-walk-94/pre-rust/corpus/inputs.txt.gz
gzip -dc research/work-items/RE-007-impact-notional-walk-94/pre-rust/corpus/expected.txt.gz
```

No Rust crate/client exists at this freeze. The coordinator must review the
proof/corpus before source authoring, then the actual source/graph/toolchain
before compilation. The complete operation remains conditional on stable
truthful native views, selected lookup results, normal helper/frame contracts
and the stated binary64 environment. It does not recover economic units,
generic hashes, allocation/unwind behavior, original source types/ABI, live
admission, producer completeness or whole settlement. The checker establishes
evidence integrity and finite witnesses; it does not mechanically prove the
manual semantics. No full-node build, captured execution or gate advancement
is claimed.
