# Native value to safe Rust

The pre-code files, manifest and `PRE-RUST-FREEZE.json` remain unchanged. Their source-absence observation is historical. `SOURCE-FREEZE.json` separately binds the five real component files and this phase's harness before any production compilation. The root's independent pre-code gate passed before source creation; its private review also recomputed all 12,724 expectations using separately authored 32-bit-limb arithmetic. That is additional review, not another target or source organization.

`hash_key` uses the two explicit `u64` seed words in the four lanes proved in `PROOF.md`. Its private `round` mutates a four-word array with explicit wrapping additions. In logical order, the first two additions form a and c; the next two XORs form b and d; the later additions form e and f; the remaining rotations/XORs give exactly R. `compress` supplies the pre-v3 and post-v0 message XORs. No generic streaming state is public.

The safe implementation divides the original borrowed input into exact eight-byte chunks and a remainder of length q <= 7. Every full chunk is copied into a fixed local eight-byte array and decoded little-endian. The copy length is exactly eight by `chunks_exact`; there is no data-dependent out-of-bounds access or allocation. The remainder packs q original bytes with shifts 0..48, then ORs one FF at shift 8q <= 56. For q=7 this completes a word, so the implementation compresses it and resets the tail to zero. For q=0..6 it stays a tail of q+1 <= 7 bytes. These are precisely the manual two-call native cases, derived without recreating native registers or exposing a feed API.

The total length byte is `(input.len()+1) mod256`. `wrapping_add(1)` makes host integer overflow explicit; on the qualified 64-bit host valid safe slice length is at most `isize::MAX`, so the native N <= 2^63-1 correspondence domain applies. The final tail has no high-byte bits. It combines with the projected length byte, passes through one compression, XORs lane2 with FF, applies three complete logical rounds and returns all four lanes' XOR. The native shortened final round is covered by the manual cancellation proof. Source computes the whole logical round, so no native instruction evaluator is introduced.

The public component is dependency-free `no_std`, forbids unsafe code and has no callback, process, filesystem or network interface. The separately linked `input_client.rs` uses host standard I/O solely for the input protocol. It has no expected values, oracle import, fixture include or filesystem read. Only `build.py` receives the separate expected stream and performs strict byte comparison. Handwritten integration tests contain selected literal expectations already frozen in `frozen/corpus.json`; tests are not linked into the production rlib/client. Provenance categories never enter client stdin.

`build.py` admits the complete original pre-code manifest, the new source/harness freeze and actual dependency-free Cargo manifest/lock. It uses a new private build directory, a fresh `CARGO_HOME`, an explicit environment, pinned installed toolchain bin/lib bytes and lexical/canonical ancestor Cargo-config absence. Every build copies and rechecks the source. It records actual Cargo metadata and admits exactly the library plus integration-test target, uses offline/locked commands, runs both debug/release profiles and separately links the client to that profile's actual rlib. Two clean source/build roots establish the limited own-build comparison; no original code-byte equivalence follows.

All raw build subprocess stdout/stderr is content-addressed and retained, with commands and environment using documented logical paths. The private mapping stays outside the public packet. No raw output byte is normalized; a private home path causes rejection rather than silent replacement. Host OS/dyld and the complete SDK are not hermetically pinned. Debug Mach-O may still contain canonical object paths after compiler remapping; any inequality is reported, not masked or repaired for a cosmetic match.

The 19 planned semantic source controls are compiled independently in both profiles and compared using their actual client values. The source edits cover each of the frozen mutation-plan categories; a compilation failure is not a detection. Ten strict output comparator controls and eleven malformed input-client streams test different boundaries. All controls remain finite sensitivity checks, not a universal proof. A draft test-name typo caused a `rustfmt` parse failure before any source freeze or compilation; `DRAFT-FORMATTING-FAILURE.json` records the correction and private diagnostic identity. Production library logic was unchanged by that correction.

No table membership/cache/mirror/probe property, seed generation, source-library identity, cryptographic strength, target fault/ABI behavior, generic streaming or component completion is added by host compilation.
