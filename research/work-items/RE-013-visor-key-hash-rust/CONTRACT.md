# Proposed seeded key-hash value component

The proposed real dependency-free crate is `src/visor-key-hash`, with a Cargo-generated lockfile, a safe library, focused tests and README. Production Rust must follow an independent pre-code corpus freeze and parent review. No source directory or Rust code is created during this phase. There is no root workspace, external crate, build script or placeholder CLI/parser.

The proposed API is `hash_key(seed: [u64; 2], input: &[u8]) -> u64`. The two words are exactly the little-endian qwords read from the native seed address, not chosen zero constants or a recovered random-seed generator. Every input byte is significant, including empty input, NUL, FF and invalid UTF-8. Exactly one FF byte is appended implicitly, even if the supplied bytes already end in FF. The result is the complete 64-bit arithmetic value. No generic streaming API is exposed.

The target is solely Visor SHA-256 `89338207c793d80ac2fba75bb0d36c659e2cabc87a94e61a57ba532b8d212e31`. The full outer body is `0x626760..0x6268c0`; its only two calls target the complete call-free feed `0x628d00..0x628ed7`. Together they are 823 bytes and 231 native rows. PR #1009 binds the outer's boundary and selected calls but explicitly leaves hashing opaque. This proposal closes that concrete arithmetic dependency. It does not replace #1009's lookup-return proof or infer table membership.

All additions are modulo 2^64, rotations are 64-bit rotations, and the length word is projected to its low byte in the final block. The normal native domain requires an immutable readable 16-byte seed and an immutable readable nonwrapping input span of length N <= 2^63-1, valid aligned stack/return storage, immutable image constants and ordinary completion of the shown instructions. Seed bytes may overlap input bytes because both remain read-only. Neither may alias the combined live stack interval described in PROOF.md. These are native correspondence premises, not runtime checks of native addresses in the safe API.

The safe borrowed slice supplies host-valid bytes and the result needs no allocation, target pointer, callback, process, filesystem or network interface. Source uses explicit wrapping arithmetic and safe byte accesses. The public function does not recover target ABI, scratch registers, memory-access traces, original compiler, stack layout or fault behavior. The planned qualified host is the installed Rust/Cargo 1.94.1 aarch64-apple-darwin toolchain; other targets remain untested.

The manual equations are derived from actual Visor operand flow and constants. They resemble familiar keyed add/rotate/XOR hashing, but no source-library identity, named algorithm conformance, cryptographic strength or secure-hashing recommendation is claimed. The existing MIT `src/node94-alias` is separate-target research with fixed seed initialization and an additional counter/letter projection; it is not the expected-output oracle and is not imported as a dependency.

Independent expectations will be constructed from whole-message little-endian block decomposition and a logical four-word permutation, not native registers, instruction dispatch, a program counter or simulated target memory. The selected whole input is followed by one FF, divided into complete eight-byte words and a final tail/length word, compressed once per word, then finalized with the proved three-round relation. Oracle source, corpus, input-only format and semantic mutation plan must be frozen before production source. The later client receives only opaque IDs, seeds and input bytes; the build/comparison harness alone receives expected outputs; the input-only Rust driver/client never reads expectations.

Actual lookup cache consistency, occupancy, control mirroring (especially capacities below 16), insertion/growth, key ownership, probe reachability and membership completeness remain unresolved. The selected caller uses returned hash bits, but this function does not select a table, interpret `skip-download`, implement `child-args`, or produce a public CLI effect. The upstream seed/table producer and its TLS/parser/cleanup behavior are outside this value contract. No native-byte or component-gate credit is added.
