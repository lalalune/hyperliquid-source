# Pre-code validation and later build plan

This phase admits native bytes/data and independent expectations before any production Rust. The later component must be a real dependency-free `src/visor-key-hash` Cargo package with a Cargo-generated lock, no root workspace/build hook, and one safe whole-input `hash_key([u64;2], &[u8]) -> u64` API. No streaming or table API is proposed. Only the later explicit root gate authorizes source writing.

`collect.py` authenticates the complete Visor snapshot and credited main-base packets, independently maps ELF VAs through PT_LOAD, binds actual full FDE/CIE bytes, scans every RELA writer, and retains complete GNU/LLVM exports. Both native byte partitions must agree with the same admitted snapshot. Value scope is the two complete outer/feed bodies; the full lookup and caller are context only. Anchor and data controls below whole-image/body hashes test operand/binding integrity, not native execution or universal semantic correctness.

`corpus.py` independently decomposes the whole message `input||FF` into little-endian eight-byte words and a tail/length word. Its functional four-word permutation is mathematical, with no native instruction/reg/flag state or source-library dependency. All 264 seed pairs and 12,724 deduplicated cases are fixed before Rust. They cover seed bit/carry extremes, every single input byte under ten seeds, block/tail and length-byte rollover boundaries including 255/256, single message-bit changes, embedded NUL/FF and invalid UTF-8. The 9,520 quotient/remainder rows, 224 packing basis bits and 66 final-cancellation falsifiers support the manual general proof; their finite checks are not observed target outputs.

Input TSV has exactly four fields: opaque `cNNNNNN` ID, sixteen lowercase hex digits for seed0, the same for seed1, and even lowercase byte hex or `-` for empty. Output TSV has ID and sixteen lowercase hex digits for the actual u64 value. All records use TAB and LF. `provenance.tsv.gz` contains semantic categories separately and is not given to the input-only client. Neither expected values nor hashes/categories enter the Rust driver/client. Only the Python build/comparison harness reads the separate expected stream.

The pre-code checker must reject changed image identity, altered native operands/literals, rebound bad FDE start/size/CIE link, overlapping/duplicate RELA bindings and false/truncated native exports. It must compare regenerated native/corpus files byte-for-byte with retained files, and the pre-code gate explicitly requires source absence. After Rust exists the same static checker may run without that explicit source-absence flag; source/build admission will be the later build harness's responsibility. Historical source absence is never reported as a current property after source is written.

The future Rust implementation must compile with the pinned actual 1.94.1 toolchain, offline/locked, in two clean build roots and both debug/release profiles. The full source, driver and build harness will be separately frozen before compilation. Actual package metadata, Cargo config lexical/canonical ancestors, symlinks, compiler/sysroot/linker/SDK inputs and explicit environment must be audited. The separately linked input-only client must call the actual crate, and retain every raw output. Host allocation/OOM, target ABI/memory traces and Linux binary equivalence are outside the value API. Debug Mach-O path differences are retained rather than masked or cosmetically retried.

Planned compiling semantic controls include: zero both seeds; swap seeds; duplicate one seed; wrong seed XOR constant; omit FF; append a second FF; feed the suffix before input; treat NUL as termination; decode words big-endian; omit the final length byte; use N instead of N+1; project the wrong length byte; fail to compress at original tail length7; use two or four final rounds; alter a rotation; omit the pre/post message-word XOR; and truncate the result to32 bits. Exact source mutations and witnesses will be bound after the source freeze. A control only counts if it compiles and its actual value output differs; compilation failure is retained but never credited as semantic sensitivity.

Handwritten tests will separately exercise exact bytes, arbitrary seeds, empty/NUL/FF behavior and boundary examples. Strict comparator controls will alter rows, IDs, seed/input parsing, values and final LF. Finite matching and own-build byte equality remain host qualification only. No captured program or captured instruction evaluator will run, and no component completion or new native-byte credit follows from this work.
