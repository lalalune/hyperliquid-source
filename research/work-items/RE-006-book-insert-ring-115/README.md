# RE-006: node #115 book insert path (register or ring append) with the tree next function that feeds its cached argument

The two twin insert-path bodies of node #115 (`0x5911890`, `0x5911b30`) and the tree next function they call (`0x4e188f0`, run as real bytes on hand-built trees) can now be rebuilt as executable Python specifications. The owner specification predicts every callee call (key construction, level lookup, level operation, tree range, tree next, shared insert, track recorder, ring grow, order copy, panic) and every byte of the level record and ring for 10,436 generated cases with 0 mismatches; the next specification predicts the return pair and every changed state word for 5,000 cases with 0 mismatches. This fixes from #115 bytes the signed price key, the book-half selection, the register-versus-append split, the low-byte flag test that gates the cached argument, the carry word and argument each arm hands to the shared insert, the 32-byte ring element layout and index arithmetic, and the exact B-tree range-iterator step (ascent, descent, exhausted test, panics) behind the derived argument.

- Target release and full SHA-256: node #115, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
- Source commit / reference commit: `0781ce04826eeefd89fe336cb8ea073be0c1de30` / no reference source is used
- Claim status: observation for the byte-level facts and the comparison counts; inference where the Results section says so; unresolved points are listed there
- Scope included and excluded: included are the two owner bodies (663 bytes each, 150 of 157 instructions stepped; the other 7 are the unwind cleanup block) and the tree next function `0x4e188f0` (431 bytes, 104 of 111 instructions stepped). Excluded, and stubbed with recorded arguments in the owner harness: key construction `0x4dc42f0` / `0x4dc52b0`, level lookup `0x4da5f90` / `0x4da7010`, level operation `0x518e690`, range builder `0x4dce580`, shared insert `0x58df360` / `0x58df790`, track recorder `0x4dbe910`, the four insert caller bodies, the ring grow helper behind slot `0x64e27a8`, the copy import in slot `0x64df508` and the panic routine behind slot `0x64df6a0`. In the next harness only the panic routine behind slot `0x64df830` is stubbed.

## Reproduce

From the repository root, on Linux with Python 3 and the pinned artifact in place:

```sh
python3 tools/book_insert_ring_115.py --out research/work-items/RE-006-book-insert-ring-115
python3 -m unittest tests.test_book_insert_ring_115
cd research/work-items/RE-006-book-insert-ring-115 && sha256sum -c MANIFEST.sha256
```

The tool checks the binary digest first and fails on any other input. It reads ELF bytes through `tools/elf_index.py` and `tools/fde_extents.py`, parses no disassembler or ELF dump text, calls no external program and never executes the binary. It takes about 75 s and about 0.5 GB. `--cases` (default 5200 per owner), `--next-cases` (default 5000) and `--sample` (every Nth case is kept in the case tables, default 4) scale the proof. Two runs with different hash seeds and time zones give identical bytes. The unit tests take about 60 s.

Generated files: `evidence.json`, `measure.json` (the counts quoted below), `cases.tsv`, `outcomes.tsv`, `owners.tsv`, `owner_differences.tsv`, `mutants.tsv`, `variants.tsv`, `controls.tsv` for the owners, and `next_cases.tsv`, `next_outcomes.tsv`, `next_mutants.tsv`, `next_variants.tsv`, `equivalent-mutants.tsv` for the next function.

## Evidence

Coordinates are virtual addresses. Both owners are whole FDEs (`0x5911890..0x5911b27` and `0x5911b30..0x5911dc7`, 663 bytes, 157 decoded instructions). `owner_differences.tsv` lists every instruction pair whose decoded shape differs: 4 rows, all call targets (key construction, level lookup and the shared insert, which is called from two sites). Everything else, including every branch target and constant, is identical, so one specification covers both.

Owner entry arguments: `rdi` the book, `rsi` the 0x110-byte order, `rdx` a pointer to a 12-byte record that is passed on to the level operation and later patched into the element, `rcx` an opaque qword for the shared insert, `xmm0` an f64 for the level operation.

1. **Sign guard.** The qword at order `+0xb0` is tested with `js`. A set sign bit calls the panic routine through slot `0x64df6a0` with length `0x2b`, message `0x91f9eb`, argument record `0x64a35e0` and location `0x64a3508`, before any callee runs (0 events in the 295 and 311 panic cases).
2. **Key and level.** The key is the qword when the side byte at order `+0xd2` is nonzero and its two's complement negation when the byte is zero. The book half is `book + 0xa8 + ((side << 5) & 0xffffffff)`, so a side byte above 1 selects a half the specification reproduces from the shift rather than from a boolean. Key construction takes (half, key), the level lookup returns the level handle, and the level operation runs on (level, `rdx`, `book + 0x80`, `xmm0`).
3. **Arm split.** The dword at order `+0xd8` is compared with 1. Any other value takes the registration arm; the value 1 takes the append arm.
4. **Registration arm.** The order is copied (0x110 bytes) and the shared insert runs on (`book + 0x80`, copy, qword at `book + 0x110`, `rcx`, `book + 0x118`, level) with a pushed zero. If the low byte of the level qword at `+0x20` is zero, the level stores 1 there and the insert result at `+0x28`. A flag word such as `0x100` (low byte zero) therefore still counts as unset. The result is returned.
5. **Append arm.** A record {1, qword at order `+0xf0`, dword at order `+0xdc`, 2} goes to the range builder with `level + 0x50`, then the tree next returns a pointer pair. When it returns nonzero, the carry word is 1 and the argument is the qword the second register points at; otherwise the carry word is the level qword at `+0x20` and the argument is the qword at `+0x28`. The order is copied again and the shared insert runs with the same register arguments and two stack words (carry, argument). The track recorder runs on (`level + 0x50`, order `+0xf0` qword, order `+0xdc` dword, insert result) with location record `0x64b6558`, decoded from the `lea` in both owners. Copy bytes 4..12 are patched with the qword at `rdx` and bytes 12..16 with its following dword.
6. **Ring append.** With capacity at level `+0x30`, buffer `+0x38`, head `+0x40`, length `+0x48`: a full ring calls the grow helper first, length is incremented, and the element is written at slot `head + length` reduced by one conditional subtraction of capacity: qword `+0` the saved order `+0xf0` word, dword `+8` the order `+0xdc` word, bytes `+0xc..+0x1c` the patched copy prefix; bytes `+0x1c..+0x20` keep their old value.
7. **Tree next (`0x4e188f0`, 431 bytes, one argument `rdi` = a 7-word state, returns `rax`/`rdx`).** Word 0 is a tag. A zero tag returns 0 at once and leaves `rdx` alone. A tag whose low dword is 1 (the compare is `cmp eax,1`, so `0x100000001` counts) selects a chunk arm over 0x18-byte entries: words 1 and 2 are the current and end pointers; when they are equal the pair of words 3 and 4 is moved into them and the old pair stored into words 3 and 4; if they are still equal it returns 0 with `rdx = 0x10`; otherwise it returns the current pointer, `rdx = pointer + 0x10`, and advances the current pointer by 0x18. Any other tag selects a B-tree range step over nodes with 16-byte values at `+0`, 8-byte keys at `+0xb8`, parent pointer `+0xb0`, parent index `u16 +0x110`, length `u16 +0x112` and edges at `+0x118`: words 1, 2, 3 are the front node, its height and the edge index, words 4 and 6 the back node and index (word 5 is untouched). Equal front and back handles return 0 with `rdx` = the back node; a null front node returns 0 when the back node is null and panics (message pointer `0x64a3748`) otherwise. Otherwise the step ascends while the index is at or past the node length (panic with `0x64a3760` at a missing parent), then returns the value pointer `node + 16*idx` and key pointer `node + 0xb8 + 8*idx`; the new front is the next leaf edge: (node, idx+1) at height 0, or the leftmost leaf of child `idx+1` descended `height` levels with index 0. The descent is unrolled by eight; 100 deep cases (heights 8, 9 and 10) reach its unrolled loop.

Comparison rows are in `cases.tsv` and `next_cases.tsv` (one row in four), outcome counts in `outcomes.tsv` and `next_outcomes.tsv`, control results in `controls.tsv`, spec variants in `variants.tsv` and `next_variants.tsv`, branch and constant flips in `mutants.tsv` and `next_mutants.tsv`.

## Implementation and comparison

`tools/book_insert_ring_115.py` carries its own small x86-64 evaluator (decoder, flags, memory, the instruction forms these bodies and the earlier TWAP packets use, plus `push imm8` and `push m64`) and runs the function bytes. Separately written functions `spec_insert` and `spec_next` predict the stub call sequence and the final bytes. Owner cases come from a fixed linear congruential generator plus 18 hand-written edge cases per owner (negative keys, side bytes 0/1/2/255, kind values 0/1/2/3/0xffffffff/0x100, flag words with a clear low byte, full, empty and wrapped rings, found and not found tree results). Next cases build random B-trees of height 0 to 3 (1 to 11 entries per node) plus deep trees of height 8 to 10, and random chunk states and zero tags. The ring grow stub doubles the capacity (4 from empty), copies the live elements in logical order to a new buffer and resets head to 0; the specification applies the same rule, so grow is an edge of the harness and not a claim about the real helper.

- Cases: 15,436 (10,436 owner cases, 5,218 per owner, and 5,000 next cases), mismatches 0. Owner outcomes per owner: about 2,200 append, 2,700 register, 300 panic. Next outcomes: 1,000 chunk, 500 zero tag, 2,322 tree steps, 725 zero returns on the tree arm (exhausted or null front), 453 panics.
- Negative controls: 90 made, 89 detected, 1 equivalent. Owners: 42 byte mutants (10 conditional-branch flips and 32 flips of the low bit of an immediate operand, each judged by a probe of 300 cases and then 1,500), 15 specification variants (no negation, negation on the wrong side, boolean side, no panic, wrong arm test, whole-word flag test, no cache, cache always, no wrap, wrap on `>`, no grow, ignore derived argument, wrong carry word, swapped patch, length not incremented) and 4 structural controls (wrong digest, address outside every FDE, two addresses that are not FDE starts). Next function: 26 byte mutants (25 detected), 3 specification variants. A mutant that crashes the evaluator counts as detected.
- The one equivalent mutant is `0x4e189e8` (`cmp rsi,8` turned into `cmp rsi,9`): it is reached only when `rsi mod 8` is not zero, so `rsi == 8` never arrives there (`equivalent-mutants.tsv`); a test runs it on the deep cases and confirms it agrees with the bytes.
- Unit tests: `tests/test_book_insert_ring_115.py`, 21 tests including the track location and both next panic pointers decoded from the bytes, the sign guard before any callee, the low-byte flag rule, ring wrap and grow, the low-dword tag rule, branch flips for both functions and corrupted specification values.
- No Rust path is written here; these are executable specifications only.

## Results and limitations

Inferences, kept apart from the observations: the 0x110-byte record is a book order and the level at `+0x20..+0x50` is a cached-argument slot plus a ring of 32-byte elements (the panic location of the earlier pin of these twins is `l1/src/book/level.rs:32:54` and the track location names `impl_insert_order.rs`); the tree next is a Rust `BTreeMap` range iterator (node layout and step match) behind a small enum of iterator kinds; the registration arm is the path for orders that do not add a ring element. These names are not proved by the bytes.

Not established: what the other stubbed callees do, in particular the range builder that fills the state words the next function reads, what the shared insert does with the carry word and the argument, and what the grow helper does exactly. The stack word after the pushed zero on the registration arm is not set by the owner and is not compared. The unwind cleanup block of the owners (7 instructions) and 7 instructions of the next function (the instruction-level gaps are listed by the stepped counts in `evidence.json`) are never entered. The next harness never drives the real range builder, so the link between a real book level and these states is not measured. No progress gate is requested.
