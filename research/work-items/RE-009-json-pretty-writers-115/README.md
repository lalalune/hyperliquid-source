# RE-009: reconstruct the node #115 pretty-JSON writer family used by the state/snapshot output path

- Component ID: abci (state save / snapshot JSON output), work item RE-009
- Target release and full SHA-256: Linux x86-64 node #115, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
- Source commit / reference commit: repository base `0781ce04826eeefd89fe336cb8ea073be0c1de30`; no reference source is copied
- Claim status: inference (behavioural reconstruction proven by evaluation of the original bytes); the names are ours
- Scope included and excluded: the string escaper, byte-slice array writer, object key writer, object key-state closer, struct opener and object closer listed below. Excluded: the buffer reserve helper `0x231e050` and the value serializer `0x2c6c800` (both hooked, see Limits), every caller above `0x22ebc70`, and any claim that a progress gate is met.

With this packet the pretty-printed JSON bytes that node #115 writes for an object key, a byte-slice array,
an escaped string and an object close can be regenerated by plain Python: the six functions are rebuilt as
`ref_escape`, `ref_array`, `ref_key`, `ref_end`, `ref_close` and `ref_begin` in `tools/json_pretty_writers_115.py`,
and 12,000 generated cases (checked against the original machine code run on the shared concrete evaluator, not
against our own expectations) agree byte for byte, including the growth path of the output buffer and every
panic branch, while 46 deliberately wrong models, corrupted code or table bytes and out-of-range inputs are all
detected. The recovered contract is: the writer is a growable byte vector `{capacity, pointer, length}`; the
formatter is `{indent_ptr, indent_len, current_indent, has_value}` at serializer offset `+8`
(the serializer is `{writer, formatter}`, so `has_value` sits at serializer offset `0x20`); the key writer emits
`"\n"` for the first entry and `",\n"` afterwards, then `indent * current_indent`, then the quoted escaped key.

## Reproduce

```sh
python3 tools/artifacts.py verify
python3 tools/json_pretty_writers_115.py --out research/work-items/RE-009-json-pretty-writers-115
python3 -m unittest tests.test_json_pretty_writers_115
(cd research/work-items/RE-009-json-pretty-writers-115 && sha256sum -c MANIFEST.sha256)
```

The tool checks the binary SHA-256 first, reads the ELF only with the shared `Image`/`Machine` helpers of
`tools/decimal_scaled_u64.py` (section map, FDE table, relative relocations, instruction decoder and concrete
evaluator), never executes the binary and calls no external program. Output is deterministic (fixed seeds,
no clocks). Peak memory is a few hundred MB (one 106 MB image copy, sparse byte memory per case); runtime about
one minute. Platform: Linux x86-64 host, CPython 3 standard library only.

## Evidence

All addresses are original ELF virtual addresses of node #115; every FDE start equals the entry (`functions.tsv`
holds start, end, length and SHA-256 of the FDE bytes).

| entry | FDE length | recovered role |
| --- | --- | --- |
| `0x25bf330` | 552 | escape the bytes at `rsi,len rdx` into writer `rdi`: runs of unescaped bytes are copied, others use the 256-byte table read through the relocated slot `0x64e13d8` and the hex digits through `0x64e13e0` |
| `0x25bf560` | 943 | write a `u8` slice as a pretty JSON array: `[`, per element `"\n"` or `",\n"`, `indent*(current_indent+1)`, decimal digits from the pair table at `0x5f1383`, then `"\n" indent*current_indent "]"`; an empty slice writes `[]` and leaves `has_value` 0 |
| `0x26077c0` | 520 | object key: state byte at +1 (1 = first entry), error byte at +0 must be 0 (otherwise the entry branch at `0x26077d1` goes to a panic), writes separator, `indent*depth`, quote, escaped key, quote, sets the state byte to 2 |
| `0x26079d0` | 100 | key-state closer: panics on error byte 1, writes `}` only when the state byte is nonzero |
| `0x22ebc70` | 333 | struct opener for the single-field wrapper: depth overflow panic, depth+1, `{`, key `exchange` (8 bytes at `0x458fc8`) through `0x26077c0`, `: `, value serializer `0x2c6c800`; on success sets `has_value` and calls the object closer |
| `0x232b070` | 311 | object closer: depth 0 panics, depth-1, if `has_value` writes `"\n" indent*depth`, then `}` |

Observations from the bytes (`tables.tsv`): the escape table equals serde_json's table at every one of 256
indexes (b, t, n, f, r, quote, backslash, `u` for the other control bytes, 0 elsewhere including `0x7f`); the hex
table is lower case; the 100 decimal pairs are `00`..`99`; the copy slot `0x64df508` is a `GLOB_DAT` relocation of
dynamic symbol 7, named `memcpy` in `.dynstr`. Three panic slots (`0x64df520`, `0x64df730`, `0x64df848`) are
relative relocations to the panic stubs.

Every buffer write in these functions has the same shape: if remaining capacity is less than the byte count the
reserve helper `0x231e050` is called with `(vec, length, additional)`, then the bytes are stored; the harness
checks that growth is requested only when needed and that every written byte lies below the final length.

## Implementation and comparison

`tools/json_pretty_writers_115.py` has three parts: the pure reference model (`ref_*`), the evaluator harness
(`Emu`: indirect `call *reg` support, `memcpy` hook, reserve hook, a recording stub for the value serializer),
and the driver that generates cases, compares, runs the negative controls and writes the evidence.
No Rust path or Cargo build exists for this packet (not yet implemented); the reconstruction is Python.

| group | cases | returned | panicked | reserve calls |
| --- | --- | --- | --- | --- |
| escape `0x25bf330` | 3,600 | 3,600 | 0 | 13,582 |
| array `0x25bf560` | 2,600 | 2,593 | 7 | 45,264 |
| key `0x26077c0` | 2,200 | 2,159 | 41 | 11,381 |
| key closer `0x26079d0` | 400 | 300 | 100 | 23 |
| close `0x232b070` | 1,400 | 1,318 | 82 | 618 |
| open `0x22ebc70` (key writer, escaper and closer run for real) | 1,800 | 1,792 | 8 | 10,433 |

Each case sets the initial writer capacity to 0..4096 bytes beyond a short random prefix, so the growth branches
run, and compares output bytes, final formatter/state bytes, and for the opener the call wiring and return value
with the reconstruction. `groups.tsv` carries a SHA-256 over the full per-case stream, `cases.tsv` the first 100
cases of each group.

Negative controls (`controls.tsv`, 46 total, all detected): 24 one-byte code or immediate corruptions in the
original functions (quotes, newline, separator immediates, brackets, braces, thresholds, inverted branches), 5
corrupted table bytes, 14 wrong reconstruction models, and 3 out-of-range or corrupted-input checks (start address
outside every FDE, start inside data, corrupted binary digest).

## Results and limitations

Machine-readable counts are in `measure.json`: 12,000 cases, 46 negative controls, 46 detected. All
reconstruction agreements held; the tool aborts if any case differs or any control is missed.

Limits. (1) The reserve helper `0x231e050` is modelled only as "capacity becomes length+additional"; its real
growth policy and allocator are not claimed. (2) The value serializer `0x2c6c800` is a recording stub returning 0 or a
nonzero error value; the 59-field exchange payload behind it is outside this packet. (3) `memcpy` is the dynamic
symbol; its body is not analysed. (4) Roles such as "state/snapshot output" rest on the earlier object-key and
snapshot packets and on the `exchange` key text; no runtime was observed. (5) The error byte test at `0x22ebcd3`
after the key call is structurally unreachable here (the key writer never sets it), so that branch is not exercised.
No progress gate is requested.

Next question: the real value serializer `0x2c6c800` and the reserve helper `0x231e050` growth policy, so the
complete `exchange` object framing can be reconstructed end to end.
