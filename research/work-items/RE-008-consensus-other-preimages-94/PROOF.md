## Serialization relation

Let `V(x)` be the existing little-endian unsigned integer encoding: one byte for x<251, fb+LE16 for x<65536, fc+LE32 for x<2^32, and fd+LE64 otherwise; u32 has only its first three cases. Let `v(x)` be its length. `A` is 20 uninterpreted address bytes and `H` is 32 uninterpreted hash bytes. Every preimage starts with the literal 29-byte ASCII `Hyperliquid Consensus Payload`. The separately passed 13-byte `consensus msg` is a timing label, not a preimage field.

## Sizing, success and allocation induction

The common dispatcher seeds size counter1 for the enum tag, measures every selected field in serialization order and allocates the resulting D bytes; writer Vec starts length0/capacityD. Every subtree measures exactly its actual writes under stable inputs. Under D+29<2^63, truthful nonwrapping counts, ordinary successful allocation with fresh disjoint storage, accessible input and preserved frame/live aliases, all arithmetic/remaining-capacity guards stay on their non-error sides and growth is unreachable. Each successful writer returns raw status8; intermediate failure checks prevent subsequent field calls, with error payload words treated as active/opaque only. No claim that machine-copied inactive words are initialized. Panics/unwind remain outside this normal-success theorem, and no generic no-return assumption is needed to eliminate them under the domain.

The concat full FDE48454d0..484565a sums the two lengths with overflow/sign checks, allocates exactlyD+29, and copies prefix then encoded payload. Native allocator policy is deliberately opaque; own Rust will return allocation/length errors rather than mimic panic/unwind payloads.


The imported `memcpy` at slot0x576dfe0 is assumed to implement ordinary exact-copy/frame semantics: for valid readable source and writable destination spans of n bytes that do not overlap, it copies exactly source[0:n] into destination[0:n], leaves source and all memory outside the destination unchanged, and returns normally under the ABI. This applies to concat at48455dd and finalizer context/output copies at4f59e65/4f5a02b. Binding the import name does not prove its implementation; normal return and register preservation alone are insufficient.

## Frame and representation premises

The initial payload, nested rows/nodes, reachable active fields and all required input buffers are accessible and stable for both the sizing pass and the writing pass. They do not alias serializer state, output allocations, local frames, caller outputs or each other in ways that allow writes to change later reads. Each allocation succeeds with fresh sufficiently large, disjoint writable memory. The sum D+29 is strictly below2^63, every array pointer addition and96*N is nonwrapping and within its live allocation, and every selected object has its stated valid discriminants. No foreign/concurrent mutation occurs. These are assumptions, not allocator, ownership or concurrency theorems.

Calls obey the x86-64 SysV saved-register/stack contract. The timing/prelude helpers4ee3800 and4ee3730 return normally and preserve all payloads, serialized Vec fields/contents and local result words that they can reach via previously escaped pointers. The same preservation condition applies to the prior caller helpers, optional QC verifier, membership lookup/comparison, and opaque allocation/deallocation/signing/recovery callees, restricted to the live fields claimed across each call. An apparent absence of explicit stores in a caller does not prove such preservation. `records.json` inventories every call in every selected full FDE; opaque implementations and LSDA/unwind behavior are excluded. The six caller bodies establish only the selected digest handoff/order on traces reaching it, not independent correctness of all their other gates.

For the inline map/set iteration, each node has k<=11 keys, a consistent parent pointer/index, and either no children at height0 or k+1 accessible children of height h-1. The root parent is null. Reachable nodes form a finite acyclic tree; the supplied height is truthful and the supplied count is the sum of all node-key counts. Native field offsets and row widths are as listed above. In-order sequence means recursively child0,key0,child1,key1,...,childk. Source ordered slices must equal that sequence; no sorting, duplicate removal, comparator identity or constructor is inferred. Key-order invariants may hold in a producer but are unnecessary to this sequence projection. Empty trees encode count0; the malformed null-root/positive-count counterexample is explicitly outside this domain.

At every iterator header, remaining count equals the number of not-yet-emitted elements, the cursor is immediately before the next in-order element, and the candidate height is the number of levels ascended. Descent through child0 reaches the leftmost leaf in exactly the recorded height. A leaf slot advances by1. An exhausted node ascends via its parent index until a parent key remains, then prepares the leftmost cursor in that key's right child before emitting the key. Valid parent indices and equal child heights preserve the invariant. Each successful emitted entry decrements count once. Therefore allN entries are visited exactly once, in order; neither panic sentinel is reachable. The sizer follows the same transitions and counts exactly the writer's field lengths. Tree metadata is not serialized; key/value bytes and iteration order are.

For the timeout array, afteri successful iterations, the row pointer is base+96*i and remaining output corresponds to the suffix of entriesi..N. The writer uses end=base+96*N and moves row+0x58+8 to the next row; the sizer subtracts96 from its byte countdown. On the valid nonwrapping array domain these terminate after exactlyN rows and have the same encoded length.

For every subtree, prove by field order and loop induction that starting at lengthl with remaining capacity at least its measured size appends exactly the stated bytes, finishes at l+size, and returns raw status8. The leaves require1/3/5/9,20or32 bytes as appropriate. Every compound body guards its next field on status8; the successful-domain induction makes each guard true. Starting common capacityD and length0 therefore excludes every growth call. Overflow checks are excluded by D+29<2^63 and nonnegative prefix sums. Unwinding, allocation failure and malformed inputs are outside this theorem; the safe source API can refuse its own length/allocation errors without claiming target ABI equality.

No byte of old fixtures' SHA256 signing oracle is an expected native digest. Signature limb interpretation here is the observed little-endian memory projection, not a claim that these are canonical secp256k1 scalar encodings. The old opaque SignatureBytes72 abstraction can carry this projection, while signing/recovery remain separate.
