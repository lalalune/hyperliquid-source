## Bounded question

What does the routine at 0x5d50470 do when it clears one container:
which gate selects the free-only path, how are the pair array's
elements ordered and deduplicated, which elements get disposed and in
what order, and what happens to the object's head, chain and buffer?

## Semantics

Object layout (rdi = object pointer): +0x00 head function pointer,
+0x08/+0x10 its two arguments, +0x18 chain head, +0x20 flag byte,
+0x28 pair-array begin, +0x30 pair-array end, +0x38 pair-array
capacity end. Each array element is 16 bytes: +0x00 argument qword,
+0x08 disposer function pointer.

1. Flag gate. Flag byte +0x20 zero: skip straight to step 6 (free
   phase) — no sort, no dispose, no virtual phase, and +0x00/+0x18
   are left untouched. Flag nonzero: the flag is cleared first, then
   the full clear runs.
2. Sort phase (flag-set path, non-empty range only). The sort callee
   0x5d4a3f0 is called with (begin, end, depth), where depth is
   2*floor(log2(element count)) — or the literal -2 left in the
   register when the byte count is below 16. Then: byte count at
   most 0x100 (16 elements) calls 0x5d497e0 with (begin, end);
   otherwise 0x5d497e0 is called with (begin, begin + 0x100) and an
   inlined insertion sort runs over [begin + 0x100, end), ascending
   by unsigned (first qword, second qword), shifting larger pairs
   right until each pair's slot is found; the inner walk has no
   lower-bound check. The two callee bodies are not pinned here —
   only their call sites and arguments; the final-insertion-sort
   shape is inference from that call pattern plus the inlined tail.
3. Unique phase. Adjacent pairs are scanned from the second element;
   the first pair whose both qwords equal its predecessor is the
   first duplicate. With no duplicate, every element is kept. With
   a duplicate, later pairs differing from the last kept pair in
   either qword are copied forward in order and equal pairs are
   skipped, leaving exactly one copy of each distinct pair, sorted.
   The duplicate-found path's end-equality test on the write cursor
   cannot be true (the read cursor never passes the old end) and is
   recorded as a dead branch.
4. Destroy phase. Each kept pair is disposed in array (sorted)
   order by calling its +0x08 qword with its +0x00 qword. Duplicate
   copies beyond the new end are never disposed; their storage is
   abandoned with the freed buffer.
5. Reset and virtual phase. The array end (+0x30) is set to begin
   when it differs. Then, when +0x00 is non-null, it is called with
   (+0x08, +0x10); then the +0x18 chain is walked — each node is
   called with (node +0x08, node +0x10) and deleted with size
   0x20 — and afterwards +0x00 and +0x18 are zeroed. This phase
   runs on the empty-range path too, but never on the flag-clear
   path.
6. Free phase. When +0x28 is non-null, operator delete is called
   with (+0x28, +0x38 minus +0x28). The routine never writes +0x28,
   +0x30 or +0x38 afterwards; the buffer pointer is left dangling.
   The routine never returns normally: it tail-jumps to 0x61bd0e0
   with the object pointer, whose body is not pinned here.

## Unknowns

- Bodies of the sort-phase callees 0x5d4a3f0 and 0x5d497e0 and of
  the tail callee 0x61bd0e0; only their call sites and arguments
  are pinned.
- Identities of the head, chain-node and element-disposer callees
  and the element type names; only the call protocol is pinned.
- The purpose behind disposing each distinct pair exactly once in
  sorted order; the disposal order and the once-each rule are
  observed, the reason is not claimed.
- Behavior when the pair-array byte count is not a multiple of 16;
  the depth literal -2 for a sub-16-byte count is pinned, nothing
  further is claimed.
