On the cited all-collection worker path the stack adapter is initialized with tag 1, current pointer from state `+0x7c8`, end pointer from state `+0x7c8 + state[+0x7d0]*0x510`, and a zero active-row pointer. If the range contains a valid first row whose word `+0x10` is nonzero, `0x2344708..0x2344727` advances the row pointer by `0x510` and transfers to `0x2344885` with the original row and index zero. At `0x234489e..0x23448b3`, the adapter computes `N = 10000 * row[+0x50] + 0`, with explicit multiplication-overflow and addition-carry branches. On the selected normal allocation continuation, `0x2344904` clears EBX and `0x234498c..0x23449a0` stores the first output pair `(0, N)` and count 1. It is then available to the previously documented 16-byte entry loop if the output reaches that loop unchanged.

For this pair, #7119's first-word-not-1 branch computes `floor(N/10000)`. Given the no-overflow premise, it equals the original row word `+0x50`, and its remainder is zero. A successful lookup still additionally requires that quotient be within state `+0x7d0`, that the row reached by that quotient satisfy the consumer's equality/bounds checks, and that helper calls return normally. In particular, this packet does not assume the first physical row's field equals its position.

This is a conditional static producer/consumer relation, not proof of live execution, valid on-disk state, first blockchain record, checkpoint recovery, snapshot correctness or root alignment. Empty ranges, empty rows, later entries, overflow, aliasing, allocator failures and intervening mutations remain outside this path. No target executes and no component gate changes.
