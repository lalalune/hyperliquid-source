0x5f6b620 do to the accumulator counters, under what gate, and who

## Semantics, stated literally

The leaf takes (base, element) in (rdi, rsi) and returns void. All
arithmetic is wrapping 64-bit.

* Gate: the byte at element +0xb5 is compared against zero
  (0x5f6b624). A zero byte returns at once (0x5f6b62b jumps to the
  `ret`); no counter is read or written.
* Otherwise, in order:
  * base +0xfb0 becomes old base +0xfb0, plus element +0x88, minus
    element +0x80 (0x5f6b62d..0x5f6b642);
  * base +0xfc0 is decremented by one (0x5f6b650);
  * base +0xfb8 is decremented by element +0x88 (0x5f6b649..0x5f6b658).
* Nothing else is touched: in particular the leaf never reads or
  writes base +0xf88, +0xf90, +0xf98, +0xfa0 or +0xfa8.

In the caller terms of the accumulation-leaf item (base = obj +0x40,
so base +0xfb0 is obj +0xff0): obj +0xff0 becomes old obj +0xff0,
plus element +0x88, minus element +0x80; obj +0x1000 is decremented
by one; obj +0xff8 is decremented by element +0x88 — but only when
the element's +0xb5 byte is nonzero.

## Relation to the accumulation leaf (not a re-claim)

The accumulation leaf adds element +0x10 to base +0xf88, element
+0x90 to +0xf90, element +0x98 to +0xf98, element +0x80 minus
element +0x88 to +0xfa0, element +0x88 to +0xfa8, element +0x80
minus element +0x88 to +0xfb0, one to +0xfc0, and element +0x88 to
+0xfb8. This leaf exactly reverses three of those eight updates
(+0xfb0, +0xfb8, +0xfc0) and leaves the other five untouched. The
+0xb5 gate byte is the same offset the lazy-materialize predicate
sets to 1 on attempt, so the reversal applies only to attempted
elements and never to flag-zero elements; the callers' timing —
when a reversal runs relative to an accumulation — is site-only
and is NOT claimed here.

## Consumers and argument setup (site only)

* 0x5f53747 (inside 0x5f52c50): base = the qword at the caller's
  stack slot rsp +0x30 (loaded at 0x5f53742); element = the pointer
  loaded from the loop cursor [rbp] at 0x5f536ff, whose +0x8 field
  is the key compared just before the call. The leaf returns void;
  the caller then reloads its loop bound and advances rbp by 8.
* 0x5f537af (inside 0x5f52c50): base = the qword at rsp +0x30
  (loaded at 0x5f537aa); element = the pointer loaded from the loop
  cursor [rbx] at 0x5f5376b, whose +0x8 field is the key compared
  just before the call. The leaf returns void; the caller advances
  rbx by 8 and loops back.
* 0x5f5390a (inside 0x5f52c50): base = the qword at rsp +0x30
  (loaded at 0x5f53902); element = rbx, the loop's current element,
  whose +0x8 field is the key compared just before the call
  (loaded into the key register at 0x5f538cd). The leaf returns
  void; the caller advances its loop index by 8 and jumps back to
  the loop head.
* 0x5f45d50 (inside 0x5f45cf0, tail jump): base = the lookup
  function's incoming rsi argument (saved in r9 at entry,
  0x5f45cf3, and moved to rdi at 0x5f45d4b); element = the lookup
  function's incoming rcx argument (moved to rdi at entry,
  0x5f45cf9, and moved to rsi at 0x5f45d47). The lookup function
  returns through the leaf; there is no post-call code in the
  caller on this path.
* 0x5f45df6 (inside 0x5f45cf0, tail jump): base and element are
  the same two incoming arguments, established the same way
  (r9 at entry, moved to rdi at 0x5f45df1; incoming rcx moved to
  rsi at 0x5f45ded). The lookup function returns through the leaf;
  there is no post-call code in the caller on this path.
