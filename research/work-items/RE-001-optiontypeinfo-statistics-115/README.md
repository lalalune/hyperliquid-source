# RE-001: node #115's OptionTypeInfo::AsCustomSharedPtr<Statistics> record

## Bounded question

How does node #115 build the OptionTypeInfo record for a custom
shared_ptr Statistics option, and how do the record's two create
hooks resolve that option by name?

## Answer (pinned)

- **Builder** (`0x6071520`, 426 bytes): `rocksdb::OptionTypeInfo::
  AsCustomSharedPtr<Statistics>(offset, verification, flags)` fills
  a 0xb8-byte record: offset at +0x00 (esi), 16 zero bytes at
  +0x08, the create-hook pair at +0x18/+0x20, zeroes at +0x28..+0xa8,
  type 22 at +0xa8, verification at +0xac (edx), flags at +0xb0
  (ecx). The hooks are the std::function manager `0x606fa80` and the
  invoker `0x60780a0`, copied from the GOT RELATIVE slots
  0x64eda58/0x64eda60 — link-time constants, not computed. The
  builder first fills an identical record as a stack temporary at
  rsp+0x10 and writes out field-wise. Its one manager call
  (0x607161e, op 2 = clone_functor) is a proven no-op: the lambda
  captures nothing.
- **Manager** (`0x606fa80`, 45 bytes): the std::function manager for
  the lambda. Op 0 (get_type_info) writes the typeinfo object
  0x64d2d38; op 1 (get_functor_ptr) copies the functor pointer; ops
  2 (clone), 3 (destroy) and anything else return 0 without touching
  memory. Open PR #3386 records this address as the manager and
  explicitly excludes it from its packet; its internals are pinned
  here for the first time.
- **Invoker** (`0x60780a0`, 267 bytes): the std::function _M_invoke
  for the lambda. When the id-string (rcx) has length 2 and starts
  with "id" (word 0x6469) and the name-string (r8) is empty, it
  releases the shared_ptr at *(dest_slot) — zeroing the slot and
  running the counted release (packed 0x100000001 fast path with
  vtable dispose/destroy, otherwise the use-count decrement with the
  0x64ed290 atomicity selector and the 0x5d35070 dispose helper when
  the old use-count was 1) — writes an empty Status and returns.
  Otherwise it forwards to the create-by-name host `0x6077820` with
  (out, config_options, name_string, *dest_slot).
- **Create host** (`0x6077820`, by contract only): pinned by open PR
  #3386, not re-derived here. Empty name or "BasicStatistics"
  constructs a fresh StatisticsImpl via ctor 0x6071a00 (open PR
  #3572); a registrar-built name match releases the slot; any other
  name goes through the registry lookup 0x609e510 with translator
  0x6076b20 and Status builder 0x61cf670 (open PR #3440).
- **Installer**: the builder's sole direct caller is 0x6074d8f in
  the options-table builder (FDE 0x6073060..0x6075ae2, not pinned),
  installing the record with offset 0, verification 3, flags 1.

## Census correction

The RE-002 vendor census matched this body 413/426 (96.95%) to
`AsCustomSharedPtr<FileSystem>`. The GOT-resolved hooks prove
**Statistics**: the manager's kind-0 typeinfo name at 0x975620 is
the `AsCustomSharedPtr<Statistics>` lambda, and the invoker calls
the Statistics create host 0x6077820. The 13 differing bytes are
the hook pointers; the instantiations share one code shape. There is
exactly one copy of this body in the binary.

## Environment limits

This VM has no cargo/rustc, no git-lfs and no Ghidra/Java, so the
repo gates (`make verify`, `make test`, `make catalogue-check`)
could not be run here; the packet is validated only by its own
`verify.py` (digest, manifest, excerpt regeneration, byte-for-byte
gate spots, frames, census reproduction, relocations, literals and
the model tests). The model in `tools/optiontypeinfo_statistics_115.py`
and its tests in `tests/test_optiontypeinfo_statistics_115.py` are
the executable form of the pinned behaviour.

## Open unknowns

See `records.json` "unknowns": the enum spellings for verification
3 / flags 1; the semantic names of the invoker's two string args
beyond their observed roles; the runtime content of the
registrar-built global string at 0x6508980; whether the "id" fast
path means "reset to default" or "release and return empty" in the
caller's terms.
