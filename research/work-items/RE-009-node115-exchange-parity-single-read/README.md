# RE-009 #115 single-read Exchange parity intake

Read and authenticate a named RMP checkpoint once before running the combined 22-slot raw Exchange comparison in [#7683](https://github.com/lalalune/hyperliquid-source/pull/7683). Each comparison can reuse the small temporary projection in place of rereading a whole checkpoint. The final receipt retains the original checkpoint SHA-256 and includes the distinct SHA-256 and size of the temporary projection.

The original byte stream supplies both MessagePack parsing and the source digest. Capture the encoded extent for each selected field and the exact Context height value. Write only new map headers and keys to build the temporary named projection. Preserve the original value bytes, including the distinction between binary32 and binary64 and the sign bit of zero. Retain recent chunks to capture a field across read boundaries. A selected encoded value can be up to 256 KiB. The 22 supported fields are scalar or fixed-field records substantially below this limit on ordinary inputs. Each original comparator still verifies and reads the same original raw reference. The projection remains a scoped input and cannot serve as a complete checkpoint.

Use the directory layout and byte pins for [#7445](https://github.com/lalalune/hyperliquid-source/pull/7445), [#7683](https://github.com/lalalune/hyperliquid-source/pull/7683), and their transitive helpers. From the repository root run `python -B research/work-items/RE-009-node115-exchange-parity-single-read/verify.py --helpers PATH --rustc PATH`. The test compares the complete legacy and projected receipts for matching and differing synthetic input pairs. It measures actual bytes read, preserves a floating-point value crossing a chunk boundary, and tests binary32, stale reference, wrong-height, oversize and trailing data controls. No genuine checkpoint or observed root is included.
