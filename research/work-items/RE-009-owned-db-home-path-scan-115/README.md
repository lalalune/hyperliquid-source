# RE-009: owned_db_home.rs path-row constructor 0x16961b0, `checkpoint` scan and row drop glue (node #115)

Component ID: RE-009 (storage and state roots, `db/owned_db_home.rs`)
Target release and full SHA-256: node #115, `artifacts/node/115/hl-node`, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
Source commit: workspace `origin/main` at the time of the run (no repository file changed; this folder, one tool and one test are new)
Claim status: reconstructed and differentially checked against the interpreted #115 bytes; source-level names and the opaque callees are unresolved (see Limits)

This run shows that the object constructor `0x16961b0` of `db/owned_db_home.rs` is an exact, case-sensitive "path contains the ten bytes `checkpoint`" gate, which turns a rejected path into a panic with the message `OwnedDbDir invalid dir {path}` at `db/src/owned_db_home.rs:21:9`, and otherwise moves the path `String` triple unchanged into a 0x58-byte box that the neighbouring drop glue `0x1696780` releases; so a reimplementation can now model every path length, not only the at-most-24-byte inputs left open by the RE-015 item, as a pure function with a 0x58-byte output layout.

## Scope

Bundle from the exploration target: root `0x16961b0` (1,401 bytes, FDE `0x1069df8`) and member `0x1696870` (241 bytes). The same source neighbourhood adds two FDE-bounded drop bodies, `0x1696730` (79 bytes) and `0x1696780` (231 bytes), because they consume exactly the box the constructor builds. The constructor has no direct caller; RE-015 records it as a relocated object constructor reached from the db-root-open path, and RE-017 lists it in a three-address tuple. Neither item models the search or the drop, and no address of this folder is taken by an open item.

In scope: the length dispatch and the four search loops, the candidate verifier, the panic route, the box layout, the allocation failure route and the drop glue. Out of scope: the callers, the opaque formatter, the allocator, the unwinder and the Once initialiser body.

The tool refuses to run unless the binary digest above matches. It reads ELF sections, relocations and `.eh_frame` through the shared `elf_index` and `fde_extents` parsers and never runs the node. A regeneration takes about 75 seconds. The tests rebuild a small synthetic image from the retained body bytes in `bodies.tsv` and the constants in `references.tsv`, so they do not need the binary.

Observed (from the bytes):

1. Input is a Rust `String` triple at `rdi`: capacity `+0`, pointer `+8`, length `+0x10` (`0x16961c4`, `0x16961c8`). Length `<= 9` skips the search (`jbe`/`jne` at `0x16961d0`, `0x1696217`), length 10 compares the eight bytes `checkpoi` (`0x696f706b63656863` at `0x16961dc`) and the two bytes `nt` (`0x746e`), lengths 11..24 slide that 10-byte compare one byte at a time (`0x16961f0..0x1696210`), lengths 25..73 (`cmp $0x4a` at `0x169628d`) run a 16-lane loop (`0x16962c0..0x16962f3`) and longer inputs a four-block loop with stride `0x40` and guard `0x89` (`0x1696490..0x16966b3`).
2. The lane loop compares the byte at `i` with sixteen `c` (constant `0x4566b0`) and the byte at `i+9` with sixteen `t` (`0x452340`), ANDs and takes `pmovmskb`. A nonzero mask calls `0x1696870` with the 9-byte tail `heckpoint` (`0x47b3d9`, length stored at `0x1696284`). A final window at `n-25` (`0x169631f`) is always examined, so no start position is missed.
3. `0x1696870(state, offset, mask, flag)` answers false when `flag != 0`; otherwise it takes the lowest set mask bit (`tzcnt`), compares the tail four bytes at a time and once more on the last four (`0x16968d0..0x1696892`), clears the bit with `rol` (`0x16968a1`) and repeats; a tail shorter than four bytes uses a byte ladder (`0x16968f0..0x1696957`).
4. A found needle goes to `0x169623f`: it builds `{&String, 0x1696190}` on the stack, passes the compact format entry `0x447e28` (length byte `0x17`, text `OwnedDbDir invalid dir `, then `c0 00` for argument 0) and the location slot `0x6408bd0` (file `db/src/owned_db_home.rs`, line 21, column 9) to slot `0x64df6b8` (wrapper `0x1680e80`), then `ud2`. Function `0x1696190` is the string Display shim: it loads pointer and length from the String and tail-jumps through slot `0x64df720`.
5. Otherwise the formatter slot `0x64e11e0` (callee `0x1560e30`, lock word `0x64ffe60`) is called with the 10 bytes `OwnedDbDir` (`0x47b3e2`) and the path pointer and length; its 48-byte result and the String triple are assembled into `{1, 1, triple, 48 bytes}` and written to a `0x58`-byte allocation obtained from slot `0x64df480`. A null allocation goes to slot `0x64df490` with `(8, 0x58)` and `ud2`.
6. `0x1696780(box)`: if the 32-bit word `0x64f01d8` is nonzero it calls the Once slot `0x64df9f0` with a closure naming cell `0x64f01c0`; it frees the path String (`dealloc(ptr = box+0x18, size = box+0x10, 0)`) when the capacity is nonzero, calls the element-drop slot `0x64e10a0` on `box+0x28`, and frees `ptr = box+0x30`, `size = box+0x28` when that capacity is nonzero. `0x1696730` is the same vector drop on a bare triple.

## Implementation and comparison

`tools/hl_storage_owned_home_path_115.py` holds an offline x86-64 interpreter (decoder, memory, machine; reads the image through the shared parsers) and three independent reference models written from the reading above: `ctor_model` (substring gate, box layout, failure routes), `verify_model` (flag, mask, tail compare) and `glue_model` (drop events). Each case is run on the interpreted real bytes under four different byte fills around the string (0xa5, a cycle of `checkpoint`, all `t`, all `c`), which would expose any read outside the string that happens to complete a needle. Callouts are served by contract hooks: the formatter writes 48 bytes derived from the path, the allocator hands out boxes, and the panic and allocation-error hooks stop the run after recording their arguments.

Case families (all counts are from `routes.tsv`): placement of the needle at every position of every length 10..120 (6,216), random misses with decoys `c????????t` of lengths 0..260 (783), single-byte near misses (520), needle halves at the very start and end (284), 22 boundary offsets around 16/64-byte block edges in six lengths (101), long inputs (300), allocation failure (200), 45 literal path strings, 4,976 direct verifier calls (including every mask bit against matches at other bits) and 2,159 drop-glue runs (500 bare vectors, 1,500 random boxes, 159 boxes built by the constructor itself).

## Results and limitations

- 15,584 cases, all agree with the models: the constructor panics exactly on `checkpoint` containment, builds the 0x58-byte box otherwise, and the drop glue frees what the box describes. 395 of 443 instructions are executed; the other 48 are unwind landing pads, the jump after the noreturn panic call, `ud2` after the allocation error, and two alignment `nop`s.
- Negative controls: 218 single-byte mutations of the four bodies (46 condition flips, 61 branch retargets to the next instruction boundary, 39 immediates, 72 displacements); 187 detected and 31 undetected. All 31 have a stated reason in `equivalent-mutants.tsv`: 17 are landing-pad bytes never entered without an unwind, the others move a length cut-over between two correct search loops, run one more in-bounds block, drop the last needle byte that the pair filter already required (`0x1696284`), or alter a store that nothing reads.
- The tests (55) add wrong models (case-insensitive, nine-byte needle, truncated prefix, 24-byte cap, wrong box word, wrong allocation size, swapped drop order and arguments), byte-level mutants through `detect`, a refused wrong digest, refused out-of-range addresses and a refused unmodelled call.

Limits (unresolved):

- The formatter `0x1560e30`, the allocator `0x6355830`, the panic machinery, the Once body and the element-drop callee `0x1570bf0` are not decoded; the 48-byte value is treated as opaque bytes copied verbatim, and its first three words are called a vector triple only because `0x1696780` drops them that way.
- Field names (`path`, "row"), the meaning of `OwnedDbDir` as a type, and the claim that this is `str::contains("checkpoint")` in source are inferences from the bytes, not from symbols.
- Only the stated 0x58-byte allocation is modelled; unwind behaviour is not (landing pads are never entered).
- No caller was modelled and no run claim is made about which paths real configurations pass. Release #94 was not consulted.
