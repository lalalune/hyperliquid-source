# staking: c-signer jail-time conversion in node 94

This packet establishes that the `voteJail` time adapter returns success only with a nonzero packed date, resolving the zero-date input question at this boundary and recovering date and clock rules needed to reconstruct it.

- Component ID: staking, validator lifecycle and the `CSignerAction::VoteJail` time input.
- Target release and full SHA-256: node #94, `artifacts/node/94/hl-node`, `3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`.
- Source commit / reference commit: `e5c9b6436876b2a4a39daef813171f9879317699` / `999556f6e0a474b8312db96ec3149e1c44e97c23`. The unlicensed reference is a lead only; no code was copied from it. The bounded x86 decoder and interpreter are adapted from the repository's MIT-licensed `tools/staking_stake_accounting.py`.
- Claim status: observed linked ELF bytes, FDEs, relocation entries and bounded interpreter results; the `voteJail` association joins the checked incoming call sites to the earlier signer-action work. The meaning of the parsed-field offsets is inferred from the operations and checked examples. Unreached code and real input reachability remain unresolved.
- Scope included and excluded: six selected FDEs at `0x219ab90`, `0x21c7170`, `0x151c2c0`, `0x151b830`, `0x151c0b0` and `0x151c1c0`. The adapter tag branches, the two stated date construction routes, a calendar/ordinal consistency check and selected date/time failure paths are evaluated. The existing c-signer map and sequence readers, their value wrapper, the text parser, error formatter, cleanup and the actual parser inputs are context or hook boundaries. They are not claimed as new function analyses. Other date routes, all chain state changes and node #115 are excluded.

## Evidence

All addresses in this packet are linked ELF virtual addresses; file offsets and FDE record addresses are explicit in `functions.tsv`. An FDE is unwind evidence for a range, not by itself proof of a complete semantic function. The rows in `instructions.tsv` are produced by a strict subset decoder from the selected FDE bytes. `anchors.tsv` fixes reviewed branch and data-flow bytes; `links.tsv` checks the listed direct calls and RIP-relative slots using relocation addends. `content-table.tsv` and `format-descriptors.tsv` are read directly from ELF bytes. The two incoming reader sites and their wrapper are linkage context, not selected functions.

The earlier c-signer input work identifies the two incoming value sites as the map and sequence paths of the jail vote. The bytes connect them to the adapter:

```
map and sequence value sites
  -> value wrapper                     (context only)
    -> 0x219ab90                      content adapter
      -> 0x21c7170                    invalid-content result
      -> parser boundary               injected result and fields
      -> 0x151c2c0                     date/time conversion
         -> 0x151b830                  date construction
            -> 0x151c0b0               date-constraint check
         -> 0x151c1c0                  clock fallback
```

### Nonzero date at the adapter boundary

The adapter has a four-entry table for internal tags `0x0c` through `0x0f`; the numbers are internal discriminants, not claimed JSON or MessagePack tags. `content-cases.tsv` runs all 256 tag bytes with the stated parser and error hooks. The saved control flow has these normally returning outcomes:

| Internal tag | Result |
| --- | --- |
| `0x0c` or `0x0d` | Parser failure takes an error path. After parser success, a zero first date word takes an error path; a nonzero word is copied to a success result. |
| `0x0e` | The selected `0x21c7170` helper writes error status 1 after its error-construction call. |
| `0x0f` or any other tag | The adapter stores error status 1 after its error-construction call. |

The `0x0c` and `0x0d` branches test the converter's first 32-bit result directly; a zero result cannot reach their success stores. Consequently, for a normal return from this adapter, success implies a nonzero first date word regardless of which field combinations the parser can produce. This is an input-boundary invariant, not a claim that a real converter can produce zero on a successful date. The earlier `staking-c-signer-jail-94` packet reports a zero-date terminator in the downstream vote-row list; the guard rules out a successful zero-date value through this adapter, but does not establish the invariant for all other vote producers. The wrapper's checked copy sites pass that same word to its success result. `forced-date-cases.tsv` deliberately replaces the converter with a synthetic output and checks zero and four nonzero words through both the adapter and the direct wrapper. `boxed-cases.tsv` repeats the zero/nonzero control through one and two synthetic wrapper boxes. Their free and error functions are hooks; the cases do not prove allocator behavior or input reachability.

The tested parser success boundary supplies the format-descriptor range and two abstract result words. The conversion arm requires the first word nonzero and the second zero. `parse-controls.tsv` contains two deliberate parser-result failures. Hook pointer values are synthetic markers, not node error objects.

### Date construction under the stated field assumptions

The tested parsed object has a supplied year, either a supplied ordinal or a supplied month and day, no additional date constraints, and the weekday sentinel used by the fixture. `calendar-cases.tsv` and `date-cases.tsv` show the modeled outcomes, with a separate Gregorian calendar rule providing expectations. Year flag bytes come from the 400-byte ELF table in `year-flags.tsv`.

| Condition | Observed result in these fixtures |
| --- | --- |
| Year from -262143 through 262142 and valid month/day or ordinal | packed date `(year << 13) | (ordinal << 4) | year_flag`, reduced to 32 bits |
| Invalid month/day, ordinal 0, ordinal above the year's length, or year outside that range | date conversion failure, followed by the synthetic error formatter |
| Year 0, first day | `0x14`, not zero |
| Year 1970, first day | `0xf6401a` |

For these two routes, the ordinal is at least 1, the flag is in the low four bits and the shifted year occupies higher bits. Thus their accepted packed value cannot be zero. This conclusion is limited to these field shapes: no claim is made about other ways the converter can construct a date, or about whether the upstream parser can supply every synthetic combination.

When a year/month/day fixture also supplies an ordinal, `0x151c0b0` compares that ordinal to the constructed date. All 1600 matching combinations in `consistency-cases.tsv` succeeded; all 3200 off-by-one combinations took the mismatch branch and reached the formatter hook with code 1. An invalid calendar date reaches the separately tested code 0. These cases add that one constraint; other optional date fields remain outside the claim.

### Clock fields and result

The following names describe the observed field operations; they are not recovered Rust type declarations. A field's presence indicator and value are adjacent 32-bit words. `clock-cases.tsv` contains the independent rule comparison, including missing fields and boundary values.

| Parsed offset | Role on this route | Rule |
| --- | --- | --- |
| `+0x70/+0x74` | half-of-day presence/value | presence must be 1; value 0 or 1 |
| `+0x78/+0x7c` | 12-hour part | presence must be 1; value 0 through 11 |
| `+0x80/+0x84` | minute | presence must be 1; value 0 through 59 |
| `+0x88/+0x8c` | optional second | zero presence means zero seconds; otherwise 0 through 60 |
| `+0x90/+0x94` | optional fractional nanoseconds | presence 1 requires a present second and a value below 1000000000; other presence values take the absent branch |

For seconds 0 through 59, the seconds word is `(12 * half + hour12) * 3600 + minute * 60 + second`. For second 60, the code uses 59 in that word and adds 1000000000 to the fraction. In the bounded fields model, `00:00:60` takes this branch too; this is a conversion observation, not a claim that an external timestamp with that text is accepted. At the upper tested boundary, the result is 86399 seconds and 1999999999 nanoseconds. The standalone clock helper reports distinct error bytes 0 and 2 on the tested failures; the integrated cases show the subsequent formatter hook, not real formatted messages.

`path-cases.tsv` combines accepted and refused calendar/clock fields through the adapter and date/time converter. The clock fallback is also run directly in `clock-cases.tsv`; its direct cases are not represented as separate executions of the upstream readers. The upstream parser is a hook that supplies the parsed fields and the parser success/failure words. All memory, input flags and error markers in these cases are synthetic.

## Results and limitations

- The tool compares 33660 calendar cases (21324 successful), 2065 year/ordinal cases (923 successful), 4800 calendar/ordinal consistency cases (1600 successful), 605 standalone clock cases (121 successful), 11 combined path cases, 256 content-tag cases, 20 injected-date cases, 8 boxed cases and 2 parser-result controls to the stated rules. There were no mismatches in those sets.
- The selected six FDEs decode to 1231 instruction rows; 680 distinct instruction starts were reached by the generated cases. This is a denominator for these decoded ranges only, not component coverage. `functions.tsv` breaks it down by range.
- The focused test module has 24 passing tests and no skips. Wrong digest, altered witness, an out-of-range read, duplicate FDE, NOBITS handling, and eight instruction mutants are negative controls. Mutants test the parser-result gate, both zero-date gates, year/ordinal gate, calendar/ordinal comparison, month bound, hour bound and second-60 bound.
- No actual string parser is run; malformed text, timezone suffixes, valid-state reachability of the injected fields, allocation and cleanup are not established. Only the year/ordinal and year/month/day shapes and the stated combined ordinal constraint are tested. Other date/time paths and byte-interpreter correctness outside reached rows are open.
- No staking progress gate is requested. This does not complete staking or either release's epoch transition.
