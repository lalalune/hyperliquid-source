# RE-007: reconstruct the node #115 borrowLend operation-identifier deserializers: 5 Content-pair bodies, 24,020 byte-level runs

This packet makes the *reader* side of the four-name borrowLend operation enum of node #115 (`borrow`, `supply`, `repay`, `withdraw`, variant index 0..3) rebuildable as executable code, including every failure path. The merged borrowLend packet (`RE-007-borrow-lend-codec-115`) covered the msgpack writers and the eighteen name and field visitors; this packet resolves the five bodies that call those visitors from a serde `Content` buffer. Each body takes a 0x40-byte pair of `Content` values (the identifier at +0x00, the value at +0x20) and returns the operation index together with the untouched value `Content`, or an error. A borrowLend action reconstruction can now decode a buffered operation identifier exactly: only the `U8` and `U64` Content tags are integer indexes (a second four-entry table sends 0, 1, 2, 3 to operations 0..3, which the tool reads from the file bytes; 4 and above is an invalid-value error that reports the number), `String` and `Str` go to the `&str` name visitor, `ByteBuf` and `Bytes` to the `&[u8]` name visitor (an owned buffer is freed afterwards and the identifier is not dropped; a borrowed one is dropped after the visit), and every other tag - including `U16` and `U32` - is an invalid-type error that leaves the identifier undropped. The reconstruction agrees with the interpreted original machine code on 24,020 of 24,020 runs, and 89 of 89 negative controls (21 deliberately wrong reconstructions, 63 damaged code or jump-table bytes, 5 out-of-range inputs) are detected.

## Reproduce

Run from the repository root on Linux x86-64 with Python 3.12. Only the standard library is needed, plus `tools/elf_index.py`, `tools/fde_extents.py` and `tools/re007_margin_identifier_115.py`.

- The producer checks the full SHA-256 of the input before it parses anything.
- It never executes the capture and starts no process. It interprets the selected machine code in Python.
- Output contains no time, randomness, absolute path or unordered iteration.

```sh
python3 tools/re007_borrow_lend_identifier_115.py --out research/work-items/RE-007-borrow-lend-identifier-115
python3 -m unittest tests.test_re007_borrow_lend_identifier_115
python3 tools/artifacts.py verify
python3 tools/catalogue.py --check
cd research/work-items/RE-007-borrow-lend-identifier-115 && sha256sum -c MANIFEST.sha256
```

Cases are generated by the tool and are the same for every body (4,804 per body): integers 0..8 and edge values (0x7f..0x0300000000000000) in four value-Content tags, 21 other tags, and for each of the four text arms every text input (exact names, every prefix, one-byte mutations, case changes, spliced names, invalid UTF-8, lengths 0..19) crossed with four value-Content tags and a zero or nonzero capacity for owned text. The committed `cases.tsv` is a regular sample of those runs plus every mismatch; the rest is regenerated by the command above.

(`functions.tsv` has sizes, hashes and instruction counts; `instructions.tsv` the decoded bytes. The visitor addresses are the ones listed in the merged borrowLend packet.)

**Dispatch.** The first byte of the identifier minus one is an index; above 14 the body goes to the invalid-type arm. A 15-entry table of 32-bit offsets (`jump-tables.tsv`, read from the file bytes) sends tags 1, 4, 12, 13, 14 and 15 to six distinct arms and tags 2, 3, 5..11 to the same target as the out-of-range tags. The tool fails if any other tag has its own target.

| Tag | Arm | Reads | Decision |
| --- | --- | --- | --- |
| 1 | integer | byte +1 | 0..3 select the operation through a four-entry table; otherwise invalid-value with the number; then the identifier is dropped |
| 4 | integer | qword +8 | same, on the full 64-bit value |
| 13 | text, borrowed | ptr +8, len +0x10 | `&str` name visitor; then the identifier is dropped |
| 12 | text, owned | cap +8, ptr +0x10, len +0x18 | `&str` name visitor; frees the buffer when cap is nonzero; the identifier is **not** dropped |
| 15 | bytes, borrowed | ptr +8, len +0x10 | `&[u8]` name visitor; then the identifier is dropped |
| 14 | bytes, owned | cap +8, ptr +0x10, len +0x18 | `&[u8]` name visitor; frees the buffer when cap is nonzero; no drop |
| others | invalid-type | the Content itself | error built from the Content tag; the identifier is **not** dropped |

**Integer tables.** `int-tables.tsv` lists the second-level tables (one for the U8 arm, one for the U64 arm, per body): the compare bound is 3, each of the four entries lands on an immediate store of the operation tag (`movb $k` in the result form, `movw $0x?09` in the tagged form), and the tool requires the stored tag of entry k to be k. Values above 3 go to the invalid-value constructor with the number.

**Result.** Byte 0 of the result is the operation index (0..3) with the value `Content` copied unchanged to +8..+0x28, or 4 with the error at +8: a 32-byte record in the tagged form, a boxed error pointer in the result form. Bytes +1..+7 of an Ok result are stack padding that the bodies never write, so they are excluded from the comparison. On an error the value `Content` is dropped unless its tag is `0x16`; on success it is handed back. Unlike the margin-mode bodies there is no name compare in these bodies and no lossy conversion: a visitor error is passed through unchanged.

**Callees (stubbed, argument-checked).** `callees.tsv` binds eight distinct callees per body by first appearance (`&str` visitor, `&[u8]` visitor, free, drop, invalid-type, invalid-value, resume, unwind). The two visitor stubs record the text they receive (`vs`, `vb`) and answer with the exact-name classification of the merged packet in the ABI of the form (a two-byte `0x09 | tag << 8` word or a result byte); the other stubs record `iv`, `it`, `drop` and `free` with their arguments. The event list is compared in order. The error constructors write a role-specific record or sentinel, so an error built by the wrong callee is a mismatch. The invalid-type pool of each family is read from the `lea` before the call.

## Implementation and comparison

Independent Rust path: not yet implemented. The reconstruction is `recon()` in `tools/re007_borrow_lend_identifier_115.py`, a pure-Python function of the identifier case; it never reads the binary. The interpreter is the merged margin-identifier packet's fixed x86-64 subset (no instruction was added). The comparison is exact: outcome (index or error role), the complete ordered event list with arguments, and the value Content bytes.

Negative controls (`negative-controls.tsv`, `damage-controls.tsv`):

| Kind | Count | Detected |
| --- | --- | --- |
| deliberately wrong reconstruction (bound 2, low byte only, swapped indexes, missing/extra drop and free, drop order, wrong visitor for owned or borrowed text, tag plus one, niche ignored, U16 as integer, `withdraw` unknown, error instead of ok, ...) | 21 | 21 |
| damaged code: an executed compare immediate with bit 3 flipped, or an executed conditional jump with its condition inverted | 43 | 43 |
| damaged jump-table entry (tag 4 as 1, 13 as 12, 15 as 14, 12 as 14), per body | 20 | 20 |
| out of range: truncated binary, entry that is not an FDE start, missing stub, family-2 visitors on a family-1 body, tagged stubs on a result body | 5 | 5 |

Every damaged-code site is chosen from instructions the baseline run actually executed; a rejected run counts as detected. No executed site turned out to be an equivalent mutant.

Limits:

- Callee bodies (drop, free, error constructors, the name visitors) are stubs; only their call order and arguments are proved here, not their effect. The visitors' behaviour comes from the earlier packet.
- The `Content` model is the arm set the bytes use; the other tags are proved only to reach the invalid-type call with the tag byte.
- Unwind landing pads (resume and cleanup callees) are never entered.
- No cross-family claim is made beyond equal behaviour on these runs.
- No progress gate is requested.
