# RE-004: reference-oracle configuration change and decimal fraction gate

Node #94 applies a reference-oracle configuration change by validating an optional decimal fraction before its optional integer, preserving unspecified default fields, and applying per-asset changes only after validation; this lets a reconstruction preserve the error order and the default values passed to the existing price-update path.

- Component ID: RE-004, quantities and rounding, reference-oracle price configuration.
- Target release and full SHA-256: node #94 `artifacts/node/94/hl-node`, `3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`.
- Source commit / reference commit: `966865f1637a29ce75b019e1bf11d5529cc6f519` / `999556f6e0a474b8312db96ec3149e1c44e97c23`. The unlicensed reference is a lead only and no reference code is copied.
- Claim status: observation for checked bytes, branch targets, constants and call links; the relationship to the existing price reader is an inference from matching layout and the earlier packet. Converter-output reachability and an actual state instance are unresolved.
- Scope included and excluded: four previously unclaimed FDE intervals, selected instruction windows within the existing vote dispatcher, the tag's table entry, the validator's finite-output decision and the initial default-field stores in the writer. The decoder internals beyond the pinned calls and stores, decimal parser and decimal-to-f64 callee bodies, other dispatcher arms, tree helpers, output-state readers, permissions, nonfinite converter outputs and node #115 are excluded. The dispatcher itself is an existing shared function, not a subject of this packet.

## Evidence

All addresses are node #94 ELF virtual addresses. The evidence JSON includes the corresponding file offsets, full bytes and hashes for each FDE interval. FDE intervals are unwind extents, not independent proof that every byte is reachable or a complete source-level function.

| variant decoder | `0x1f571a0` | `0x1f575a4` | Calls the first decoder; its success stores raw action tag `0x6e` and the decoded fields. Its failure metadata names `VoteGlobalAction::SetReferenceOracleConfig`. |

The signed displacement at the `0x6e - 0x12` entry of table `0x3dd1b8` selects dispatcher site `0x235801f`. That site copies the five-word first value, calls the validator through a relative relocation, and handles its status. It also checks that the following list has at most 10,000 entries; the per-entry loop resolves a name and calls the same validator. On the later writer path the call at `0x235baa6` passes the validated default and constructed change map. The windows and call targets are recorded, but authorization, all loop paths, and transaction rollback are not established.

The validator's optional string occupies input offsets `+0x10`, `+0x18`, `+0x20`; the first word equal to `0x8000000000000000` is the absent niche. An optional integer uses a tag at `+0` and value at `+8`; a byte at `+0x28` is copied to the successful output. The parser and converter are separately relocated calls, and this packet does not interpret their internals.

The fraction comparisons use binary64 instructions, with the upper bound read as the exact bits for 1.0. For finite returned values, positive zero and negative zero pass, the largest representable value below 1 passes, 1 fails, and a strictly negative value fails. The generator's bit-class model covers all finite binary64 bit patterns by sign and magnitude intervals, conditional on the converter returning such a value; it does not prove which values the decimal parser can produce, the conversion rounding, or the processor floating-point mode. The absent-fraction payload is not claimed to be initialized.

### Default updates and override map

For writer destination `D`, its default fraction, integer and byte are at `D+0x18`, `D+0x20`, and `D+0x28`. The first incoming option tag controls the fraction; the second controls the integer. A zero tag preserves the previous word and any nonzero tag selects the supplied word. Incoming byte 3 preserves the old byte; any other incoming byte is stored. `default-merge.tsv` enumerates zero, one and two for each option tag and five byte values. These are raw-machine-input cases, not a claim that every tag is reachable from serde.

For each change-map item, the writer calls an iterator. An item with both option words zero and byte 3 calls one helper; other items call a different helper. An iterator sentinel exits the loop. The call pattern suggests removal and update respectively, but their effects are not established without reading the helpers. Map structure, ordering, allocation failure, unwind cleanup and whether a particular action reaches the final writer are not independently reconstructed here.

### Relationship to price updates

The dispatcher passes a row-relative `+0xa8` address to the writer. Thus its three default stores are at row offsets `+0xc0`, `+0xc8`, and `+0xd0`. The existing `RE-004-mark-move-clamp-94` packet describes a price-update argument at row `+0x60`, with its fallback fraction, integer and byte at argument offsets `+0x60`, `+0x68`, `+0x70`, and passes them to a reference-price check. The offset arithmetic is an exact layout match. It supports the inference that this vote updates that fallback configuration; the earlier packet stubs the reference-price checker, and neither packet proves that a particular update and a particular read operate on the same live object.

## Results and limitations

- Four FDE intervals, 17 fixed windows, 16 decoded conditional sites, 144 finite gate cases, 7 error-order cases and 45 default-merge cases are retained. The lists are selected scope, not a node-wide census.
- 23 focused unit tests pass without skips, including changed digest, FDE, function body, dispatcher bytes, relocation, branch opcode, unbacked and NOBITS controls. Two generations under different hash seeds and time zones match byte for byte.
- Decimal parsing and conversion are existing external calls. The packet does not establish their rounding, accepted string grammar, or whether arbitrary binary64 values can arise. The static interval model is conditional on finite converter output and the pinned byte interpretation.
- The earlier price-reader link is layout-based, the map helpers are not modeled, and there is no independent Rust implementation or authorized target comparison. No milestone gate is advanced.
