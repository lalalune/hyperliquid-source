# RE-009: which RocksDB options do the two tuned open wrappers set in node #94?

- Component ID: RE-009 (storage and state roots; `db/*`)
- Target release and full SHA-256: node #94 `artifacts/node/94/hl-node`,
  `3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`
- Source commit / reference commit: hyperliquid-source `1f8c67c63ca4794c9689235471c60297f8a5c985`;
  references/can1357-hl at the pin of that commit (labels used only as claims to test)
- Claim status: observation for constants, call order, offsets and call sites;
  inference for upstream RocksDB field names; unresolved for the values callers
  pass as the cache override
- Scope included: `0x3421980` and `0x42c70c0`, their single rel32 callers, the
  two path validators they call first, ten RocksDB C API slots and their bodies,
  and the option constructors that give those offsets their defaults.
- Scope excluded: `DB::open` bodies `0x3c98770` and `0x4b70480`, the nine other
  `options_create` owners, key/value schemas and file formats.

## Reproduce

From the repository root, Python 3 standard library only. The binary is read
and never run; the tool starts no external program.

```sh
python3 tools/artifacts.py verify
python3 tools/rocksdb_open_options.py --out research/work-items/RE-009-rocksdb-open-options-94
python3 -m unittest tests.test_rocksdb_open_options
```

`open-options.json` and `ffi-site-census.tsv` are regenerated byte for byte. Section,
FDE and relocation data come from `tools/elf_index.py`, `tools/fde_extents.py` and
`.rela.dyn` through `struct`. Instructions are matched as fixed byte patterns, so
no list or count depends on a disassembler version. The `objdump -d -M intel`
excerpt below is for reading only and no generated file uses it.

### Order

Both wrappers run the same sequence, and the tool rejects any other:

```
block options create -> LRU cache create -> set block cache -> set block size
-> options create -> create_if_missing(1) -> write buffer(0x8000000)
-> set table factory -> open
```

`all_call_positions_create_to_open` lists each call in that span. The only
others are allocator `0x54c06b0` and Arc drop `0x4ea9d90`. A manual read of the
span finds no direct store into either options object.

### Cache capacity

```
3421a56: test r15b,0x1
3421a5a: mov  edi,0x2
3421a5f: cmovne rdi,r14
3421a66: shr  rax,0x22
3421a6a: jne  3421d0d          ; -> capacity 0xffffffffffffffff
3421a70: shl  rdi,0x1e
```

The override is `(rcx bit 0, r8)`. A GiB count below 2^34 is shifted left by 30;
2^34 and above becomes `u64::MAX`. The LRU wrapper passes shard bits -1 and
pool ratio 0.5 from `0x209180`.

### Gates before option creation

- Home lookup: both walk a B-tree keyed by the `u8` argument. `+0x62` is the
  `u16` length, entries start at `+0x64`, values at `+0x08`, edges at `+0x70`.
  A miss panics with `db/src/owned_db_home.rs:72:37`.
- Validators: `0x332eba0` forbids bundle byte 2 and `0x459b500` loops over
  bytes 0 and 1. Table `0x572d7c8`/`0x6f8900` names them `Exchange`, `Rpc`,
  `EvmState`.
- Only the checkpoint wrapper tests the first word of its second argument:
  `0x8000000000000001` at `0x42c717b` exits to `0x42c7401`, which returns first
  word `0x8000000000000000` before the validator and all option calls.
- Only the state caller skips bundle byte 3 (`cmp bl,3` at `0x3be4b59`).
- An `Err` from open panics with `db/src/rocks_db.rs:63:43`.

### Census

`ffi-site-census.tsv` has every byte position that resolves to one of the ten
slots or bodies. Block size, block cache, write buffer and table factory each
have 2 sites, both inside the two wrappers. No rel32 edge reaches their bodies
and no other RELATIVE slot holds them. Of 11 `options_create` owners, 2 have all
three tuning setters, 4 have only `set_create_if_missing`, and 5 have none of the
pinned setters.

Panic Locations name `rocksdb-0.21.0/src/db_options.rs` lines 56, 650 and 3065.

### Inferences (separate from the observations above)

1. `+0x58` is `block_size`. The neighbouring defaults 4096, 10, 16, 1, 4096 match
   the upstream `BlockBasedTableOptions` run block size, size deviation, restart
   interval, index restart interval, metadata block size.
2. `+0x4a8` is `write_buffer_size`, so both profiles use 128 MiB. Its default is
   64 MiB, the upstream default, and the same constructor has 4 at `+0x288`, the
   upstream L0 compaction trigger default. The binary holds no name for this
   offset, so this rests on defaults alone.
3. `0x3421980` is `state` and `0x42c70c0` is `checkpoint`. The binary supports
   this through its forbidden bundle sets and defaults, which match the
   reference's split; it does not contain those two words as labels.

## Results and limitations

- `tests.test_rocksdb_open_options`: 27 tests. 13 are corruption or out-of-range
  controls; 2 more confirm values come from bytes, not from the pin table.
- Generated denominators: 77 census rows, 11 `options_create` owners, 10 slots.
- Upstream names rely on defaults in RocksDB's public source. This packet did
  not recover the RocksDB version; the crate path gives only `rocksdb-0.21.0`.
- The census sees rel32, RIP-relative slot and RELATIVE references. A computed
  target or an inlined store elsewhere is outside it.
- The rest of `DB::open`, including paths or column family settings, is unread.
  The 5 owners with no pinned setter may use other setters.
- Which value the `(rcx, r8)` override holds at runtime is unresolved. Both
  callers load it through a captured pointer.
- No completion gate is requested.
