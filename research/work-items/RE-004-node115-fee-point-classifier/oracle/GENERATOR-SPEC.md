# Bounded deterministic corpus specification

This concrete generator refines the larger optional families in the preserved
CORPUS-PLAN.md. It is authored but unexecuted; exact retained counts are pending.
It never changes the reviewed mathematical reference or any expected hand row.

## Fixed transport

Input-only records are eight ASCII TSV fields, no header, terminated by LF:

    case_id quantity scale_bits t_bits d_bits q_bits m_bits h_bits

Spaces above stand for exactly one TAB. IDs match[A-Za-z0-9_-]+. Quantity uses
canonical unsigned decimal1..10000000. Every bits field is exactly16 lowercase
hex digits; scale is one of the six approved encodings. Every row has a final
LF. Expected and future actual output records have two fields:

    case_id ClassName

ClassName is exactly one of the five approved classification strings. A future
comparator must require one well-formed actual row for each input, preserve IDs
and order, and reject missing/extra/duplicate IDs, malformed rows and process
failure before making any numeric-equivalence claim. No expected-output field
is supplied to the future input-only Rust driver.

## Family order and exact deterministic inputs

1. The36 independent rows are first, in original file order with original IDs.
   They are always retained, even if two hand rows share an input. Their
   expected classes are retained from the fixture, after comparison against
   the reviewed reference; any mismatch aborts. The entire original JSON is
   copied verbatim into the output evidence.
2. An explicit arithmetic-interaction point has t=d=0,q=1,m=2,h=+2^63,s=1,n=1.
   Its expected label is generated by the reviewed reference. A separate parent
   algebraic handcase review supplies independent reasoning for the intended
   saturation-versus-wrap control; the generator does not pretend this new
   point belonged to the original36-row freeze.
3. Three fixed contexts cross15 quantity boundaries and all6scales:270 requests.
   Contexts in(t,d,q,m,h) order are allzero; (1,0,0,0,0); (1,0,1/2,0,1/4).
   Quantities are[1,2,3,7,10,127,128,255,256,1023,1024,65535,65536,9999999,10000000].
4. A32-encoding alphabet is substituted into each of5fields of contexts0and2,
   crossing all6scales and quantities1and10000000:3840requests. The raw encodings
   cover signed zeros/subnormals/min-normal,1/10,1/2,neighbors of1,2^53/2^63
   boundaries,maxfinite,infinities and quiet/signaling NaNs. Source lists all
   encodings; no decimal parsing or host float constructs them.
5. Each original hand input receives in-range raw-bit neighbors ±1 for each
   field, quantity neighbors ±1 and each of the other5scales. Neighbors get
   fresh reference expectations; the original expected label is not assumed
   invariant. This contributes at most612requests, fewer at domain boundaries.
6. Exactly1024 arbitrary-bit points derive per-field64-bit words from SHA256:
   seed `node115-fee-point-precode-v1`, NUL, family `raw_bits`, NUL, ASCII decimal
   counter without leading zeros, NUL, field name. Use the first8digest bytes
   big-endian. Field names are t,d,q,m,h,quantity,scale. Scalars use raw words;
   quantity=1+word mod10000000; scale=word mod6 selecting the fixed scale order.
7. Exactly480 exponent-stratified requests: exponent in
   [0,1,2,1022,1023,1024,1075,1085,1086,2045,2046,2047], sign0then1,
   significand in[0,1,2^52-1,0x5555555555555], then each of5fields. For the
   monotonically increasing zero-based row index, context=index mod3,
   scale=index mod6 and quantity=index mod15. The explicit exponent/significand
   bits are inserted into the selected field of that context.

The mathematical maximum requested count is6263, below the hard cap8192. This
is an upper bound, not an observed execution count. Generated duplicates are
identified only by the complete7-scalar tuple, retained by first occurrence,
and recorded in input-aliases.jsonl.gz. Metadata unions family membership into
the retained row. Independent rows are never silently dropped. No case is
removed merely because its expected class duplicates another row's class.

## Provenance and output accounting

SUMMARY.json records actual requested/retained/alias counts, family requests,
retained family memberships, five-class histogram, all six scales, quantity
endpoints, source/fixture hashes, interpreter version, and uncompressed hashes.
case-metadata.jsonl.gz records the origin of each expected label and independent
coverage labels where provided. Such labels are inherited mathematical claims,
not automatically established native path coverage. MANIFEST.sha256 pins all
six output data/summary files; raw execution receipts are kept by the parent.

No fresh expectation generation or Rust begins before approved qualification
and generator review. Later changes require new outputs/receipts, preserving
this authored source and the old frozen expectations. No native/runtime or
60million-conjunction result is inferred from a matching corpus.
