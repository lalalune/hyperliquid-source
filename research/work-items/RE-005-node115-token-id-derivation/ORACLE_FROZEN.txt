What the generator contains (no library code, no copied tables, no Rust):
  * MessagePack: written from the public spec; checked in --selftest against 17 byte-exact
    spec examples (fixint, cc/cd/ce/cf widths at 127/128, 255/256, 65535/65536, 2^32-1/2^32,
    u64 max; fixstr/str8/str16/str32 headers at 31/32, 255/256, 65535/65536).
  * Keccak-256: lane matrix with rho offsets and round constants derived from their defining
    recurrences, whole-message padding, then block absorption (a different shape from the
    incremental absorb/finalize the Rust side uses). --selftest checks three published
    Keccak-256 vectors (empty string, "abc", "The quick brown fox jumps over the lazy dog";
    reproduced from the public Keccak/Ethereum test material, no network in this session)
    and, with delimiter 0x06, equality with the OS hashlib.sha3_256 for every length 0..699,
    1000 and 4096 (all rate boundaries up to five blocks). Delimiter 0x01 itself rests only
    on the three published vectors.
  * Scout anchor: name "X", szDecimals 6, weiDecimals 8, index 0 -> preimage
    9283a46e...0800, digest 9058f458...dd40, recorded in SCOUT.md from Node crypto/OpenSSL; the
    selftest asserts it. Node was not re-run here (not permitted in this session).

The expected values follow what the #115 bytes do (field order, widths, truncation point),
as pinned in README.md / pins.json, not the generic standard. Where the standard and the
bytes could differ they agree here; see README "Differences from the standard".
That reading of the bytes is the author's; this file does not make it independent.

the index as well as the outer array and gave one id for every index. After the freeze, gen_oracle.py was
changed in `wrong_variants` only:

  * `map_then_index_no_outer_array` was added: spec map followed by the minimal unsigned index, without the
    `0x92` array header. It keeps the index, so its ids differ per index, and none equals a #115 id
    (the generator asserts it).
Nothing else in gen_oracle.py changed: the preimage, Keccak, MessagePack and case-building code is
byte-for-byte what was frozen. Consequently corpus.tsv is unchanged (cmp silent, same sha256 as above) and
wrong-variants.tsv grew from 602 to 703 ids (101 new rows).
