# RE-017 · Mixed-root history replacement

Target Linux x86-64 Node #115 SHA-256 a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301. The [linked commit packet](../RE-017-abci-linked-commit-115/README.md) identifies the mixed digest and its consumer at 0x5a08ac7. Here the new scope is the consumer's record layout, cutoff selection and descriptor replacement at 0x5a046f0.

The consumer moves its original second and third arguments into the third and fourth argument registers for 0x4dce8b0 and passes the descriptor as the second argument. After the call it reads the descriptor word at +24. Values below 51 return before the following selection. On the ordinary flat-buffer arm the selected pointer construction uses offsets in units of 40 bytes. The separate sentinel arm constructs a different iterator descriptor.

In the final unrolled portion there are 43 calls to 0x4e2a4e0, each followed by a null test and branch to return. If every call returns non-null, the first word of the last returned record becomes the third argument of 0x4de4a60, with the existing descriptor as its second argument and a stack output address as its first. The selected key is described relative to this final portion. Its absolute rank in the history depends on the earlier iterator steps.

After the helper returns, a sentinel old head selects the member cleanup call at 0x5a04dab. A non-sentinel, nonzero old head supplies a 40-times-head byte count for the other release boundary. A zero head skips that boundary. Both normal continuations copy the same 32-byte helper output back to the descriptor. This records the handoff and replacement order, including the storage difference from a raw-root history tree. The helper behavior on the flat path is described below. Tree partitioning and unwind behavior remain open.

For a valid ordered flat ring, the helper at 0x4de4a60 splits its rows into up to two contiguous 40-byte spans. If the wrapped span exists and its first unsigned key is below the cutoff, the helper counts the whole first span and searches the wrapped span. Otherwise it searches the first span. Its comparisons count the strict prefix of keys below the cutoff, so equal keys are in the suffix. It uses total count minus prefix count to size a new allocation and copies the suffix in logical order. When the suffix begins in the first physical span, the copy at 0x4de4f66 is followed by the wrapped portion at 0x4de4fc2. When it begins in the wrapped span, only the latter site is used. On the normal continuation the original descriptor's count becomes the prefix length, and the returned descriptor holds the suffix with start zero. The outer consumer replaces the original descriptor with that result.
