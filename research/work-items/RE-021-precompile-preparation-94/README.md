On node #94's raw-revision-18 EVM path, the 20 bytes at transaction environment `+0x295` become the frame lookup key at `+0x60` after gas validation, access-list preparation, payer precharge and authorization processing, making the input condition for the previously mapped address-09 precompile path reconstructible.

- Target release and full SHA-256: node #94, Linux x86-64, `3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`.

- Claim status: **observation** for selected bytes, FDE/CIE/LSDA coordinates, fixed branch forms, relocation records, constants and descriptor entries; **inference** for source-level names, field roles and conditional composition with the earlier engine route; **unresolved** for actual live selection, the upstream producer of the environment field, external helpers and native behavioral equivalence.

### Validation and initial-gas arithmetic

`0x21b9430` first requires its input byte at `+0xe4` to equal one and the OR of the first two words to be nonzero. Failure yields outer tag 1 with subcode 0 or 1. It then invokes `0x1e6c0d0`, whose raw success value is 25. The following selected failure tags are machine stores; field names are inferred from their uses.

| Predicate, under the corresponding enabled checks | Inner raw tag |
| --- | --- |
| Optional network word differs from the configured network word | 12 |
| Transaction gas limit exceeds the selected block limit | 2 |
| Four-limb priority value exceeds its cap | 0 |
| Effective price is below the selected base value | 1 |
| Create-input length exceeds the selected bound | 11 |
| Auxiliary fee/list predicates fail | 15, 16, 17, 18, 19 or 20, as distinguished in `tag-stores.tsv` |
| Authorization list is present with an incompatible auxiliary input or is empty | 23 or 24 |
| Accepted | 25 |

For raw revision 18 and a valid accessible input buffer, let `z` and `n` be the counts of zero and nonzero input bytes, `a` the number of 48-byte address entries, `s` the total count of 32-byte slots, and `q` the selected authorization count. If its environment variant is 2, the wrapper passes `q = 0`. The selected helper computes:

```text
tokens  = z + 4*n
initial = 4*tokens + 2400*a + 1900*s + base + 25000*q
floor   = 21000 + 10*tokens
base    = 21000 for a call, or 53000 + 2*ceil(input_length/32) for create
```

`0x21b85e0` first rejects `initial > limit` with outer tag 0/code 3, then rejects `floor > limit` with outer tag 0/code 4; equality is accepted. On success it returns tag 5 and both computed words. A synthetic arithmetic example with one nonzero byte and no entries gives initial 21016 and floor 21040, so a limit of 21016 passes the first comparison and fails the second. The helper also contains revision thresholds at 2, 9, 11, 16 and 18, captured in its windows and tested at both sides. Arithmetic-overflow branches lead to selected failure calls. The machine's `input_length + 31` itself has no checked-add branch; the model limits that formula to a valid-buffer domain where it cannot wrap and makes no claim about pathological impossible-to-materialize lengths.

`0x21b9db0` obtains a 20-byte payer key from environment `+0x280`, calls `0x1eb1cc0`, and forwards a non-five account result. The five-entry payer code-tag table is at `0x3bd348` in `payer-variant-table.tsv`: tags 0, 1 and 2 check lengths; tag 3 bypasses that length check; tag 4 reaches an invariant failure when the check is enabled. A nonempty checked code value returns inner tag 5. An optional requested nonce below or above the account nonce returns 10 or 9 respectively. The gas-limit times maximum-price product and subsequent value/auxiliary additions are checked as four-limb values; overflow returns 7, insufficient balance returns 6, and success is 25. If environment option `+0x151` is enabled, the insufficient-balance branch instead writes the computed required value to account `+0x40..+0x5f` and returns 25. That is a state write during validation, before the selected preparation callbacks. The label of the option and the full external auxiliary-fee helper are not established.

### Address warming and payer precharge

At `0x276ec80`, the revision byte 18 is stored at context `+0xb0`; one 20-byte value from environment `+0xd0` and the fixed 20-byte value in `constants.json` are passed to the set-insertion boundary on context `+0x80`. The identification of this set as a warm-address set is an inference. `0x278e2f0` reads a list pointer/count at environment `+0x1f0/+0x1f8`, walks 48-byte entries containing a 20-byte address at `+0x18` and a slot pointer/count at `+0x08/+0x10`, and visits each 32-byte slot. Its selected windows show account probing, external database loading on a vacant account, 208-byte account buckets, slot probes with 104-byte bucket stride, and four reversed, byte-swapped input words. Empty input reaches return tag 5. Runtime seeds, external database operations and exhaustive storage failure meanings are outside the packet.

`0x276e340` loads the payer account and propagates any non-five result before calling `0x279d0c0`. Interpreting four-limb operands as unsigned integers, the effective price is the cap unless price-kind equals one; in that arm it is `min(cap, (base + priority) mod 2^256)`. The selected arithmetic saturates an overflowing gas-times-price product and the subsequent auxiliary-cost addition to `2^256 - 1`. The auxiliary term uses a 128-bit supplied price times `count << 17`, with a failure branch if the count is at least `2^47`. A required environment flag has a separate failure call. The account balance at `+0x40..+0x5f` is saturating-subtracted; when environment byte `+0x294` is one, account nonce `+0x60` is saturating-incremented; flag byte `+0xb0` has bit 2 set. These observations do not establish atomicity across subsequent failures.

### Authorization iteration, writes and unwind

`0x279d5e0` returns tag 5 and word zero immediately for environment variant 2. Otherwise the iterator constructor `0x4ea42a0` selects either a 136-byte item adapter (`0x4ea4150`, using selected recovery conversion `0x1353d50`) or an 88-byte adapter. The 88-byte next function `0x4ea4220` is already covered by another work item and is only an external dependency here. For an available item the selected branch sequence is:

| Test | Observed result |
| --- | --- |
| 32-byte chain value is nonzero and differs from the zero-extended environment network word | Skip item. |
| Item nonce is `2^64 - 1` or recovered-authority tag has its low bit set | Skip item. |
| Account/code loader result is not tag 5 | Forward that result and clean up the iterator. |
| Code tag 0, 1 or 2 has a nonzero selected length | Skip item; tag 1 also checks its internal length bound. |
| Code tag 3 or 4, or a zero length from tags 0..2 | Continue to compare account and item nonces. |
| Account nonce differs | Skip item. |
| Eligible item | Increment a counter for a previously nonempty account, construct replacement code, write the new hash/code and update nonce/flag. |

The five entries and destinations are retained in `code-variant-table.tsv`; there is no general valid-tag-domain claim. The observed counter increments if the code hash is neither zero nor the retained empty-code digest, or the balance is nonzero, or the matching nonce is nonzero. At iteration end, its checked product by 12,500 is returned with tag 5. Calling this word a refund is an inference from its downstream role; final settlement remains earlier work.

For a zero target address, the code comes from an external builder and the hash is the 32-byte constant in `constants.json`; naming that helper an empty-code builder is an inference. A nonzero target goes through `0x4ea2ec0`, whose pinned prefix and length construct `ef 01 00` followed by the 20-byte target; the external digest helper supplies its hash. Account hash at `+0x68..+0x87` is stored before an optional old-code drop at `0x279d9ba`, then replacement code at `+0..+0x3f`, saturating nonce increment and flag bit 2 are stored on the normal path. The LSDA row covering the old-code drop points to landing pad `0x279db37`: the selected landing window installs the replacement code fields, then proceeds through cleanup and `_Unwind_Resume`. It does not perform the later normal-path nonce/flag stores. This is observed instruction and unwind-table ordering, not a claim that an unwind happened in a target run or that all surrounding state changes roll back.

### Frame input and the conditional address-09 connection

The previously mapped executor calls through slot `0x5774588` after its environment `+0x294` byte equals one. PR #1413 retained that relocation to `0x4e91cb0`, and shows its argument is the environment pointer plus `0x158`. This packet newly selects the actual constructor FDE `0x4e91cb0..0x4e91e2b`; the prior packet's edge label did not analyze this body. All constructor offsets in `frame-layout.tsv` are relative to its first argument, while its frame offsets are relative to the eventual copied 160-byte object.

The constructor checks argument byte `+0x13c`: zero returns a null pointer. On its nonzero branch it reads 16 bytes at argument `+0x13d` and four at `+0x14d`, saves them across a dynamic payload-clone call, and writes the same 20 bytes to both frame `+0x60..+0x73` and `+0x74..+0x87`. The table records the load and store instruction bytes and their independently extracted displacements. It also records the input value at argument `+0x108..+0x127` to frame `+0x08..+0x27`, and the payer at argument `+0x128..+0x13b` to frame `+0x88..+0x9b`. The body stores a zero frame tag, passes its second argument to frame `+0x58`, stores zero at scheme byte `+0x9e`, allocates 160 bytes and copies the frame. Allocation failure has a separate failure call; the LSDA rows retain cleanup for the allocation failure/unwind. Payload cloning, allocation, memcpy interposition and destructor behavior are external boundaries.

With the earlier executor's argument adjustment, the constructor offsets correspond to environment `+0x294` for the variant, `+0x295..+0x2a8` for both copied addresses, `+0x260..+0x27f` for value and `+0x280..+0x293` for the payer. The earlier private handler uses the resulting frame field at `+0x60` for the full 20-byte registry lookup, and skips that lookup for scheme byte 6. Therefore, **if** the environment value at `+0x295` consists of nineteen zero bytes followed by `09`, the frame constructor and its clone/allocation/copy complete normally, the previously traced raw-revision-18 callback bindings and registry remain in force, and the prior depth/account/value/table guards permit lookup, the lookup key is the address-09 key and scheme zero does not trigger that bypass. This composition assumes the payload clone does not alias the saved address and normal `memcpy` behavior, since those dynamic boundaries are not proved here. The earlier mode-5 lineage retains the address-09 wrapper and the private overlay is disjoint from its key; this is conditional static composition across the earlier packets, not captured runtime reachability. No claim is made about who populated the environment address, the runtime seed, or arbitrary registration changes.
