# RE-012: CLI executor dispatch byte on return and unwind

Target Linux x86-64 node #115 `artifacts/node/115/hl-node`, SHA-256 `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`. Component: node runtime. The existing `RE-012-node115-cli-execution-dispatch` packet verifies an entry table indexed by object byte `+0x21a` but leaves its relationship to the extracted command open. This packet identifies two actual writes and their subsequent dispatch entries; it does not re-credit the full table inventory.

At `0x2ae41f1..0x2ae4209`, the executor saves its input pointer in RBX and dispatches through a signed-relative table using input byte `+0x21a`. On the selected normal exit `0x2ae5e50..0x2ae5e74`, the code clears the word at object `+0x218`, assigns `CL=1`, sets EAX=0, stores CL at `+0x21a`, and returns. On the selected unwind continuation `0x2ae65dc..0x2ae65f0`, the code clears the same word, stores 2 at `+0x21a`, and calls `_Unwind_Resume@plt`. If the same object is subsequently entered unchanged, table index 1 lands at `0x2ae5ff9` and index 2 at `0x2ae5fec`; these blocks call distinct indirect slots `0x64e1368` and `0x64e1360` respectively. No normal return is observed in these short blocks.

This establishes a lifecycle relationship for these two values: the dispatch byte is written at the indicated exit and unwind sites. It does not prove parser-selected command values are never copied to this field on some other path; a complete writer census, all 16 table cases, executor semantics, and runtime reachability remain open. In particular, the CLI contract's command tags 2 and 3 cannot be identified with this entry byte solely because the numeric values match. Addresses are link-time VAs. No captured code executes and no completion gate changes.
