# RE-001: selector-inversion wrapper 0x5ebd130 (node #115)

Bounded question: for a given index, what does the wrapper at
0x5ebd130 return, and what exactly does it pass to the index
selector 0x5f6c2a0 on the path that calls it?

## What is pinned

The whole 136-byte wrapper 0x5ebd130..0x5ebd1b8, end to end — a
complete function, not a lone-window fragment — plus its whole
83-byte index selector as a referenced window (the selector's own
semantics are pinned by the RE-001 later-group predicate item and
are NOT re-claimed here).

- Zero-index fast path: the return register is preset to 1 and the
  index test (test edx,edx at 0x5ebd14d) jumps straight to the
  epilogue, so an index of 0 returns 1 without reading any object
  or record-source field and without calling the selector.
- Nonzero-index path: the wrapper reads the qword at outer+0x40
  (a struct pointer), then the qword at that struct's +0x30; the
  selector's object pointer is that link value plus 0x40 (64-bit
  wrapping add, at 0x5ebd175). It builds two 16-byte records on the
  stack from the record source: record 1 is (source+0x20,
  source+0x28 - 8 wrapping) and record 2 is (source+0x40,
  source+0x48 - 8 wrapping). It calls the selector with (rdi =
  selector object, esi = index, rdx = record 1 pointer, rcx =
  record 2 pointer) at site 0x5ebd196.
- Inversion: the wrapper returns the selector's result with its
  low bit flipped (xor $0x1 at 0x5ebd19b). For the selector's
  pinned 0/1 contract that is exactly NOT: selector 0 -> 1,
  selector 1 -> 0.
- Census (whole-file scan, reproduced by the packet's census.py):
  the wrapper has exactly 3 direct calls (0x5ebd203, 0x5ec9076,
  0x5ec9394, sites only), 0 tail jumps, 0 stored qwords, 0
  RELATIVE addends; the selector has exactly 4 direct calls (this
  wrapper's site 0x5ebd196, the later-group predicate's site
  0x5f6d67e, plus 0x5df1739 and 0x5df186a, sites only), 0 tail
  jumps, 0 stored qwords, 0 RELATIVE addends.

The model in tools/selector_inversion_wrapper_115.py takes selector
results as an oracle callable, exactly the input the native wrapper
consults, and tests in
tests/test_selector_inversion_wrapper_115.py cover the zero-index
fast path with no selector call and no input reads, both inversion
directions, the exact record construction and selector-object
derivation, the wrapping -8 subtractions and +0x40 add, the signed
32-bit index passed to the selector, the missing-input guard, and
packet checks.

Out of contract, stated honestly: the stack-canary check in the
epilogue is standard hardening, not behaviour, and is not
modelled. Whether the selector or its dispatch mutates the object
is not pinned; the model treats all inputs as stable across one
call. What the wrapper's three callers pass as the record source
and index is not pinned by this item.

## Evidence

All claims bind to one artifact: artifacts/node/115/hl-node, SHA-256
a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301
(the materialized work/hl-node-115.bin hashes exactly to this digest;
see provenance/artifacts.json). The packet holds semantic records only
(records.json); instruction-level detail lives only in the verbatim
whole-function disassembly excerpts in excerpts/, generated by
export_excerpts.py with these commands:

    objdump -d --start-address=0x5ebd130 --stop-address=0x5ebd1b8 \
      work/hl-node-115.bin
    objdump -d --start-address=0x5f6c2a0 --stop-address=0x5f6c2f3 \
      work/hl-node-115.bin

Run verify.py from the clone root to re-check the digest, the manifest,
excerpt regeneration, gate instructions against the raw binary, FDE
ranges, the census, and the model tests. Instruction mnemonics in the
excerpts, such as `endbr64`, are genuine instructions present in the
target binary, not placeholders; verify.py checks the excerpts
byte-for-byte against a fresh objdump run and the gate instructions
byte-for-byte against the raw binary.

pytest-style test file runs under plain python3 via its `__main__`
