# RE-001: map node #115 counted-array drain and range destroy 0x5d5e860

## Bounded question

Open PR #2421 mapped the single-object destructor at `0x5d5e5d0`
and open PR #2423 mapped the vector destructor at `0x5d5e220`,
but neither pinned this routine. What does the routine at
`0x5d5e860` (FDE `0x5d5e860..0x5d5ef7a`, 1818 bytes) destroy end
to end? It destroys two collections of the same `0x3f0`-byte
elements that live on one object: first a counted array, drained
in reverse, then a begin/end range, destroyed forward.

## Answer, stated literally

The routine takes one object pointer in `rdi` and returns void.
It writes nothing except the two fields noted below, never frees
either collection's storage, and never deletes the object itself.

### Phase A: counted drain, in reverse

The count is the qword at obj+0x00 and the base is the qword at
obj+0x1f88. While the count is nonzero, the routine decrements
the stored count first, then destroys the element at base +
(count - 1) * `0x3f0`. The stride computation in the bytes is
(count - 1) * 64, minus (count - 1), times 16, which is
(count - 1) * `0x3f0`. So element count-1 is destroyed first and
element 0 last, and the stored count ends at 0. A zero count
skips this phase entirely.

### Phase B: range destroy, forward

The begin pointer is the qword at obj+0x1f90 and the end pointer
is the qword at obj+0x1f98, both read once at phase entry. If
begin == end nothing is destroyed and the routine returns.
Otherwise each element from begin, advancing by `0x3f0`, is
destroyed until the cursor equals end, and then begin is stored
into obj+0x1f98, so the range is left empty (end = begin). The
range storage itself is never deleted.

### Per-element destruction (both phases)

Each element is destroyed with exactly the field sequence open
PR #2421 pins for one object (same offsets, same order); the
sequence is reproduced here because it is literally this
routine's loop body in both phases, not re-claimed as a separate
result:

1. Three string fields, in this order: +0x3b8, +0x398, +0x368.
2. The tree list at element+0x318, walked inline, then the tree
   list at element+0x2e8, walked the same way: per node, the
   child list at node+0x18 is handed to the `0x5d4cfd0`
   teardown (sites `0x5d5e91f` and `0x5d5e988` in phase A,
   `0x5d5ec79` and `0x5d5ece0` in phase B), then string B is
   disposed, string A is disposed, the node is deleted with size
   `0x60`, and the walk advances to the +0x10 successor loaded
   before the node's own deletes. A null list head destroys
   nothing.
3. Fifteen string fields in descending offset order: +0x2b8,
   +0x298, +0x278, +0x258, +0x238, +0x218, +0x1f8, +0x1d8, +0x1b8,
   +0x198, +0x178, +0x158, +0x40, +0x20, +0x00.

A string field is a pointer/size/capacity-or-inline triple:
pointer at +X, size at +X+0x08, capacity-or-inline at +X+0x10.
It is inline exactly when its stored pointer equals the address
of its own capacity/inline slot; a heap string is freed as
delete(ptr, capacity + 1). For the element's +0x00 field the
inline case rejoins the phase-A loop-head count test through a
separate tail block (`0x5d5ef50`) while the heap case deletes
then rejoins it directly; both paths are the same loop test.
The teardown's own destroy order is pinned by open PR #2409 and
referenced here, not re-claimed.

### Census and consumers

Whole-binary census, reproduced by `census.py` and re-run inside
`verify.py`: this routine has exactly 9 direct calls, 0 tail
jumps, 0 stored qwords, 0 RELATIVE addends. The 9 sites, with
their caller FDE ranges, are recorded in `callers.tsv` only; no
caller semantics are claimed. The same eight caller functions
call open PR #2423's vector destructor at adjacent sites, which
is expected for sibling cleanup calls and is not an overlap:
this routine is disjoint from #2423 (`0x5d5e220..0x5d5e5c1`)
and from #2421 (`0x5d5e5d0..0x5d5e852`), and unlike #2423 it
frees no storage.

### Not claimed

What the object, its counted collection, its range collection,
the elements, trees, nodes, or strings denote; caller semantics
beyond the recorded site addresses and caller FDE ranges;
behavior on a null counted base with a nonzero count, on a null
range begin with a nonzero range, or on cyclic or dangling trees
(the model raises on these instead, where the binary would
dereference unchecked or loop).
