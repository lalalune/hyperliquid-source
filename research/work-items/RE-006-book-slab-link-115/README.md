# RE-006: reconstruct the node #115 order-slab insert and unlink bodies (book_orders.rs:81/89/137/145) and replay them on the real bytes

- Component ID: orderbook (RE-006, book transitions); neighbours exchange and risk read the same slab
- Target release and full SHA-256: Linux x86-64 node #115, `artifacts/node/115/hl-node`, a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301
- Source commit / reference commit: 0781ce04826eeefd89fe336cb8ea073be0c1de30 (no reference source is used; the reference labels were not consulted)
- Claim status: observation (bytes replayed) plus inference (field names); no progress gate is requested
- Scope included and excluded: six bodies, four copies of the slab insert and two copies of the slab unlink, with every edge stubbed; the level BTree step (callee 0x4de02d0), the vector/slab grow routines, memcpy and the overflow reporter are modelled as edges and are not reconstructed here

This packet makes it possible to rebuild, as plain code and with every branch and failure arm, how #115 puts a resting order into the 0x110 byte order slab (vacant entries start with the word 2 and carry the next free index) and links it into the per-level doubly linked list (before a chosen slot, or at the level tail), and how it takes an order out again and unlinks it: which bytes of the order, the level record, the slab header and the journal record each path writes, which total saturates or reports, which of the five panic sites fires for which corrupted link, and what the emptied-level flag is. 10,800 generated worlds were run through the real function bytes and agreed with the reconstruction on panic site, call events and every compared byte in all of them; 472 negative controls (deliberately wrong reconstructions and corrupted bytes) were replayed: 456 detected, 16 proven equivalent (see below), 0 undetected.

## Reproduce

Working directory: the repository root, Python 3 standard library only (no binutils on the path, the binary is never executed).

```
python3 tools/book_slab_link_115.py --out research/work-items/RE-006-book-slab-link-115
python3 -m unittest tests.test_book_slab_link_115
sha256sum -c research/work-items/RE-006-book-slab-link-115/MANIFEST.sha256
```

The tool refuses to run unless the SHA-256 of `artifacts/node/115/hl-node` equals the digest above. It parses the ELF with the shared `tools/elf_index.py` and `tools/fde_extents.py`, decodes each function between its FDE bounds, and runs the real bytes in the embedded x86-64 interpreter (about 1,100 lines, copied from the verified interpreter used by earlier #115 tools; the 1,139-line original gains a `call_site` field set when a stub is invoked). All files in this folder except README.md and MANIFEST.sha256 are regenerated byte for byte by the command above (checked twice, with different hash randomization and time zones). Output hashes are in MANIFEST.sha256 and the whole run is summarised by `run_digest` in results.json.

## Evidence

Coordinates are virtual addresses of the file (`.text` VA = file offset + 0x1000). Boundaries come from the FDE start table: each entry below is an exact FDE start and the FDE end is the function end (functions.tsv).

| name | start | bytes | journal record | role |
| --- | --- | --- | --- | --- |
| insert-a1 | 0x23cd2d0 | 1061 | 0x2b8 | slab insert + level link |
| insert-b1 | 0x23cd700 | 1061 | 0x2c8 | same, other journal element type |
| insert-a2 | 0x58df360 | 1067 | 0x2b8 | later-section copy of a1 |
| insert-b2 | 0x58df790 | 1067 | 0x2c8 | later-section copy of b1 |
| unlink-b | 0x58dfbc0 | 860 | 0x2c8 | slab remove + level unlink |
| unlink-a | 0x58dff20 | 860 | 0x2b8 | same, other journal element type |

Observations (all re-derived by the tool from the bytes; decode.tsv lists every instruction of the six functions with its bytes, sites.tsv every call site with its Location row):

- Slab header at the first argument: +0x00 capacity, +0x08 buffer, +0x10 length, +0x18 live count (saturating +1 on insert, saturating -1 to 0 on unlink), +0x20 next free index. Entry stride 0x110. A vacant entry has the qword 2 at +0 and the next free index at +8; the occupied entry is the order record itself, whose first four qwords are the list links: +0 prev kind, +8 prev index, +0x10 next kind, +0x18 next index.
- Insert: size = order +0xe0; the caller total (qword behind the fifth argument) gains size, and a carry calls the overflow reporter (qtys/mod.rs:831) and saturates to the maximum. With tag 1 and an in-range occupied slot (first test is a qword compare with 2) the new order is linked before that slot, taking over its prev link and the journal word `entry +0xf0`; a vacant or out-of-range slot, or any other tag, appends after the level tail (level +0x10/+0x18) and the journal word is `index * 0x110` for a vacant in-range slot and the tag otherwise. The journal record (0x2b8 or 0x2c8 bytes, pushed with a grow call when length equals capacity) gets: +0 word 2, +8 found flag, +0x10 that word, +0x18 size, +0x20 order +0xb0, +0x28 the third argument, +0x30 order +0xf0, +0x38..0x4b order +0xf8..0x10b, +0x4c order +0xd2. The slab takes the record at the free index (push when the free index equals the length, with a grow call at full capacity; reuse when it is a vacant slot, whose +8 becomes the free index; a free index above the length or onto a slot whose low dword is not 2 is the panic at slab.rs:78). Then the neighbours are patched: the previous slot (low dword 2 is the panic at book_orders.rs:81), the old prev neighbour's next link (book_orders.rs:89), or the level head when the prev kind low dword is not 1; level +0x70 gains size (carry reports and saturates) and level +0x78 counts up (saturating).
- Unlink: slot absent (index at or above length, or qword 2) writes only the word 2 to the result and does nothing else. Otherwise the entry becomes vacant (word 2, old free index at +8), count saturates down, the free index becomes the slot, a journal record (word 2, kind 3, +0x20 order +0xb0, +0x28 third argument, +0x30 order +0xf0, +0x38.. order +0xf8.., +0x4c order +0xd2) is pushed, the caller total loses size (an underflow reports through impl_sz.rs:9 and clamps to 0). With a non-null level pointer (stack argument): a sign bit in order +0xb0 is the panic at level.rs:32; a level cursor (+0x20 dword 1 and +0x28 equal to the slot) takes the removed entry's next link; when byte +0xd8 is set the level BTree step 0x4de02d0 is called with (level +0x50, key = entry +0xf0, dword = entry +0xdc); level +0x70 loses size with a clamp at 0 and no report; level +0x78 counts down; then the prev side (low bit of the removed prev kind: set means patch the previous slot's next link, panic book_orders.rs:137 when missing, clear means the level head takes the next link) and the next side (kind zero sets the level tail to the removed prev link, otherwise the next slot's prev link is patched, panic book_orders.rs:145 when missing). The result byte after the 0x110 copied entry bytes is 1 when the level head is empty and the tail kind is 0, else 0; a null level pointer gives 0.
- Edges (stubbed with the same observable contract the callers rely on): the slot reads 0x64df508 (copy), 0x64e5a28/0x64e5a30/0x64e5a38/0x64e4f88 (vector grow for the journal and the slab; which is which is decided from the argument register that feeds each call), 0x64e4ea8 (overflow report), 0x64df830/0x64df6b8/0x64df6a0 (panic with Location), and the direct call 0x4de02d0.

Inferences (kept apart): the names "order slab", "level record", "journal record" and the tag values 1/2/3 as event kinds are inferred from the layout and the Location paths (l1/src/book/book_orders.rs, l1/src/slab/slab.rs, l1/src/book/level.rs); the Location rows themselves are observations (sites.tsv).

## Implementation and comparison

The reconstruction is `spec_insert`, `spec_unlink` and `push_journal` in tools/book_slab_link_115.py: executable pure functions over a byte image, written from a full read of the disassembly (not from any reference source). `run_all` builds {1,800} worlds per copy with a fixed xorshift generator (slab length 0-8, vacant chains, consistent and corrupted link graphs, dirty high dwords in link kinds, saturating counters and totals, full and non-full vectors, every tag/index class), runs the real bytes of the copy on each, and compares: panic site (by call-site address mapped to a label, with the Location row), the ordered call events (overflow reports, vector grows, BTree step), the return value of insert, and a snapshot of the slab header, every live entry, the journal records (only the fields the function writes in the new record; the rest is stack garbage and is masked), the total, the 0x80 level bytes, the order record and the result buffer. Masks: order +0x18 and the stored entry +0x18 when no slot was found (stale frame word); the unwritten parts of the new journal record.

Negative controls (472 in controls.tsv; the tool counts all of them):
- 130 reconstruction flaws (22 on each of the four insert copies, 21 on each of the two unlink copies; each is compared with the real results of every case until the first difference): wrapping instead of saturating, wrong width of the kind tests, skipped prev link, head instead of tail, wrong journal word, dropped events, and so on. All are detected; the first detecting case index is in controls.tsv.
- Byte controls on the real code: every conditional jump flipped, plus up to 14 immediates (bit 0) and up to 24 displacements (bit 3) per function sampled by position, replayed on the cases that reach the patched address. Patches keep the instruction length and still decode.
- 16 byte controls survive and are listed in equivalent-mutants.tsv, each with a static proof the tool re-checks on every run: 14 are `mov $imm,%edx` copy lengths one byte longer (the extra byte lands in frame scratch, in the slot after the compared record, or is overwritten by the very next store), 2 are frame slots written with a lea and read only after the last `ret` (unwind landing pad). 4 jump flips sit in the unwind landing pad and are never reached by a replayed case; they are listed in unreached-mutants.tsv and are not counted as controls.

Unit tests (tests/test_book_slab_link_115.py, 25 tests, no skips, about 10 s): FDE starts and journal sizes read from bytes, digest rejection of a changed binary, call-site Location rows, hand-built worlds for every path (append, insert before, reuse of a vacant slot, saturation with reports, panic on a free index past the end, dirty vacant word, journal record fields, absent slot, only entry, middle and head removal with cursor, tree step, negative key, null level, missing neighbours) each checked against the reconstruction and the real bytes with explicit expected values, ten hand probes that make a named flaw visible, a real-bytes jump-flip control, and a small deterministic replay.

## Results and limitations

Metrics (measure.json): cases 10,800, negative controls 472, detected 456, equivalent 16, mismatches between reconstruction and bytes 0. Per copy outcome counts are in outcomes.tsv (insert: push/reuse x before/tail plus the three panics; unlink: absent, removed with level, removed without level, the three panics), a sample of every seventh case with its digest, outcome and state hash is in cases-sample.tsv.

Limits: the edges are stubbed, so the BTree step at 0x4de02d0, the vector grow routines and the overflow reporter are not verified here; the worlds are generated, not captured, so relationships between slab, level and journal that the callers guarantee (for example consistent links) are covered for the consistent case and for corrupted cases, but real call-site invariants are not shown; the third and fourth arguments of the insert and the stack arguments are only given their observed roles; field names are inferences. The replay compares masked frame garbage out of the comparison by design (listed above). No Rust is written and no progress gate is requested.
