# RE-017 #115 compact checkpoint LtHash ingress in Rust

The [compact lane comparator](https://github.com/lalalune/hyperliquid-source/pull/7366) verifies complete record digests from a local fixture. The reconstructed Rust library gains a corresponding read-only projection into `LtHashes`, so callers can use the restored accumulators without reconstructing their offsets and counters themselves. This fills the ingress between the existing compact fixture assembly and Rust hash operations. The output type also accepts the [native JSON sidecar writer](https://github.com/lalalune/hyperliquid-source/pull/7513).

The [cache constructors](../RE-011-evm-db-checkpoint-hashes-115/README.md) and [materializer](../RE-016-state-materialize-3c2e860-115/README.md) supply three `0x810`-byte records at offsets `0x1200`, `0x1b08` and `0x2410`. Each contains a `0x800`-byte payload followed by two little-endian counters. The input must be a caller-pinned compact fixture. `LtHashes::from_compact_checkpoint` verifies exact size `0x42c8` and compares the word at `+0x28` with the requested height. It only reads the three records and does not interpret any descriptors.

The existing Rust checksum API hashes each payload without its counters, as in the [selected checksum evidence](../RE-009-node115-lthash-homomorphic-and-hardfork-version/README.md). The focused regressions exercise independent lane bytes, counter preservation, a payload/counter distinction, and invalid height and shape. A compiled Rust consumer also validates a fixture generated by the existing cache block builder and compact assembler.

```sh
python3 -B research/work-items/RE-009-node115-lthash-homomorphic-and-hardfork-version/verify.py --self-test
cargo test --offline --locked --manifest-path src/node115-abci/Cargo.toml
```

The three checksum values remain distinct from a checkpoint's ABCI root. The offline projection does not establish a live checkpoint match or activate a replay engine. No captured instructions were executed.
