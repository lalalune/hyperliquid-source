# RE-019: reconstruct the node #115 JSON unsigned-integer reader 0x3ef2dc0, its digit parser 0x3ef2440 and the error-position path

With this packet the JSON text branch of the state loader's scalar reader (the routine that reads a block height such as
the `height` field) can be reimplemented as a pure function: whitespace set, sign dispatch, the exact u64 accumulator
limit (`18446744073709551615`), the leading-zero rejection, which tag of the number parser is accepted, which tags become
type-mismatch errors and which error gets a position attached. The reconstruction is checked against the real machine code
of five functions on 12,000 byte-derived cases.

- Component ID: storage (RE-019 MessagePack/JSON state loader)
- Target release and full SHA-256: Linux x86-64 node #115, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
- Source commit / reference commit: repository head `0781ce04826eeefd89fe336cb8ea073be0c1de30`; no reference source is copied
- Claim status: observation (code bytes, constants, relocations, executed traces) with inference (role names)
- Scope included: functions `0x3ef2dc0` (reader), `0x3ef2440` (digit parser), `0x3ef1a90` and `0x3ef3450` (error
  constructors), `0x4671240` (position fix-up), evaluated as real machine code. Excluded and stubbed at their call
  interface: `0x3ef20f0` (fraction/exponent/finishing tail), `0x3ef2ab0` (type-mismatch peek), `0x5c56920` (position
  helper), the slots `0x64e0900`, `0x64e0910`, `0x64e1340`, `0x64e0b08`, `0x64df4a0` and the panic slot `0x64df520`.

## Reproduce

```
python3 tools/re19_json_u64_115.py --out research/work-items/RE-019-json-u64-reader-115
python3 -m unittest tests.test_re19_json_u64_115
```

The tool checks the binary SHA-256 first, reads every code byte, constant and relocation from the ELF with the
repository interpreters (`tools/elf_index.py`, `tools/fde_extents.py`) and the concrete x86-64 evaluator of
`tools/re16_state_materialize115.py`, and never executes the binary. It runs in about 10 s with about 330 MB. Two runs
give byte-identical output.

## Evidence

All addresses are virtual addresses of #115. Files (all generated by the tool):

| File | Content |
| --- | --- |
| `constants.json` | whitespace mask `0x100002600` (bytes 9, 10, 13, 32), accumulator limit `0x1999999999999998` and its successor, last-digit limit 5, error codes 5 / 13 / 13, three vtable targets, field offsets, relocated slot targets |
| `cases.tsv` | first 1,200 of the 12,000 cases with input hex, start index, result class, call sequence and final index |
| `outcome-classes.tsv` | outcome counts over all 12,000 cases |
| `negative-controls.tsv` | 61 negative controls and the first case that caught each |
| `summary.json`, `measure.json` | counts and a SHA-256 over every case's full result |

Observed behavior of the reader `0x3ef2dc0(de)` (decoder fields: `+0x18` data pointer, `+0x20` length, `+0x28` index):

1. Bytes `09 0a 0d 20` are consumed one at a time (the index is stored after each). At end of input it builds code 5 with
   `0x3ef1a90` and returns `(1, error)`.
2. `-` (0x2d) is consumed and `0x3ef2440` is called with positive = 0; an ASCII digit calls it with positive = 1 and
   consumes nothing; any other byte (including `0x0b`, `0x0c`, `+`, `.`) calls the type-mismatch helper with the vtable
   at `0x647b210`, then `0x4671240`, and returns `(1, error)`.
3. Number tag 3 returns `(1, error)` unchanged (no position fix-up). Tag 1 returns `(0, value)`. Tag 2 returns `(0, value)`
   only if the value's sign bit is clear; otherwise it reports a signed mismatch through slot `0x64e0910`. Tag 0 reports a
   float mismatch (vtable `0x646b0f0`) through slot `0x64e0900`. Both mismatch errors then go through `0x4671240`.

Observed behavior of the digit parser `0x3ef2440(out, de, positive)`:

1. End of input: code 5 through `0x3ef3450`, tag 3.
2. First byte `0`: a following digit gives code 13 through `0x3ef1a90`; otherwise `0x3ef20f0(out, de, positive, 0)`.
3. First byte `1`..`9`: digits are accumulated while the accumulator is at most `0x1999999999999998`, or equals
   `0x1999999999999999` and the next digit is at most 5. A digit that would overflow calls slot `0x64e1340` with the
   accumulator and the unconsumed index (flag 0 gives tag 0 plus an f64 word, flag nonzero gives tag 3). A non-digit or
   end of input calls `0x3ef20f0(out, de, positive, accumulator)`.
4. Any other first byte: code 13 through `0x3ef3450`, tag 3.

Position path: `0x3ef1a90` clamps `index + 1` to the length, `0x3ef3450` uses the index unclamped; both call `0x5c56920`
and tail-call slot `0x64e0b08` with the code pointer and the result. `0x4671240` returns an error unchanged if its line
word (`+0x18`) is nonzero; otherwise it rebuilds it through `0x3ef3450` using the code in word 0, releases the old
0x28-byte object through slot `0x64df4a0` and returns the new one.

## Implementation and comparison

`tools/re19_json_u64_115.py` holds `model_reader`, `model_number` and an `Env` that models the stubbed callees and the
error objects. For every case the real code and the model run against the same deterministic callee results, and the
return registers, the `ParserNumber` pair, the final decoder index, the callee-saved registers, the stack pointer and
the ordered call trace (names and arguments) must agree.

Cases: 12,000 (6,000 per entry), generated by a fixed xorshift generator from nine token families (digit runs up to 22
digits, signed runs, arbitrary and boundary bytes such as `/` `:` `0x0b`, whitespace-only, accumulator-limit strings,
leading-zero forms, malformed minus forms, mixed tails) with random start index and random stub results.

Negative controls (61): 32 model mutants (whitespace set, codes, limit and last-digit comparisons, tag mapping, fix-up
rules, vtables, argument flags), 26 single-byte code corruptions at listed addresses (each checked against the expected
old byte first), a corrupted binary digest, an address past `.text` and a start inside another function without its frame.

## Results and limitations

- 12,000 cases, 0 mismatches; 61 of 61 negative controls detected. Counts are in `measure.json`.
- The line-nonzero return of `0x4671240` is covered only by a corrupted-byte control; no reachable reader path hands it
  an error with a line, so that branch is not exercised by model cases.
- Panic slot `0x64df520` branches (index of -1 in `0x3ef1a90`, accumulator carry, zero index after a sign) are modelled
  as unreachable; the tool fails if a case reaches them.
- The stubs are not proofs of what the called code does. `0x3ef20f0` is where fraction and exponent grammar and the
  PosInt / NegInt choice live; its result tags are inputs here, so what makes tag 2 appear is not established.
- Role names (reader, digit parser, error constructor) are inferences from code shape. No claim of live snapshot parsing,
  Rust type identity or serde_json version is made. Which loader field calls the reader is stated only through the
  existing observation that the height scalar path reaches `0x3ef2dc0`; this packet does not add a caller map.
- No gate is requested; the storage component stays unchanged.

Next question: reconstruct `0x3ef20f0` (needs a wider instruction decoder for the SSE integer unpack at `0x3ef2177`) to
decide when the number parser yields tag 1 versus tag 2 for `-0`, fractions and exponents.
