# RE-016: reconstruct the db-home preparation trio 0x38b3830, 0x44681e0, 0x38b3ad0 and the mode-0 sibling composer 0x3915d30 of node #115

With this packet, the three direct callees that the composer `0x434b9f0` runs before its block builder (`RE-016-state-compose-434b9f0-115` left them as opaque stubs and asked what `h`, the second argument of the block builder, is) can be rebuilt as pure Python models of their complete call flows. `0x38b3830(out, ctx)` formats the 0x30-byte `ctx` as text, probes it, emits a gated diagnostic, removes the `<text>/<kind 2>` sub-directory when it exists, and moves `ctx` to `out`. `0x44681e0(out, vec, ares, mode)` formats the same kind of text, creates that directory (`0x1ff`, recursive) when the probe says it is missing, copies the source tree with the `-al` flag, and in mode != 0 additionally copies into `<text>/checkpoint/<vec+0x18>/<kind 2>` (unless a marker probe says the target is a file), runs a second operation, copies `lt_hashes.json`, and always writes the state file `<text>/<static item>` from `vec +0x18`. `0x38b3ad0(state, a, b)` formats and creates a directory text, collects 16-byte items into a sorted ordered map, clones the state's byte string, and returns a 0x40-byte block `{1, 1, n, ptr, n, map root, map height, map length}`, so `h` is that block's address. The second caller of the trio, `0x3915d30(out, a, b, ctx)`, is the mode-0 sibling of the composer: it fetches a list of 32-byte entries (`0x4468e30` on `a +0x1b18`), keeps the entry whose key word `+0x18` equals `b` (freeing the text of every other entry and of all entries after it), runs the trio on a stack copy of `ctx` with `mode = 0` (so the checkpoint route is only taken by the composer `0x434b9f0`, which passes 1) and hands the result block and the entry to the block builder; it is modelled with the real trio running nested inside it. The models match the real #115 machine code on all 16,800 cases (4,200 per function) with every reachable body instruction executed, every operation order the cases produce (65 distinct plans) satisfies the structural invariants of the reconstruction, and all 52 negative controls are detected.

- Component ID: `abci` (work item RE-016, state materializer call chain; the `RE-016-state-compose-434b9f0-115` packet names these three callees as its next question)
- Target release and full SHA-256: `artifacts/node/115/hl-node`, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
- Source commit: main `0781ce048` (no source; binary-only). The reference tree was not used.
- Claim status: reconstruction of the control flow, argument construction, ordering and state effects of the three bodies, validated against the evaluated #115 machine code. Every external operation (format, probes, directory and file operations, allocator, log, panic, sort, ordered-map build) is a stub that returns a chosen outcome; their internal behaviour is not claimed. Role names (directory probe, copy, hard-link flag, checkpoint directory, state file, Arc-like block) are inferences from the stub argument shapes and the compact format pieces in `.rodata`, not proven by any symbol.
- Overlap disclosure: `RE-011-evm-db-checkpoint-hashes-115` already maps `0x3915d30` as the checkpoint selector (stride 0x20, key word at `+0x18`, sentinel test, relocated slots `0x64e61d0` and `0x64e9528`) and treats the three preparation callees as boundaries; this packet does not repeat that map but reconstructs the selector loop, its frees and the nested trio flows as executable models checked against the machine code. `0x44681e0` is mapped by `RE-009-node115-checkpoint-lifecycle` (static lifecycle table); `0x38b3830` and `0x38b3ad0` appear only in census rows.
- Scope: included the complete FDE `[0x3915d30, 0x391601f)` (751 bytes, 187 instructions) of the second caller and the complete FDEs `[0x38b3830, 0x38b3ac1)` (657 bytes, 150 instructions), `[0x44681e0, 0x4468b62)` (2,434 bytes, 513) and `[0x38b3ad0, 0x38b3f8c)` (1,212 bytes, 256), all three decoded linearly to their FDE ends, their `.got` slots and direct callees, their call sites, and the two-site caller sets. Excluded: the list producer `0x4468e30`, the entry-string producer `.got 0x64e61d0` and the internals of every other stubbed callee (the directory probe `0x1500a60` and file probe `0x1500d20` are mapped by `RE-009-node115-checkpoint-lifecycle`, the block builder `0x38c2690` by `RE-001-node115-hash-diagnostic-snapshots` and `RE-011-evm-db-checkpoint-hashes-115`), the unwinding landing pads (listed, not evaluated), and the composer itself.

## Reproduce

Working directory: repo root. Python 3, stdlib only, plus the shared `tools/elf_index.py` and `tools/fde_extents.py`. No external program is called and the binary is never executed.

```
python3 tools/re16_db_home_chain115.py --out research/work-items/RE-016-db-home-chain-115
python3 -m unittest tests.test_re16_db_home_chain115
```

The tool checks the input SHA-256 first. It writes `call-sites.tsv`, `cases.tsv`, `constants.json`, `format-pieces.tsv`, `instructions.tsv`, `measure.json`, `negative-controls.tsv`, `operation-plans.tsv`, `outcome-classes.tsv`, `slot-roles.tsv` and `summary.json`. Two regenerations are byte-identical. The run takes about 35 s and about 0.55 GB of peak memory (the 12,600 generated cases are held in memory).

## Evidence

All coordinates are virtual addresses in node #115 (`.text` maps VA = file offset + 0x1000). Every number in the evidence files comes from ELF bytes read with `struct`: `.rela.dyn` RELATIVE and GLOB_DAT entries, the FDEs from `.eh_frame`, and code bytes. Instruction forms come from fixed byte patterns decoded by the tool's evaluator (the decoder gained the 16-bit `66 c7` immediate form for this packet).

- **Callers.** A byte scan of every `.text` offset as `e8 rel32` finds exactly two sites for each callee: the composer `0x434b9f0` (`0x434bb32`, `0x434bb4f`, `0x434bb5e`) and the second function `[0x3915d30, 0x391601f)` (`0x3915eb4`, `0x3915ed5`, `0x3915ee4`) that calls the same trio in the same order (the second caller passes `ecx = 0` to `0x44681e0`, the composer `ecx = 1`; both pass `esi = 0` to `0x38b3ad0`). No RELATIVE addend names any of them.
- **Slot roles** (`slot-roles.tsv`, from RELATIVE addends): `.got 0x64df6f0` -> `0x1680500` (format into a String), `0x64df6e8` -> `0x141e3a0` (format to a new String), `0x64df6a0` -> `0x1680c30` (panic with message, length, two statics), `0x64df9f0` -> `0x5c87d50` (diagnostic emission), `0x64df4a0` -> `0x635de30` (deallocate: ptr, size, flags 0), `0x64e0928` -> `0x1500a60` and `0x64e0950` -> `0x1500d20` (the two path-shape predicates of RE-009), `0x64e0940` -> `0x5c8f4c0` (directory creation with `{0x1ff, recursive}`), `0x64e0a18` -> `0x15028f0` (the RE-009 `cp` adapter, flag 1 = `-al`), `0x64e0a58` -> `0x1505de0` (file copy), `0x64e09e0` -> `0x1505a50` (an operation on a joined path, role unresolved), `0x64e0028` -> `0x15020f0` (path operation in `0x38b3ad0`), `0x64df480` -> `0x6355830` (allocator), `0x64df490` / `0x64df498` -> `0x141e251` / `0x141e264` (two allocation-error exits), `0x64e8ff8` -> `0x36e4490` (large sort), `0x64df508` is the `memcpy` import. The sibling `0x3915d30` adds `0x64e61d0` -> `0x38c2e00` (called with `(&s, a, b, 0)`; `RE-011-evm-db-checkpoint-hashes-115` maps it as the helper that saves the current records, and in the model it returns an owned (cap, ptr, len) value that `0x3915d30` frees), `0x64e9528` -> `0x38c2690` (the block builder of the composer) and `0x64df830` (expect-failure exit, resolved by the tool but not further named).
- **Compact format pieces** (`.rodata`, parsed from the bytes by `parse_pieces()` into `format-pieces.tsv`; the harness refuses a text whose placeholder count differs from the expected one; `0xc0` = placeholder, next byte = following literal length): `0x43b857` is `{}`, `0x43aa84` is `{}/{}`, `0x434739` is `{}/checkpoint`, `0x44f3c9` is `{}/lt_hashes.json`; `0x4659e8` holds the 10-byte operation name `remove_dir`; `0x465a05` holds `-R`, `-al` and `cp`. The panic messages at `0x7a15ae`/`0x7d31d2` (length 0x37) and `0x7d3212`/`0x7a1618` (length 0x2b) are the Display-error and `Result::unwrap()` texts.
- **Gate word** `0x64f01d8`: a 32-bit word; non-zero makes each body emit one diagnostic through `0x64df9f0` at fixed points (`0x38b3830`: after the first probe in both branches; `0x44681e0`: after the format, after the second operation and after the state write; `0x38b3ad0`: before the first format).
- **Kind byte.** `0x38b3830` and `0x44681e0` store the byte 2 in a local and pass it to the Display function in `.got 0x64e2078`; `0x44681e0` also passes `esi = 2` to `0x1696b90`. The `u64` in `vec +0x18` is shown through `.got 0x64e0a98`.
- **Flows** (`call-sites.tsv` lists every call site with their role and whether they sit after the `ret`; `outcome-classes.tsv` counts cases per outcome):
  - `0x38b3830`: format `{}` of `ctx` (a failed format panics) -> probe -> optional diagnostic -> if probe true: format `{}/{}` of the text and the kind, probe again, if true `remove_dir` (error object dropped through its vtable) -> free the sub text -> copy 0x30 bytes of `ctx` to `out` -> free the text.
  - `0x44681e0`: format `{}` of `ares` -> optional diagnostic -> probe, create the directory when false (a creation error goes through `0x1500b90` and the unwrap panic) -> `{}/{}` of `vec`'s string and the kind -> `cp -al` source to the text (an error panics). Mode 0 then skips to the common tail. Mode != 0: `{}/checkpoint`, `{}/{}` with `vec +0x18`, free, `{}/{}` with the kind, `0x1696b90` join and file probe; when the probe says file, free and go to the tail; else a second `cp -al`, `0x1696b90` join and `0x1505a50`, optional diagnostic, `{}/lt_hashes.json` of `vec`'s string, and when that is a file `{}/lt_hashes.json` of the checkpoint text and a file copy (errors panic). Tail: `{}/{}` with the static item at `0x648b880` (Display `0x46dd7f0`), the state write `0x422f320(vec +0x18, text)`, optional diagnostic, copy `ares` to `out`, free.
  - `0x3915d30`: `.got 0x64e61d0(&s, a, b, 0)` (`0x38c2e00`) writes an owned (cap, ptr, len) value, `0x4468e30(&list, [a+0x1b18]+0x10)` returns (cap, ptr, len); cap `0x8000000000000000` is the error niche (unwrap panic with `[rsp+0x18]`); an empty list or no usable entry reaches the expect-failure exit `.got 0x64df830`. Per entry: key != b -> free its text when its capacity is non-zero; key == b and capacity != `0x8000000000000000` -> found; key == b with that sentinel capacity -> skipped without a free. After the found entry every later entry's text is freed (non-zero capacity), the list buffer is freed with size `cap << 5`, then `0x38b3830`, `0x44681e0` (mode 0) and `0x38b3ad0` run on stack values, the block builder `.got 0x64e9528` gets (out, third result, entry), and the entry text and the first String are freed; it returns `out`.
  - `0x38b3ad0`: optional diagnostic -> format `{}` of `state` -> path operation `0x15020f0` (error panics) -> allocate 0x10 -> `0x37befd0` fills the item count -> for n == 0 free the 0x10 buffer (`n << 4`), for n >= 1 a sort (`0x4375ed0` below 0x15 items, the `0x36e4490` slot at 0x15 and above, none for n == 1), allocate a 0x70 leaf node and bulk-build the map -> clone `state`'s bytes (allocate + memcpy, empty -> dangling 1) -> allocate 0x40 -> free the text, drop `state` -> return the block.

## Implementation and comparison

`tools/re16_db_home_chain115.py` contains the evaluator (ELF image, byte-pattern decoder, concrete x86-64 machine with strict regions), four pure reconstructions `model_a`, `model_b`, `model_c` and `model_d` (the last composes the other three with the stack addresses of its own frame) that produce the expected call trace, abort kind, output bytes and block contents, and the harness. In each case the stubs record every external call with symbolized arguments (stack offsets relative to the entry rsp, region offsets, absolute values; format arguments with their pointee bytes) and scramble all caller-saved registers; the reconstruction must reproduce the trace, the return value, the 0x30-byte output (or the 0x40 block, the 0x70 leaf and the cloned string), the untouched inputs, and the callee-saved registers and rsp (aborting cases must reproduce the trace up to the panic or allocation-error exit). The case generator draws, from deterministic SHA-512 streams, the gate word (zero, one, all ones, random), format failures, probe results, creation/copy/state-write errors, string capacities (zero or not), the mode byte (including 0x100 and 0x7f, which test only the low byte), allocation failures, state lengths (0, 1, 7, 33, 64) and item counts (0, 1, 2, 3, 5, 19, 20, 21, 22, 40).

Operation plans: each case trace is reduced to its ordered file-system operations (`plan_of`: probes, directory creation, copies, joins, the state write, the removal, the path operation) and checked by `plan_errors()`: `0x38b3830` is one of `()`, `is_dir`, `is_dir is_dir`, `is_dir is_dir remove_dir`; `0x44681e0` is a prefix (when it aborts) or exactly one of the eight complete orders (`is_dir [create_dir] cp` followed by the state write, the marker route `join_kind is_file`, or the full checkpoint route `join_kind is_file cp join_kind op_09e0 is_file [copy_file]`, each ending in `write_state`) and never leaves the source copy in mode 0; `0x3915d30` never joins, copies a file or runs the second operation and ends with the state write. `operation-plans.tsv` counts the cases per function, route, outcome and order (0 violations over all 16,800 cases).

Controls (`negative-controls.tsv`, 52): 12 model mutants (probe inverted, gate ignored, kind byte 1, name length 11, leaked sub text, short output, mode inverted, `-al` flag 0, small sort always, 0x68 leaf, weak count 0, key compare off by one), 25 code-byte mutants (kind bytes, name length, probe and mode branches, `cp` flag, creation mode and recursive bytes, `esi`, the three allocation sizes, the single-item and small-sort bounds, the item stride, the two block counts, the empty branch, and for the second caller the list offset, the error branch, the entry stride, the sentinel and key tests, the buffer size and the mode register), 4 bit-flip mutants of format operands and a free test, one flipped `.text` byte (input digest refusal), one address past `.text`, and 9 plan mutations (removal before the second probe, a repeated removal, the dropped state write, swapped copy and join, a copy-file without its marker probe, a mode-0 join, a directory creation after the copy, a join in the mode-0 sibling, a second source copy), each of which violates an invariant.

## Reading the evidence files

- `summary.json` and `measure.json` hold the counts quoted above; `measure.json` has exactly the keys `cases`, `negative_controls` and `negative_detected`.
- `cases.tsv` lists every eighth case of each function (function, case index, mode byte, gate flag, outcome, call count, a 16-hex digest of the output or block, match flag); the other cases are regenerated from the fixed SHA-512 streams by the tool.
- `outcome-classes.tsv` counts cases per function, outcome (`ok`, `panic`, `oom`) and gate state; `operation-plans.tsv` counts them per ordered file-system operation list.
- `instructions.tsv` lists every decoded instruction of the four FDEs with its bytes, whether it lies before or after the `ret`, and whether any case executed it.
- `call-sites.tsv` and `slot-roles.tsv` give every call site and `.got` slot with the role the harness assigns; `format-pieces.tsv` the four format texts parsed from `.rodata`; `constants.json` the FDE coordinates, body digests, caller sets and the slot addresses of the gate word and the two Display functions.
- `negative-controls.tsv` lists the 52 controls with a detected flag; a control that is not detected makes the tool exit non-zero.

## Results and limitations

- 16,800 cases (4,200 per function), 0 mismatches. Body instructions before the `ret` executed: `0x38b3830` 96/96, `0x44681e0` 332/332, `0x38b3ad0` 155/155, `0x3915d30` 130/132 (the two others are alignment NOPs that no path falls into). After the `ret` sit the failure arms and the unwinding landing pads: 26/54, 67/181, 45/101 and 12/55 executed (the executed ones are the panic and allocation-error arms; the pads are not evaluated).
- 52/52 negative controls detected (`measure.json`: cases 16800, negative_controls 52, negative_detected 52); 65 distinct operation plans, 0 invariant violations.
- Outcome classes (`outcome-classes.tsv`): ok, panic and (for `0x38b3ad0`) allocation-error exits, each with the gate word zero and non-zero.
- Not claimed: what the stubbed operations do (the probes, `cp`, the `0x1505a50` and `0x15020f0` operations, the block builder), what the state file and the numbered directory mean at run time, what value `vec +0x18` takes, the real fork of the composer, any file system effect, or a Rust implementation. No component gate is requested; `abci` stays at its current progress.

Next question: who calls the sibling `0x3915d30` and the composer `0x434b9f0`, and which values bind `a`/`b` (the list owner and the entry key) and `ctx` on those paths? The list producer `0x4468e30` and the save-records helper behind `.got 0x64e61d0` (`0x38c2e00`) are the stubs that decide which entry (key `b`) reaches the trio.
