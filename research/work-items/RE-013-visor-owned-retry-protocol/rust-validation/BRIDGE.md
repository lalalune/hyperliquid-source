# Source/build bridge and replay scope

This is the additive implementation phase of the existing PR1599 retry extension. All54 pre-code files and all336 historical duration public-manifest entries remain exact. The new source has a real explicit local dependency on the unchanged duration crate. The original phase files are never rewritten to pretend that source existed before expected outputs were frozen.

`SOURCE-FREEZE.json` binds both five-file source packages, the input-only client, source proof, harness, actual preparation receipts, exact toolchain payload inventory and draft-correction history. `LOCK-ADMISSION.json` preserves the initial8 noncompiling preparation commands. `DRAFT-CORRECTION.json` preserves the subsequent ninth formatting command, the initial client/test copies and the final correction: remove an unnecessary local mut identified by static peer review and add the root-requested all-reached option0 test. Production library and old dependency bytes did not change in that correction. Historical draft hashes are intentionally not presented as final source identities.

The build harness rehashes both actual source trees and all frozen harness inputs before any subprocess. It rejects symlinks, unexpected source entries, parent workspaces and lexical/canonical ancestor Cargo config files. It admits the actual Cargo manifests and generated locks, then confirms full offline/locked metadata for the two packages and their four targets. It copies the full actual packages into each independent build tree and verifies those exact files again after qualification. No expectations, provenance or packet Python code are copied into candidate source or client directories; the comparison process alone reads them. The Rust client receives input bytes through stdin only.

Runtime environments are explicitly constructed. HOME, when present, is preserved and never redirected; Cargo home is a fresh private directory. RUSTC/RUSTDOC are pinned real toolchain programs, build flags are explicit and compilation is offline/locked with overflow checks and denied warnings. Existing bin/lib inventory covers97 toolchain payload files and exact symlink targets. Compiler version queries, selected actual clang/linker identities and SDK settings/libSystem inputs are retained. The host OS, dyld and entire SDK are not hermetically pinned, and these host tools are not claimed to be the target compiler.

The planned run builds debug and release libraries plus an input-only client, with eleven new integration tests and the unchanged duration tests selected explicitly. It performs one same-path clean rebuild only after archiving the earlier compared library/dependency/client artifacts, then a separate-directory build. Each artifact retains exact bytes in private content-addressed gzip storage; public receipts contain identities and equality results without distributing private compiled bytes. Different executables remain different: there is no mask or unsupported attribution of debug directory differences.

The harness proposes24 separately compiled full-stream mutations:21 native relation changes and3 safe-policy changes. Each must emit all775 canonical outputs in both profiles, and the complete output values/bytes are compared. Policy controls must differ only among the48 policy cases. One further option1 control must produce identical775-row streams, then fail the dedicated focused option test with exit101 and the actual single-test failure record. Compilation errors, timeouts, malformed/partial outputs, or a neutral full-stream mutant fail qualification. The option control demonstrates the explicitly disclosed trace blind spot; it is not counted as a stream mutant kill.

Eleven comparator controls challenge completion, IDs, duplicates, order, values, LF, duplicate JSON keys and truncated JSON. Twenty-seven malformed input streams plus an extra-argument invocation must return2 and emit no partial stdout. The framing caps and buffered-batch rejection are new client policies. They do not add native domain exclusions to the library. Empty input is malformed under the frozen protocol.

Planned totals, not observations at freeze:220 harness subprocesses,56 complete value streams,24 full-stream mutants in each profile, one focused option control in each profile. Of those proposed commands,28 malformed/argument checks expect exit2 and2 focused test assertions expect exit101. No result may be reported as observed until the gated run actually completes; the final receipt derives counts from command records.

Every run records exact stdout/stderr bytes, actual command arguments, cwd, code/completion, stdin identity and elapsed time. A timeout retains partial streams; a launch OSError gets a separate diagnostic instead of being falsely attributed to child stderr. Required failures stop the run and retain its partial command log. A failed process never counts as a killed value mutant. Logical paths are a documented receipt projection with a separate private mapping; raw stdout/stderr are never rewritten. Any raw stream containing a private HOME prefix stops public qualification and stays private. Compiled artifacts, Cargo runtime caches and private maps are not public packet payloads.

For post-source static replay, the harness copies exactly the original54 pre-code files into an isolated path with no retry source/client. It invokes the unchanged verifier there with the authenticated captured input and the real unchanged duration dependency root. The frozen physical-set and source-absence guards remain active. `precode-frozen-replay.json.gz` is the actual root pre-code replay, raw SHA2565dbe0cf97c417f9a8a431f3ed94ab62ef0c1a8c31d40f957419b7733532dd548, independently matched by the pre-code peer. Its only difference from the historical author report is the subsequent explicit freeze-admission field. The later harness requires exact raw equality to this actual frozen-admission report; it never relaxes the original verifier or rewrites historical raw output.
