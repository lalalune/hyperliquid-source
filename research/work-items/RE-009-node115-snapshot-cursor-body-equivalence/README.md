# RE-009: compare two snapshot cleanup cursor bodies

The [geometry census](../RE-009-node115-snapshot-cursor-geometry-census/) records literal operands for the cursor at `0x244b6e0`. This packet compares that cursor's full #115 FDE body with the decomposed inline cursor at `0x2442070` to establish which parts of that decomposition carry over.

Both bodies contain 225 instructions across 938 bytes. All 36 direct branches stay inside their respective FDEs and have identical encodings. The 48 differing instructions have identical encodings except for their final four-byte operands. Forty operands use one of five geometry values, all increasing by `0x580` in the second body. The remaining eight RIP-relative operands resolve to the same ELF addresses in both bodies. Those operands include the shared release slot, diagnostic descriptors and diagnostic call slot. The other 746 bytes match exactly. The alternate cursor therefore admits the same instruction-level decomposition with these five geometry substitutions, including the same direct-branch structure and diagnostic references.

Run `python3 research/work-items/RE-009-node115-snapshot-cursor-body-equivalence/verify.py` from the repository root with LLVM objdump and dwarfdump on PATH. The verifier checks the pinned artifact, FDE endpoints, instruction coverage, branch targets and operand comparison. It rechecks the comparison after independently mutating a fixed opcode and each changed operand in both bodies. The recorded windows and FDE rows preserve the original bytes and address bounds. This is static evidence for this pair. It does not validate runtime callbacks, object lifetimes or broader snapshot acceptance.
