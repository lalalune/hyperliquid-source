# RE-001: later-group predicate 0x5f6d600 (node #115)

Bounded question: for one element of one group, does any later group
decide against it, in the sense the filter pass 0x5f6d700 uses when it
calls this predicate at 0x5f6d7e1?

## What is pinned

The whole 244-byte predicate 0x5f6d600..0x5f6d6f4, end to end, plus
the whole 83-byte index selector 0x5f6c2a0 it calls, as a referenced
window (the selector's dispatch callee is NOT re-claimed here). This is
one complete function with three arms, not a lone-window fragment:

- Group 0 arm: entry 0's element count is ((entry0.end - entry0.begin)
  as a wrapping signed 64-bit difference, arithmetic-shifted right by
  3), taken at 32 bits, minus 1 (32-bit wrap). When the element index
  (r8d) is not that last index, the predicate returns 1 at once. When
  it is the last index, entries 1..count-1 are scanned and any entry
  with begin != end returns 1 at once; all empty returns 0 (a count
  <= 1 returns 0 without scanning). A begin-past-end entry counts as
  non-empty, because the test is equality, not ordering.
- Non-zero-group arm: later groups are scanned in index order from
  group + 1 up to the signed group count. Empty groups are skipped.
  For each non-empty later group the selector 0x5f6c2a0 is called with
  (obj, esi = later group index, rdx = the predicate's rsi,
  rcx = the predicate's rdx); a nonzero selector result returns 1 at
  once, a zero result continues. When the scan reaches the count, the
  predicate returns 0. The group count is re-read from obj+0x10 on
  every iteration.
- The selector (referenced, not re-claimed): returns 0 when
  signed32(obj+0x14) <= index; otherwise it picks the inline slot
  (index*16 + obj+0xb8, index <= 7 unsigned) or the heap slot
  ((index-8)*16 + obj+0xc0) and tail-jumps to dispatch 0x5f6a820 with
  (rdi = [obj], rsi = 1 if index > 0 signed else 0, rdx = selected
  slot, rcx = incoming rdx, r8 = incoming rcx).

The model in tools/later_group_predicate_115.py takes selector results
as an oracle callable, exactly the input the native loop consults, and
tests in tests/test_later_group_predicate_115.py cover both arms, the
32-bit last-index wrap, begin-past-end entries, empty-group skips,
first-hit stopping, and guards.

## Census

Whole-file scan, reproduced by census.py: the predicate has exactly
2 direct calls (the filter pass's site 0x5f6d7e1 and the site-only
0x5da51be inside the 0x5da5100 function, which inverts the result),
0 tail jumps, 0 stored qwords, 0 RELATIVE addends. The selector has
exactly 4 direct calls (this predicate's site 0x5f6d67e plus
site-only 0x5df1739, 0x5df186a, 0x5ebd196), 0 tail jumps, 0 stored
qwords, 0 RELATIVE addends.

## Unknowns (not claimed)

- The dispatch callee 0x5f6a820's semantics: what makes the selector
  return nonzero for a later group is not pinned here.
- Whether the selector or dispatch mutates the object: the predicate
  re-reads the group count each iteration, but the model treats the
  count and entries as stable across one call.
- The 0x5da5100 caller's purpose (it inverts the predicate result):
  recorded as a site only.
