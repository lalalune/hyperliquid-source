# What this correspondence establishes

This is a bounded source/configuration observation over two selected intervals.
It is not a historical build attribution, a function census or a runtime theorem.

1. The six licensed source/header/LICENSE inputs have fixed complete sizes and
   SHA-256s in the collector, plus upstream commits and Git blobs in
   UPSTREAM.json. A mutable manifest cannot repin a modified source. Their
   immutable admitted bytes alone populate fresh private build directories.
2. Each full captured image is independently admitted as immutable bytes under
   its exact maintained digest. The selected VA interval has one executable
   section and one executable PT_LOAD mapping; those mappings must agree on
   its file offset and VA. Every reference byte comes from that same admitted
   object. No later path read supplies target facts or native-provider input.
3. The exact qualified GNU binaries and installed header identities are checked
   before building. Actual macros and dependency output establish the active
   Linux/x86/assembler/BMI2/CET closure. The compiler reads exact staged source,
   real portability macros and actual system headers. No substitute definitions,
   linker script, captured code, manual opcode or padding patch supplies code.
   Installed tools/headers are trusted stable files checked again afterward;
   this does not establish atomic execution provenance or historical flags.
4. The built own object is read once as immutable bytes. Its actual x86-64 ET_REL
   section table, aliases, visibility, NOTYPE/zero-size attributes and text
   relocation records define the observation. The X1 label starts at text
   offset zero, X2 at 1,149, and the exact text end is 2,418. No STT_FUNC or
   nonzero symbol size is invented; nothing is trimmed before comparison.
5. Source-defined X1-to-X2 and X2-to-text-end byte strings are compared whole
   against A and B in each target. No raw byte is normalized. Positive success
   requires zero text relocations and zero mismatches, including alignment
   bytes, constants, register encodings and local branch fields. The native
   listing and exported text separately bind the immutable own object; GNU
   reads only a tiny private copy of that snapshot.
6. The unique selected text is 2,418 bytes per own object and per target. One
   positive build performs four A/B checks over 4,836 target-byte positions;
   two positive builds perform eight checks over 9,672 positions. Repeated
   comparisons are not counted as additional recovered functions or code.
7. The second unchanged source/configuration build produces an identical whole
   own object and text. This qualifies reproducibility of this measured recipe.
   It neither reconstructs the original executable nor identifies its compiler.
8. The same-source CET-disabled control is a real different configuration. Its
   text length and source label partition remain 2,418 and 0/1,149, while all
   comparisons reject its 281 A plus 276 B byte differences per target. The
   full mismatch arrays are retained; size agreement alone is insufficient.
9. The official 1.5.7 source/header blobs differ from 1.5.6. Their measured
   compiler-produced line-marker-free assembly output is exactly identical
   under this non-Windows recipe. No hand editing or machine-code mask creates
   that equality. No 1.5.7 object is built or assigned a hypothetical hash.
   This limits release attribution; it does not establish a unique version.

The resulting exact claim is that the pinned licensed source/configuration can
generate all selected captured bytes. The original archive, fork, crate graph,
commit, flags, compiler, original source/symbol identity and runtime context
remain unknown. Source-level register/record comments are not independently
promoted into caller, table, ABI, CPU-support or all-input behavior conclusions.
No Rust reconstruction, whole-ELF equality or component gate follows.
