# evm: ReadPrecompileResult codec (Ok / OutOfGas / Error / UnexpectedError) on node #115

This packet makes the node #115 EVM read-precompile result enum `ReadPrecompileResult`
reconstructible end to end: its Rust name, its four wire names and tags, the exact-name `&str` and `&[u8]` visitors with their
length jump tables and lossy unknown-variant error path, and the msgpack
serializer, including the Ok arm `{"Ok": [gas_used, bytes]}`, the struct-as-map
key rules, every reserve edge and both writer-failure exits. The
reconstruction is proven against the original machine code on 5,696 cases.

- Component ID: `evm`
- Target release and full SHA-256: Linux x86-64 node #115 `artifacts/node/115/hl-node`, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
- Source commit: `05bc2de303c05525b71e7e257426e741bc66a390` (origin/main at the time of the run)
- Claim status: behavior reconstructed for three bodies (static interpretation of the original bytes, callees stubbed); no gate change claimed
- Scope: the three #115 bodies that carry the four names: the `&[u8]` visitor `0x2692850`, the `&str` visitor `0x2692a20` and the msgpack serializer `0x5af5570`, plus the name pool `0x64373c8` and the three `.rodata` jump tables they index. The callees (u64 writer `0x57cfd20`, bytes writer `0x531cd60`, grow `0x5963a10`, unknown-variant `0x17fbba0`, lossy conversion/free slots) are modelled by role only.

## Reproduce

```
python3 tools/artifacts.py verify
python3 tools/evm_call_outcome_codec_115.py --out research/work-items/evm-call-outcome-codec-115
python3 -m unittest tests.test_evm_call_outcome_codec_115
```

The tool authenticates the #115 SHA-256 first and refuses any other input. It
reads only ELF bytes, through `tools/elf_index.py` (sections) and
`tools/fde_extents.py` (unwind extents). It never executes the capture and
never calls an external program. Two runs into different folders are
byte-identical, and `MANIFEST.sha256` covers every file except itself.

## Evidence

All addresses are #115 virtual addresses. All numbers below come from the
generated files.

### Name pool and owners

- `name-pools.tsv`: the pool `0x64373c8` is four 16-byte `(ptr, len)` slots. Each
  pointer comes from a RELATIVE relocation in `.rela.dyn`; the table gives the file
  offset of each relocation. The names, in this order, are `Ok`(2),
  `OutOfGas`(8), `Error`(5) and `UnexpectedError`(15).
- `name-pool-refs.tsv`: the rip-relative `lea` of this pool in each visitor. Both
  visitors pass it to the same unknown-variant callee `0x17fbba0` with `r8d = 4`.
  A whole-`.text` scan finds only one other `lea` of the pool, at `0x27b42a6` in
  the seq visitor `0x27b4150` (see Limits). The serializer does not load the
  pool; it stores the names as immediates.
- `enum-access-name.tsv`: the enum's Rust name. The tool decodes the argument
  set-up of the enum-access call `0x27b42ad` (callee `0x17b0ce0`) in the seq visitor
  `0x27b4150`: `rdx` = `0x5f41a9`, `ecx` = 20, `r8` = the pool `0x64373c8`, `r9d` = 4.
  It reads `ReadPrecompileResult` from `.rodata`, and it rejects the site unless
  the pool and the variant count match.
- `functions.tsv`: the FDE extent, SHA-256, decoded instruction count and callees
  of each body. 521 instructions are decoded, covering every byte of the three
  FDE bodies up to the int3 padding.
- `instructions.tsv`: the decoded instruction list (VA, length, raw bytes, op,
  branch target). It is generated by the tool's fixed-subset decoder, not by
  objdump.

### Visitors (`0x2692850` bytes, `0x2692a20` str)

- `visitor-length-tables.tsv`: each visitor starts with
  `lea r,[rdx-2]; cmp r,0xd; ja reject; lea base(rip); movsxd; add; jmp r`. The
  tool reads every row of the two 14-row `.rodata` tables (`0x5f2a18` bytes,
  `0x5f2a50` str) for lengths 2..15. A row reaches a name arm exactly when its
  length is 2, 5, 8 or 15. Every other row reaches the visitor's reject block
  (the `ja` target), and the tool checks this per row.
- `visitor-literals.tsv`: the name literals each arm compares. The bytes visitor
  uses one `cmp byte [rsi+k], imm8` per byte. The str visitor uses
  `cmp word [rsi], 0x6b4f` ("Ok"), `movabs` qword compares ("OutOfGas"), a
  dword xor plus a byte xor ("Error"), and two overlapping qword xors at +0 and
  +7 ("UnexpectedError"). It also lists the result stores `0x09 | tag << 8`.
- `visitor-cases.tsv`: 1,792 inputs, each run through both visitors (3,584
  cases). The inputs cover every name, every prefix, an extra suffix byte, case
  changes, invalid UTF-8, every single-byte mutation from a fixed byte set,
  name splices and runs of lengths 0..19. 4 inputs are accepted. 139 inputs are
  invalid UTF-8; in the bytes visitor those reach the lossy conversion, and the
  owned copy is freed after the error is built.

### Serializer (`0x5af5570`)

- `serializer-unchecked-heads.tsv`: the tag dispatch is
  `mov rcx,[rsi]; lea rdi,[rip+…]; movsxd rcx,[rdi+rcx*4]; add rcx,rdi; jmp rcx`.
  There is no compare and no conditional branch, so the u64 tag indexes the
  table unchecked, and only tags 0..3 are defined inputs.
- `serializer-jump-table.tsv`: the four rows of table `0x93d260`, their arms, the
  name bytes each arm stores and that arm's length advance. The rows are
  `0 → 0x5af5590 Ok (+2)`, `1 → 0x5af56ee OutOfGas (+8)`,
  `2 → 0x5af565e Error (+5)` and `3 → 0x5af569f UnexpectedError (+15)`. The
  tool checks that the stored text equals the declared name and that the
  advance equals its length.
- `serializer-literals.tsv`: the marker bytes (`0x81`, the fixstr heads
  `0xa2/0xa5/0xa8/0xaf`), the reserve bounds (`cmp reg, n-1; jbe grow`), the
  struct-as-map flag tests at `+0x1b` and the `movabs` key bytes `gas_used`.
- `serializer-writer-calls.tsv`: the two value-writer call sites. Roles are
  bound from the body shape: calls preceded by `r8d = 1` are the grow helper,
  and the other two direct callees are, in body order, the u64 writer and the
  bytes writer.
- `serializer-cases.tsv`: 2,112 cases. They cover every tag, both flag values,
  start lengths 0/1/7/64 with 0..59 spare bytes, and, for Ok, failures of each
  writer at start lengths 0 and 9 with 0..23 spare bytes. Each row gives the
  appended bytes, the grow calls `(len, additional)`, the final length, the
  result words and the writer calls with their arguments.

### Paths and controls

- `paths.tsv`: 83 distinct (function, step count, outcome) paths and how many
  inputs reach each one.
- `negative-controls.tsv`: 16 deliberately wrong reconstructions and how many
  cases each one gets wrong (all > 0).
- `callees.tsv`, `summary.json`: the callee roles and the totals.

## Implementation and comparison

Each body runs its original bytes in a small x86-64 interpreter, restricted
to the instruction subset these bodies use. Any other encoding is rejected,
and the tests check that. The result is compared with an independent
pure-Python reconstruction of the same behavior:

- **Visitors** (`recon_visitor`): the input matches exactly one name, byte for
  byte, giving tag = declaration order, and the output word is
  `0x09 | tag << 8`. Otherwise the result is an unknown-variant error carrying
  the input text, which for `&[u8]` is first converted with lossy UTF-8. The
  converted copy is freed only when owned, and the 32-byte error is copied to
  the output.
- **Serializer** (`recon_envelope`):
  - Tags 1..3 write `fixstr(name)` and return Ok (`0x8000000000000004`).
  - Tag 0 writes `0x81`, `fixstr("Ok")`, then a header `0x82 | ((flag ^ 1) << 4)`:
    fixmap(2) when the flag is set, fixarray(2) when clear.
  - Next comes `fixstr("gas_used")` when `flag != 0`, then the u64 writer with
    the value at input `+8`.
  - Then `fixstr("bytes")` when `flag == 1`, then the bytes writer with
    `input + 0x10`.
  - Each single byte grows the vector when `cap == len`. Each multi-byte run
    grows it when `cap - len < n`.
  - A u64-writer error (its first word is not 2) is re-tagged to
    `(0x8000000000000000, code, payload)`. A bytes-writer error is returned
    unchanged.

Results: serializer 2,112 / 2,112 and visitor 3,584 / 3,584 cases match.
All 16 negative controls are caught:

- serializer: inverted header, `gas_used` key always, Ok as a bare string,
  units as `{name: nil}`, alphabetical tags, error swallowed, reserve on
  equality, bytes before gas, gas error not re-tagged;
- visitor: prefix match, case fold, swapped tags, first-dword-only,
  length-only, first-byte-only, raw (not lossy) error text.

The 27 unit tests also cover:

- negative byte mutations: a jump-table row redirected, a reserve bound
  changed, a name byte changed, a length-table row copied and the
  enum-access variant count changed, each detected;
- a checked dispatch head being refused;
- a wrong digest, an unsupported opcode, an unmodelled call, a wrong pool
  argument, a store outside scratch memory and an out-of-range read, each
  rejected.

## Results and limitations

- Observed: the bytes above, the tables and the per-case results. Inferred: the
  writer roles (u64 for `gas_used`, a bytes value) come from the key names and
  the argument shapes. The callee bodies are not interpreted here.
- The struct-as-map flag at serializer `+0x1b` is read as a bool. The
  `gas_used` key is guarded by `!= 0`, and `bytes` by `== 1`. For flag values
  other than 0 and 1 (not a valid bool) the two keys would disagree. Only 0
  and 1 are tested.
- The serializer tag index is unchecked (no bound compare). Tags above 3 are
  outside the defined domain and are not run.
- Callers are not covered: which struct holds this enum, and where the
  deserializer that uses these visitors is entered. Only the enum-access
  arguments of the seq visitor `0x27b4150` are read. Its body is not
  interpreted: it builds a `Vec` of 0x58-byte elements, with the size hint
  capped at 0x2e8b.
- No component gate is advanced by this packet.
