# RE-009: selected snapshot transform callback

For the selected snapshot worker path documented by [#7125](https://github.com/lalalune/hyperliquid-source/pull/7125) and its per-element transform in [#7126](https://github.com/lalalune/hyperliquid-source/pull/7126), the CLI wrapper supplies a concrete callback rather than an unknown function: `0x273bc2d` forms `0x2774990` and `0x273bc4b` pushes it as the third stack argument to `0x22b7510`. The worker's six pushes and `sub rsp,0x2a8` place that argument at its stack offset `+0x2f0`; the worker loads it for calls to `0x22b6220`. The helper saves RCX and invokes it from either option branch.

At `0x2774990`, the callback saves RDI, sets EDX to `0xa8`, calls through GOT slot `0x64df508`, returns the saved destination pointer, and returns. The target's dynamic relocation identifies that slot as `memcpy@GLIBC_2.14`. Thus, assuming the normal dynamic relocation and the selected caller path, each invocation copies `0xa8` bytes from the supplied RSI to RDI; this narrows the previously unknown callback but does not establish the copied bytes' semantic types. Valid non-overlapping buffers, nonexceptional return and the prior selected-path premises are assumptions. Other wrapper choices, whole snapshot contents, runtime reachability and checkpoint/state-root correctness remain unproven.

Target: Linux x86-64 node #115, SHA-256 `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`. `verify.py` checks the pinned digest, instruction spans, RIP-relative targets, relocation and mutation controls without executing the captured binary. `windows.txt` and `offline-log.txt` retain the static evidence and actual run.
