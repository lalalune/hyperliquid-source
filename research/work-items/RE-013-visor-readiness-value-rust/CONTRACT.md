# Proposed clock-sample and deadline value component

This additive phase is intended to extend the existing open calendar contribution #1361. The prior `RE-013-visor-readiness-calendar` packet remains unchanged and credited. The proposed real dependency-free crate is `src/visor-readiness-value`; production Rust must not exist until the new full proof, native bindings, independent expectations and protocol are frozen and independently admitted by the root reviewer. This phase creates no root workspace, dependency stub or runtime service.

The target is solely Visor SHA-256 `89338207c793d80ac2fba75bb0d36c659e2cabc87a94e61a57ba532b8d212e31`. The new closure follows current-sample wrapper `0x66eb20..0x66ebe9`, difference helper `0x66ea50..0x66eb16`, clock/calendar producer `0x444600..0x444705` and actual relocated day constructor `0x443ec0..0x44403a`. The admitted path converts supplied nonnegative sample seconds and ordinary nanoseconds into the canonical packed date/time required by the earlier fixed +60 theorem. The complete day constructor includes the borrow-correction path the earlier year-start argument did not need.

The proposed safe API has one private-field `Timestamp` value with these operations:

- `from_parts(year: i32, ordinal: u16, second: u32, nano: u32) -> Option<Timestamp>` admits canonical Gregorian years -262143 through 262142, valid one-based ordinal, second below 86400 and nano below 1000000000.
- `from_clock_sample(seconds: i64, nano: u64) -> Option<Timestamp>` admits 0 through 8210266876799 seconds and nano below 1000000000. Numeric sample zero maps to year 1970, ordinal 1, second 0. This operation receives supplied numbers; it never calls a clock or reads the environment.
- `raw_words(self) -> (i32, u32, u32)` exposes exactly the logical packed date, second and nano values, not a target object layout.
- `deadline_60(self) -> Timestamp` adds the proved fixed 60 seconds and saturates only past the greatest ordinary admitted timestamp.
- `is_strictly_past_deadline(current: Timestamp, source: Timestamp) -> bool` compares current with `source.deadline_60()` using the proved signed-date/unsigned-time strict ordering. Equality is false.

The private-field type and `None` refusals are newly chosen safe API policy. They do not recover native source types, error objects, panic behavior or a normal `None` return from native exceptional paths. `from_parts` supplies an explicit domain admission; it does not assert that every live source timestamp was constructed or preserved that way. The sample constructor closes the current-clock value dependency only under the explicitly stated external-return and memory/frame premises.

The imported primitive is assumed to return normally with its actual return word different from -1 and a stable ordinary output pair in its passed buffer, while preserving the stated storage/call contract. The native wrapper checks the unsigned nanosecond qword below 1000000000. The selected sample seconds are nonnegative and within the admitted maximum. No loaded-symbol identity beyond actual ELF binding, syscall success, live wall-clock measurement or interposition guarantee is inferred. Earlier/later lifecycle calls and the original source timestamp's producer remain outside this value contract.

Canonical date packing is `8192*year + 16*ordinal + flags[year mod400]`, with the exact captured flag table independently derived from Gregorian divisibility and cycle-day counts. The public component must construct values independently with safe arithmetic; it must not expose a raw arbitrary-word constructor that silently bypasses canonical admission. The native date and time helpers' generic inputs, extended nanoseconds and cold error/unwind behavior are not public functionality. The existing extended-nanosecond counterexample remains a deliberate limit of ordinary saturation.

The independent oracle will operate on whole mathematical Gregorian day counts and integer quotient/remainder, with a separately defined canonical admission and source-policy refusal. It will not follow native instructions, use a program counter, register/flag state, simulated pointers, known library implementation or copied inferred source. Expected output files, semantic provenance and the oracle remain separate from the later input-only Rust client. Only the build/comparison harness receives expectations. The production source, client and actual Cargo/toolchain build graph will have a later separate freeze.

The intended result is one coherent sample-to-calendar-to-deadline value implementation, with existing static scope credited and no new native-byte/component-gate credit. It is not the complete readiness policy, an elapsed-time/monotonicity guarantee, a clock implementation, generic date library, native ABI/machine-code equivalence, filesystem/child-process behavior or a full Visor reconstruction. All captured analysis remains static; no target executable or instruction evaluator runs.
