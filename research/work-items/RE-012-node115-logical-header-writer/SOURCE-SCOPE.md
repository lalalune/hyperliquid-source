## Chosen proposed source operation

Use actual supplied ordered primary groups and a supplied spelling map. A name is either a valid built-in ordinal0..80 or a custom immutable byte string. Each group has one name and a nonempty finite sequence of byte-string values. Both maps require unique names under the observed tagged exact equality. The primary group order is the native primary-row order. The spelling-map order does not determine output; it is searched using actual names and exact bytes. No provided hash, callback, found flag, row answer or expected-output file is accepted.

The source would perform a real linear exact-key search of the spelling groups for each primary group, then append the complete output described by HEADER-WRITER-PROOF.md: each primary value takes the corresponding spelling if one remains, otherwise the current group's canonical/title-case fallback; empty values use colon+CRLF, nonempty values use colon-space+bytes+CRLF. Excess spellings are ignored. An existing output prefix is preserved. Canonical built-in bytes come from the already credited81-entry target table.

This operation needs no reconstructed generic hasher or hash-feed module. It is not an implementation of raw arbitrary Robin-Hood table states, duplicate primary-key states, mutation/insertion, HTTP name grammar, allocator failure, or native error/ABI behavior. Constructor refusals for invalid ordinals, duplicate names, empty value groups, representation/resource overflow are separate host policy and would be frozen before source.

## Non-circular native representation invariant

To relate a logical map to a native map, require all of the following on the actual stable native state:

1. The primary row array has exactly the supplied unique names in its supplied order, and each row's finite value frontier yields exactly its supplied nonempty value sequence. Native bounds/stride/pointer calculations are valid and nonwrapping; canonical chain tags and coherent last endpoints hold as proved separately.
2. For a nonempty map the bucket capacity C is a power of two at most65536, mask=C-1, with at least one empty bucket. Every primary row appears in exactly one occupied bucket, and no bucket names another row. Resident indices are in0..65534, withffff reserved empty. Consequently there are at most65535 rows. C=1 can only represent an empty map under the empty-bucket requirement; empty maps need no bucket read at all.
3. Each resident cached hash equals the common native header-name hash H(name), already shown to be a deterministic15-bit function of that map's stable mode/seeds and the actual tagged name bytes. Equal names have equal H. The source does not receive or calculate these hashes.
4. For every resident row at bucket i with home h=H(name)&mask, each preceding cyclic bucket j on the path from h to i is occupied and its resident displacement `(j-(cached_hash_j&mask))&mask` is at least the query distance `(j-h)&mask`. This is a concrete per-bucket arithmetic condition, not an assumption that a lookup succeeds.

For a present queried name, (4) prevents the early-distance stop before its bucket and empties are excluded on that path; its cached hash agrees by(3), row index is valid by(2), and tagged equality/bcmp succeeds by(1). Uniqueness prevents an earlier different same-name row. For an absent queried name no candidate can pass exact equality; a stop occurs by the first empty bucket at latest within C probes. The probe distance never exceeds C-1 before an empty, so the native64-bit distance increment cannot overflow. Since C<=65536 and the mask is C-1, the observed32-bit subtraction followed by this mask equals the stated cyclic displacement even when subtraction wraps. Thus the real native lookup equals an ordinary exact-key search on the supplied unique names. The primary self-lookup returns its own row; the spelling lookup returns the matching group or none. This is the bridge that permits independent linear source lookup without an injected result or a new hash core.

The invariant is conditional input correspondence. Native constructors have not been proven to establish it for every runtime instance, and the source cannot validate physical memory it does not receive. Validity of raw native storage remains an explicit relation premise, as do bcmp, memcpy and successful allocation/frame contracts. This is acceptable only if root judges the resulting complete logical writer operation useful enough; otherwise retain the lead as ownership-blocked rather than fall back to a tiny helper contribution.

## Observable post-state and exact domain limits

The observation is the resulting used output byte sequence and its length. Both supplied maps and their value bytes are immutable, and the native correspondence excludes output/input aliasing and requires every opaque normal helper to preserve their live bytes. The writer itself changes only the output descriptor/allocated output bytes and local iteration state on admitted ordinary paths. Capacity, address, allocation count, callback effects, timing and failure rollback are not public observations of this value operation. The first native chain value cannot be omitted merely because its bytes are empty; a group always contains at least one value occurrence. Repeated value occurrences remain repeated lines.

Tagged uniqueness does not mean case-insensitive or byte-spelling uniqueness. Custom `x-test` and custom `X-Test` are distinct keys; a built-in name and a custom string with the same rendered spelling are also distinct and may both be present. They retain independent values, lookups and physical primary-row order. Repeated *equal tagged names* in either map are outside this chosen source domain, while the native proof retains their broader first-probe behavior. No sorting or canonical name reordering is used.

## Manual structural counterexamples and discriminators

These are manually derived proof examples, not executed fixtures, generated oracle results, or source tests. They require valid byte spans and the ordinary helper contracts already stated.

1. **Present, colliding homes, and absent.** In the non-seeded hash mode, the low15 initial discriminant product is0x39c5. Multiplication modulo2^15 gives H(builtin0)=0x6465 and H(builtin4)=0x3be1; both have home1 for C=4. Put row0 at bucket1, row1 at bucket2 and leave0/3 empty. Their resident distances are0/1. Query builtin4 passes the bucket1 cached-hash mismatch without early stopping, then finds row1 at distance1. Query builtin8 has H=0x356d, also home1; it mismatches both caches and stops at empty bucket3. These are bucket collisions, not a claim that their full15-bit hashes collide. The primary row array may instead list builtin4 before builtin0, with the bucket row indices correspondingly remapped; emitted group order then follows that supplied primary order, not bucket order.
2. **Completeness needs structural conditions.** Put builtin0 at bucket2 and leave its home1 empty. Correct cache and one bucket per row alone still give native not-found for a present row. This violates condition4. Likewise, place builtin4 at bucket3 behind a builtin3 resident at bucket2 whose true home is2: a query at distance1 stops if that resident displacement is0. An abstraction that merely checks finite capacity, correct caches and row inclusion is insufficient. These malformed-for-this-relation cases do not receive invented native error values.
3. **Cached coherence is independent.** Keeping all names/rows but changing a stored cached hash can cause a miss without changing the logical map. Therefore physical row-array equality alone is not enough. The bridge explicitly requires each cache to equal the actual native H of its own tagged name under its own map seeds/mode; the Rust proposal neither receives nor manufactures those caches.
4. **Secondary exhaustion.** Primary custom `x-test` has values `[a, empty, b]`, secondary same key has spelling values `[x-CuStOm]`, title-case enabled, prefix `P`. The appended result is `Px-CuStOm: a\r\nX-Test:\r\nX-Test: b\r\n`. The supplied spelling remains verbatim on line1; only fallback lines title-case. A spelling value `empty` is still an available spelling occurrence and writes an empty name, rather than selecting fallback. With one primary value and two spellings only the first spelling is used.
5. **Case and tag distinction.** If only secondary custom `X-Test` exists, primary custom `x-test` does not match it. Fallback may render `X-Test` after title-casing, but lookup was already exact/case-sensitive. Likewise builtin0 does not match a custom key whose bytes equal builtin0's table spelling. Flattening names to rendered bytes before lookup would be wrong.
6. **Native duplicates retained as a limit.** Two outer rows with the same tagged name can both self-lookup the same selected row and repeat its values. A map that silently replaces duplicate keys cannot claim that raw state. The proposed constructor rejects equal tagged names as host policy, retaining distinct case/tag keys and all repeated values.
