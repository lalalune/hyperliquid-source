# Manual width and representation obligations

These are algebraic obligations for future source review, not actual allocated input fixtures or passed tests. Let U=usize::MAX and I=isize::MAX for the source target. All Rust borrows must be genuinely valid; no fake pointer/slice may be constructed to exercise these cases.

- Required length begins at valid old_used. Name and payload spans may be individually <=I while their repeated concatenation overflows usize. Every add is checked; no allocation or copy occurs during planning. For example a name and nonempty value of length I would contribute2I+4=U+3 on a conventional w-bit target, which cannot fit usize. This is LengthOverflow, not wrapped Capacity success. This arithmetic example is not a claim such a fixture has been materialized.
- A total of I+1 may fit usize but cannot fit a safe output byte slice. The explicit final I bound maps it to LengthOverflow before Capacity. Example: old_used1, empty value, fallback-name length I-3 gives1+(I-3)+3=I+1.
- The extra occurrence sum is computed only after EmptyValues has been excluded; subtraction by1 therefore cannot underflow. Checked summation prevents repetition/aliasing of many valid value slices from wrapping aggregate counts. Multiplication by72(primary) or64(spelling) is checked and bounded byI. An extra count floor(I/stride)+1 is Representation even if that count fits usize. No aggregate value-byte bound is imposed beyond per-slice validity and eventual chosen-output length.
- Primary/spelling row counts <=65535 make their104/96-byte row arrays modest on32/64-bit hosts; count65536 is refused before ordinal/value/duplicate checks. Exact native pointers, allocations and base+offset nonwrap remain correspondence premises because logical Rust references are not native addresses.
- Successful required<=output.len(), after checked planning, proves every sequential append endpoint stays within the caller buffer. The second write pass must reproduce the same immutable name selection/lengths as the first. No fallible operation may be introduced after writing begins. Title-case changes no length, empty names are allowed, and empty values use3separator bytes rather than4.
- Retaining input immutability and exclusive output borrowing is necessary for two-pass agreement. No native callback effect is implemented; the native relation separately assumes ordinary opaque helper preservation and nonaliasing.

The future proof must establish these obligations from actual source. Tests should use small realizable capacity and refusal-precedence cases, plus genuine repeat-literal group-count arrays if useful; they must not fabricate giant valid slices or claim all-width proof from finite examples.
