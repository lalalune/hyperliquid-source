# Structural value-list correspondence

This adds the concrete representation bridge needed by the proposed logical API. It does not rewrite the sealed scout or assume a supplied iterator result. Native memory is stable, properly bounded and nonwrapping; payload pointers denote immutable valid byte spans, disjoint from output.

For each logical group, its matching native primary row r has row stride104 in the primary map or96 in the spelling map. The first logical value is exactly the byte span whose pointer and length are at r+0x20/r+0x28: these are payload+8/+0x10 relative to the primary payload at r+0x18. No assertion about unused payload capacity or owning-source type follows.

- A one-value group corresponds to canonical row variant byte0. Head/tail index storage is inactive and need not be read or normalized.
- A group with k+1 values, k>=1, corresponds to canonical row variant byte1 and a **concrete list of k pairwise-distinct extra indices** e0,...,e(k-1). Row qword+8 is e0; row qword+0x10 is e(k-1). Every ei is less than the map's extra count at map+0x40. The extra base is map+0x38, with stride72(primary) or64(spelling).
- Extra row ei's payload is at+0x20; its pointer/length at+0x28/+0x30 denote exactly logical value i+1. Every intermediate row's next DWORD at+0x10 is1 and its next qword at+0x18 equals e(i+1). Tail next DWORD is canonical0 or1, but its successor index is inactive because the tracked back endpoint matches first; no successor dereference/value is claimed. The tail may therefore be shared with another valid group's longer chain without inventing a mandatory tail next0.

These are raw field, index and byte-span conditions. They do not presume what the cursor yields. Immutable extra nodes may be shared across groups only when **each** group's complete relation holds; within a group the finite listed indices are distinct. This permits ordinary sharing without assuming native ownership/deallocation behavior. The host Representation pass uses an unshared canonical size bound as a stronger source restriction; it does not demand disjoint actual extra nodes in the conditional native relation.

Manual induction from the complete writer establishes the sequence. Initialization fixes front=Primary(r), back=Primary(r) for variant0, or back=Extra(tail) for variant1 (primary2e771df..2e77222; spelling2e77141..2e77182). In the single-value case front equals back, so it is exhausted and then the primary payload is returned once (primary2e77305→2e77431..43b; spelling2e77470→2e7751f..53b). For multi-value front=Primary(r), the row variant is nonzero, head is loaded and front becomes Extra(e0), while the current primary payload is returned (2e77311..324/2e7747c..491).

At each Extra(ei), bounds and exact stride establish the addressed row. If ei is the tracked tail, endpoint equality sets both ends exhausted **before returning this current extra payload**, bypassing its next fields (primary2e772b9..2e772e9; spelling2e773f0..2e7742c). Otherwise the intermediate nexttag1/nextindex condition advances to e(i+1) and returns the current payload at+0x20 (primary2e77330..340; spelling2e77505..519). Distinct finite indices ensure no early tail equality and termination after exactly k extras. The next primary cursor step sees exhausted and advances the outer physical row. For spelling, exhaustion persists and future primary occurrences use fallback. Therefore the emitted occurrence sequence is derived from the structural list, not injected as an oracle.

The native flag relation uses only the low byte saved from ECX, tested at2e77368. Chosen host Boolean false corresponds to lowbyte0; true to any nonzero lowbyte. High24bits have no effect on this branch: for example native0x100 selects the false branch and0x101 the true branch. These are manual instruction deductions, not extra raw-flag API inputs or executed cases.

For reserve context, require a native valid-Vec output capacity<=isize::MAX in addition to used<=capacity and valid backing storage. Then doubling capacity in the native u64 instruction is also its mathematical double on the64-bit target. Exact capacity/allocator effects are still excluded from the value observation. This explicitly resolves the peer's reserve-doubling precision without changing the original sealed scout bytes.
