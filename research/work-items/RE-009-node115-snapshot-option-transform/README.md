# RE-009: selected snapshot option transform

On the selected worker path in [#7125](https://github.com/lalalune/hyperliquid-source/pull/7125), `0x22b6220` receives a slice descriptor in RSI, the first snapshot option in DL and a function pointer in RCX. This packet examines its normal per-element loop, not the callback's semantics.

For a valid descriptor and representable address arithmetic, the helper reads its three qwords and constructs an end address as input pointer plus count times `0xc8`. Count zero bypasses the per-element loop. For a nonempty slice it walks `0xc8`-byte elements, and the option byte controls which of two layouts is produced. With zero, it calls the supplied function pointer with a pointer to the copied `0xb0`-byte element tail, and writes discriminant 1. With nonzero, it invokes the same pointer on that tail, combines the returned material with the copied leading `0x14` bytes, and writes discriminant 0. Each iteration writes a `0xc8`-byte result before advancing by that stride. The output descriptor is written at `0x22b63fa..0x22b6401` on normal return.

The callback's behavior, ownership and failure behavior, the full input type, output interpretation, and actual checkpoint contents remain unproven.
