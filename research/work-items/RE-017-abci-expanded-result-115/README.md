# RE-017: expanded ABCI item result and state-root input

On a selected node #115 callback-to-block path, the loader-fed expanded-state slot reaches a keyed item update and a state-root input, while the item result is reduced from 72 to 64 bytes and the callback pending slot is cleared after a normal block return; these conditional pointer and layout joins provide concrete reconstruction choices across the handoff.

- Component ID: `abci`; the state-root input also advances RE-009.
- Target release and full SHA-256: Linux x86-64 node #115, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`.
- Source commit / reference commit: `8fd8db680ec4bfef40996e5616bce3d5156d0b86`; the retired state-link packet was recorded at `b0493b6e5f232e582daba48c6e29aaba53b6b867`; unlicensed navigation reference revision `999556f6e0a474b8312db96ec3149e1c44e97c23`. No reference source is copied.
- Claim status: selected ELF bytes, unwind metadata, relocation-backed Locations, and decoded transfers are observations. Data-flow joins and meanings are conditional inferences. Runtime execution, helper side effects and object identity remain unresolved.
- Scope included and excluded: six previously unowned selected FDEs, the callback-to-block and state-slot handoffs, an expanded-state item and nested-result route, insertion layout, conditional root-input connection and parent result projection. Prior loader, callback adapter, begin/end engine, root visitors, account-entry helper, existing GOT slots and their existing call sites are context, not new ownership. This does not recover every action or the full component task.

The prior block-root packet records that the guard can call `0x560dbb0` before this item's handler, incrementing expanded state `+0x16b0` and, on tag `0x1a2`, `+0x16b8`. With a stable pointer and no intervening writes, each final word is `min(initial + 2, 2^64 - 1)`; an earlier failed result may still leave the first increment. These are conditional consequences across the two packets, not observed runtime counts.

The selected row-copy instructions include the following bytes; these are human-readable excerpts, while the generated windows remain the reproducible source of the listed bytes:

```text
0x5865e3f  4b 89 44 2f 40    store the saved word at output row +0x40
0x5865e47  49 83 c5 48       advance the output row offset by 0x48
0x5961364  49 83 c5 48       advance the projection source by 0x48
0x596137b  49 83 c7 40       advance the projection destination by 0x40
```

The projection also computes its returned capacity from the input capacity `C`. Its two selected 64-bit address calculations multiply `C` by `0x48`; the result is reduced modulo `2^64`, then shifted right by 6 for the returned capacity. When the byte count is not a multiple of `0x40`, it requests a size rounded down to a multiple of `0x40`; a zero rounded size takes a separate release path. This describes the local arithmetic, not an assertion that an overflowing or otherwise invalid capacity is reachable. Normal allocation behavior and valid vector metadata remain assumptions.

The projector's source loads precede its stores for each row. For valid, nonoverlapping logical rows in one allocation, the destination is at or before the source and its `0x40` bytes end before the next `0x48` source row. The focused tests compare a synthetic in-place projection with an independently sliced reference, including tail-only changes. That is a byte-layout check, not a captured result.

### Inferences and limitations

The map/value and root-child connection uses the previously reported `0x582c250` body and existing group/visitor records as context. This packet adds the callback worker, selected insertion body, handler, nested-result path and new pointer/result joins; it does not repin the old helper's call site, claim a completed hash, or prove that a callback is scheduled. Map mutation and root visitation can be connected only when the indicated pointer identities hold, helper calls return normally, and no alias replaces or changes the relevant fields between visits. The worker now joins the loader-fed owner and block input by instructions on the stated branch; it still does not establish that the branch ran or that intervening aliases and helpers preserve the pointed-to object.
