# RE-004: registration precision, identifier checks and append rollback

Node #94's candidate perpetual-asset registration path rejects every precision byte above 6 before inserting a 48-byte row, and a serializer walks rows with the same vector layout and stride, passing offset `+0x2a` to the `szDecimals` field; this supports a bounded reconstruction of the registration-time precision gate and its failure order.

- Component ID: RE-004, quantities and precision; candidate perpetual-asset registration
- Target release and full SHA-256: Linux x86-64 node #94, `3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`
- Source commit / reference commit: repository `56c0ec672bd8fdcfaa80f2db700a61e6240b3663`; inferred reference `999556f6e0a474b8312db96ec3149e1c44e97c23`. The reference is a lead, not an authoritative source, and no reference code is copied.
- Claim status: byte-backed observations below; field identity and product meanings are inferences; cross-function runtime identity and called-helper behavior remain unresolved.
- Scope included and excluded: four FDE extents, the selected registration checks and row append, the vector-to-field serializer call chain, selected call sites, the complete unsigned-byte precision domain, and checked identifier arithmetic. External helper bodies, all runtime states, other registration entry points, order rounding, live execution, Rust implementation and binary equivalence are excluded.

## Evidence

Addresses in the tables, including FDE and LSDA pointers, are linked ELF virtual addresses. The fields named `file_offset`, `key_file_offset`, `relocation_file_offset` and `symbol_file_offset` are file offsets. All four extents were parsed from `.eh_frame`; FDEs are unwind extents, not independently proven source-function boundaries. The complete bytes inside each extent are exported in `function-bytes.txt`.

| Role | FDE interval (end exclusive) | Evidence |
| --- | --- | --- |
| Candidate registration | `0x36f7730..0x36f7c3c` | Name and count checks, checked identifier, duplicate scan, precision gate, append, helper-result and cleanup branches |
| Row append | `0x3765fc0..0x376602e` | Capacity check, three 16-byte row copies, count increment |
| Vector serializer | `0x3c92430..0x3c927d1` | Reads pointer `+0x08` and count `+0x10`; walks 48-byte elements and calls the row serializer |
| Candidate row serializer | `0x342bb20..0x342bd31` | `szDecimals` and `marginTableId` literals paired with offsets `0x2a` and `0x18` |

The comparison call uses a GOT slot whose dynamic relocation names the undefined `bcmp` symbol; `symbols.tsv` records the relocation and symbol-table coordinates. Loader interposition and the comparison implementation are outside this static evidence.

Three selected indirect call sites (`0x273b307`, `0x4d4a8c9`, `0x4d4ae69`) use the `0x5774b78` relative relocation to reach the registration extent. They are examples, not an exhaustive caller inventory. Other direct and relocation-backed edges are in `edges.tsv`. The four cleanup calls resolve through slot `0x576e010` to `0x54c8cb0`. Callee identities in that table are coordinates, not analyses of the helper bodies.

The input pointer at entry is carried from `rcx`; the metadata pointer is in `rsi`. The following order describes the normal return path, with opaque operations represented as outcomes:

| Order | Condition observed | Local result or continuation |
| --- | --- | --- |
| 1 | Input name length at `+0x10` is at least 101 | result tag `0x143` |
| 2 | Metadata row count at `+0x10` exceeds 9999 | result tag `0x60` |
| 3 | Unsigned `10000 * metadata[+0x30] + count` | separate multiply-overflow and add-carry paths to `0x36f7bd3` and `0x36f7be2`; each calls a helper and reaches `ud2` if it returns |
| 4 | Existing rows are scanned at stride 48; length matches and the imported `bcmp` result is zero | result tag `0x3b`; this check precedes the precision check |
| 5 | Input byte at `+0x35` compares unsigned to 6 | `0..6` continue; `7..255` take result tag `0x3e` |
| 6 | Input `u32` at `+0x30` is at least 50 | tree lookup; missing entry takes result tag `0x154` |
| 7 | Input length at `+0x28` exceeds 100 | result tag `0x143`; otherwise an external parser is called and its non-`0x186` result is forwarded |
| 8 | Parser result is `0x186` | copy the input precision byte to stack row `+0x2a`, then append the 48-byte row |
| 9 | External helper at `0x36f3010` returns a tag other than `0x186` | if current count is nonzero, decrement it and conditionally call the cleanup slot for the last row; call a drop helper and return tag `0x13d` |
| 10 | That helper returns `0x186` | conditionally call a post-step when metadata byte `+0x230` differs from 3; call another post-step and return `0x186` with two result words |

The cleanup-slot call condition tests whether twice the first row word is nonzero modulo 64 bits; it is not asserted here to be unconditional. A normal append followed by a helper refusal supports an append-then-pop interpretation when the intervening external helper preserves the row vector. It does not prove rollback of all state or allocator effects. Exception/unwind paths and external helper effects are not modeled.

The vector serializer at `0x3c92430` reads its input pointer and count at `+0x08` and `+0x10`, computes the end as pointer plus 48 times count, and directly calls the row serializer at `0x3c925cf` before advancing the item pointer by 48. These positions and stride match the registration vector at metadata `+0x08` and `+0x10`. This establishes the serializer chain for a compatible vector layout, but not the identity of a concrete vector across the two paths.

At `0x342bb71`, the candidate serializer passes `rbx + 0x2a` along with 10 bytes at `0x58d301`, `szDecimals`, to a field helper. At `0x342bbc6` it passes `rbx + 0x18` with 13 bytes at `0x58d30b`, `marginTableId`. Field-call bytes, key locations and targets are independently extracted in `fields.tsv`; the field helper and complete serialization format are not interpreted. These offsets match the constructed registration row, which also stores its selector at `+0x18`. The matching layout supports identifying the checked byte as size precision and the selector as a margin-table identifier, but a runtime handoff of that particular row to this serializer has not been established.

The bytes implement unsigned multiply and add with overflow branches. Assuming valid memory and that the earlier gates have passed, for arbitrary unsigned 64-bit `dex` and an admitted row count `n <= 9999`, the arithmetic reaches the non-overflow path exactly when `dex <= floor((2^64-1)/10000)` and `n <= 2^64-1 - 10000*dex`. Write `2^64-1 = 10000*q + r`. For any `dex < q`, the maximum admitted sum is `(q-1)*10000+9999 = q*10000-1`, which fits; at `dex = q`, only `n <= r` fits; above `q`, the product overflows. The generator checks these integer identities and their preconditions. The extracted boundary is `dex = 1844674407370955`: counts through 1615 fit, and 1616 carries; `dex = 1844674407370956` already overflows the multiply. Calling these fields dex and local asset identifiers follows the inferred reference layout and remains a name inference. No price, quantity scaling or rounding rule follows from this arithmetic alone.

`anchors.tsv` contains 43 selected byte-qualified observations, `branches.tsv` contains 41 selected conditional sites and their relative targets, and `edges.tsv` contains 15 selected calls. These are selected sites, not complete instruction or CFG coverage. `precision-domain.tsv` lists all 256 byte inputs by interpreting the qualified unsigned compare and branch. `cases.tsv` records 273 synthetic scalar cases, including all precision bytes and selected boundary/error-order controls. It is a small lifted model, not captured node execution; its parser tag, duplicate result, lookup result and conversion result are supplied assumptions. Its row effects concern the row vector under the helper-preservation assumption only.

## Results and limitations

The precision-domain result covers 256 of 256 byte values: 7 take the continuation branch and 249 take refusal tag `0x3e`. Ten focused unit tests passed with no binutils on the executable search path and cover FDE extents, the full precision domain, identifier boundaries, order and selected failure cases, relocation resolution, repeated generation, and negative controls for corrupt hashes, changed instructions, unsupported calls, wrong field offsets and file-unbacked addresses. The tests and generated cases are not independent runtime oracles for external helpers.

No milestone gate is claimed. The next question is whether a binary-backed caller or type-specific serialization dispatch proves that the inserted row is the instance passed to the serializer, and whether the external conversion helper preserves the vector on its failure return.
