## Checked fold and useful discriminators

Start sum t=0. For each key yielded by the actual cursor, search the selected map representation. A miss leaves t unchanged. A hit with weight w computes mathematical t+w. If t+w<2^64, retain that value and continue. If t+w>=2^64, return status0 and `(t+w) mod 2^64` immediately; retain the consumed cursor position. Normal exhaustion returns status1 and t. `ADD` at `0x4351714`, carry branch at `0x435171c`, status0 at `0x435186e`, and RDX projection at `0x4351870` establish the overflow result. Normal status1 is initialized at `0x43516ef` for empty input and assigned at `0x4351867` after later exhaustion.

These are manual counterexamples, not executed fixtures or a frozen oracle corpus:

- Found weights MAX then1 return `(0,0)` after consuming both keys. Returning prior MAX, saturating MAX, or rejecting without advancing the cursor is wrong.
- A miss followed by MAX then1 consumes three keys; a fourth remains untouched when the third addition overflows.
- Flat logical keys `[a,x,x,x,z]` with head3/capacity5 and distinct x weights cross the seam after two rows. Query x returns logical index2 (physical0), not the later equal at index3. Repeated K occurrences of x add that same selected weight repeatedly.
- A tree root x with weight7 and a child duplicate x with weight99 returns7. In a single node with keys `[x,x]` and weights7/99 it returns7; a flat contiguous duplicate pair instead returns99. No representation-independent duplicate collapse is valid.
- K in-order occurrences `[z,a,z]` are legal under the structural iterator contract; no key sorting/deduplication may change their consumption or lookup order.
