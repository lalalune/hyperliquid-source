# RE-001: map node #115 blob-file report getter 0x5ef0670 with leaf 0x5dd3570

Bounded question: what does the getter at 0x5ef0670 compute over the entry
range of `[outer + 0x788] + 0x30`, and what report string does it assign
into `*out`?

Target: node #115 work binary `work/hl-node-115.bin`,
SHA-256 `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301`
(bound to provenance/artifacts.json for node #115).

## What is pinned

The reporter walks the same 16-byte entry range the twin entry-sum getters
of #2307 walk: member `[outer + 0x788]`, sub-object `[member + 0x30]`,
begin `[sub + 0xb18]`, end `[sub + 0xb20]`. For each entry, `E = [entry]`
and `F = [E]`. The leaf at 0x5dd3570 returns `[F + 0x10] + 62`
(64-bit wrapping; `endbr64`, `mov 0x10(%rdi),%rax`, `add $0x3e,%rax`,
`ret` — genuine instructions in the target binary, not placeholders; see
the verbatim excerpts).

Per entry the reporter accumulates two wrapping 64-bit sums:

- `leaf_sum += leaf(F)` — reported as "Total size of blob files";
- `other_sum += [E + 0x50]` — reported as "Total size of garbage in blob
  files".

The entry's second qword is never read. The report count is
`(end - begin) >> 4` (arithmetic shift; the entry count for a well-formed
range). The amplification ratio is an IEEE double:

- `0.0` when `other_sum >= leaf_sum` (unsigned compare, so an empty range
  reports 0);
- otherwise `leaf_sum / (leaf_sum - other_sum)` — note this is leaf over
  (leaf minus other), NOT leaf over other — computed with the
  unsigned-to-double conversion the binary uses (the `cvtsi2sd` +
  correction paths), so a difference with the high bit set still converts
  as unsigned.

The report is built with an ostringstream from four rodata literals pinned
byte-for-byte in `records.json` (0x43e666 "Number of blob files: ",
0x4437b1 "\nTotal size of blob files: ", 0x957348 "\nTotal size of
garbage in blob files: ", 0x95d978 "\nBlob file space amplification: "),
the ratio formatted with the default ostream double format (6 significant
digits, `%g` style), and a trailing newline appended via `put('\n')` on
the stream-good path. The finished string is assigned into `*out` and the
function returns 1 unconditionally; it checks nothing for null. The
remaining register/stack arguments of the getter's uniform signature are
saved but never read on the normal path; only `(outer, out)` matter.

## Evidence format

- `records.json`: semantic records only — windows, roles, the shared walk,
  both sums, the ratio rule, the report labels, and the census. No
  per-instruction mnemonic list: instruction-level detail lives only in
  the verbatim excerpts.
- `reporter_0x5ef0670.objdump`, `leaf_0x5dd3570.objdump`: whole-function
  excerpts exactly as objdump emitted them, regenerated by
  `export_excerpts.py` with:
  `objdump -d --start-address=0x5ef0670 --stop-address=0x5ef0a3c work/hl-node-115.bin`
  and the same for the leaf window.
- `frames.txt`, `relocations.txt`: FDE extents and relocation findings.
- `verify.py` + `export_excerpts.py` + `census.py`: the checking code is
  committed in the packet, not only claimed here.

## Model and tests

`tools/blob_file_report_115.py` models the reporter end to end (inputs
through the model to the observable report string);
`tests/test_blob_file_report_115.py` covers the empty range, single and
multiple entries, the ratio guard arm, the leaf-over-(leaf-minus-other)
shape (distinguished from leaf-over-other), 64-bit wrap, high-bit
unsigned conversion, default double formatting, and missing-field guards.
pytest is not installed on this VM, so the test file runs under plain
python3 via its `__main__` runner.

## Environment limits (stated honestly)

- This VM has no cargo/rustc, no git-lfs, no Ghidra/Java. The packet binds
  to the materialized `work/hl-node-115.bin` (digest above), not to the
  LFS-pointer artifact, so `make verify` / `make catalogue-check` fail on
  the LFS-pointer artifact here (pre-existing, as in the previous cycles).
- `make doctor` fails on missing providers (pre-existing).
- The model is a Python model of established semantics, not a Rust
  reconstruction; the ostringstream/locale machinery is PLT calls whose
  internals are left by contract, while the report text itself is pinned
  literally from rodata.
