`read_i64` selects fast exactly when input.len()>8. Thus `fast_unsigned` is
called with at least9 bytes. Reading the marker is valid. Immediate values
consume1; FB/FC/FD select widths2/4/8, so every payload slice and subsequent
advance is within that9-byte minimum. Each folded prefix has at most8 bytes;
before a shift by8 it has at most56 bits, hence neither shift nor OR overflows

For input.len()<=8, the function calls the real existing MIT `read_u64` from

For every u64 payload u, `u>>1` is at most i64::MAX, so narrowing it to i64
preserves its mathematical value. The sign expression negates only0 or1,
never i64::MIN. XOR with0 returns q; XOR with-1 complements q, representing
`-(q+1)`. Both signed endpoints are therefore defined without signed overflow.
This matches the independent piecewise oracle for all2^64 payload words.

On logical type errors, `signed_code` maps each byte independently. For code<6,
adding6 is at most11 and fits u8; every other code survives. Thus fast2:4/12

unchanged. No wrapper branch subsequently modifies the slice. These cases
exhaust normal dependency results; no inactive/padding byte is fabricated.
