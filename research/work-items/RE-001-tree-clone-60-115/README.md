# RE-001: map node #115 0x60-byte tree clone 0x5d4d050

## Bounded question

Open PR #2429 mapped the 0x60-byte two-string tree assign (assign
0x5d4ea90, rebuilder 0x5d4e6a0): it rebuilds a destination tree by
reusing nodes from a pool of detached old nodes. A different routine
in the same node family allocates fresh nodes instead. What does the
routine at `0x5d4d050` (FDE `0x5d4d050..0x5d4d241`, 497 bytes) do end
to end? It is the deep clone of a 0x60-byte two-string tree.

## Answer, stated literally

The routine takes a source node pointer in `rdi` and a link value in
`rsi`, and returns a fresh root node pointer in `rax`. It allocates
one fresh 0x60-byte node per source node, rebuilds both strings of
each node through the 0x5d4a6a0 builder, copies the tag dword, and
preserves the tree shape: child and sibling relations of the source
appear in the clone in the same order. The source tree is never
modified and no source node is destroyed. The clone root's `+0x10`
stays 0; the caller links the returned root.

The mnemonics in the excerpt files are genuine instructions present
in the target binary, not placeholders: `main.txt` is the verbatim
whole-function objdump output, regenerated byte-for-byte by
`export_excerpts.py` and re-checked byte-for-byte against the raw
binary by `verify.py`.

## Node fields

Node (0x60 bytes, fresh allocation size 0x60):

- tag dword at `+0x00`, copied from the source node.
- link qword at `+0x08`: the link argument for the root, the new
  parent node for a child clone, the previous new sibling for a
  sibling clone.
- next qword at `+0x10`: first set to 0, then set from the previous
  new sibling when a sibling is cloned.
- first child qword at `+0x18`: first set to 0, then the cloned
  child subtree, or 0 when the source child is null.
- string A object at `+0x20` (pointer `+0x20`, length `+0x28`,
  inline slot `+0x30`): the routine stores the inline slot address
  into the pointer field, then calls the 0x5d4a6a0 builder with
  the source begin pointer (`+0x20`) and end pointer (begin plus
  the length at `+0x28`).
- string B object at `+0x40` (pointer `+0x40`, length `+0x48`,
  inline slot `+0x50`): same treatment from source `+0x40`/`+0x48`.
- the qword at `+0x58` is never read or written by this routine.

The 0x5d4a6a0 builder semantics are referenced from open PR #2409
and not re-claimed here.

## Order, step by step

Root path:

1. Allocate a fresh 0x60-byte node.
2. Rebuild string A, then string B, from the source node.
3. Copy the tag dword, set link to the link argument, next to 0,
   child to 0.
4. If the source child at `+0x18` is non-null, clone it with the
   new node as its link argument (site `0x5d4d0d3`) and store the
   result at new `+0x18`.
5. Walk the source `+0x10` sibling chain. For each sibling:
   allocate a fresh 0x60-byte node, rebuild both strings, copy the
   tag, set its link to the previous new sibling, set the previous
   new sibling's `+0x10` to it, and clone its child subtree the
   same way (site `0x5d4d161`).
6. Return the fresh root node.

## Callers and census

Whole-executable-segment scan, reproduced by the packet's
`census.py` and re-run inside `verify.py`: the routine has exactly
4 direct calls, 0 tail jumps, 0 stored qwords, 0 RELATIVE addends.
The two self-recursion sites are `0x5d4d0d3` (child) and
`0x5d4d161` (sibling). The two external sites are `0x5d80073` and
`0x5d80109`, both inside the caller function
`0x5d7fc80..0x5d8043e`; caller semantics beyond those sites and
that FDE range are not claimed here. Internal calls of the routine
itself: the 0x5d4a6a0 builder at `0x5d4d086`, `0x5d4d0a5`,
`0x5d4d117`, `0x5d4d133`, and, in the exception pads only, the
0x5d4cfd0 teardown at `0x5d4d20d` (semantics referenced from open
PR #2409, not re-claimed).

## Exception pads (not the normal path)

The landing pads inside the FDE range dispose a partially built
string via the `_M_dispose` PLT, delete the fresh node with size
0x60, and rethrow; one pad destroys the partially built root
subtree via the 0x5d4cfd0 teardown and rethrows. These pads run
only when a build throws; the normal path never deletes anything.

## Distinct from neighbouring work

This clone is distinct from open PR #2429's rebuilder (0x5d4e6a0),
which reuses nodes from a detached pool and destroys leftovers:
this routine always allocates fresh nodes and never touches the
source tree's lifetime. It is distinct from the 0x48-byte assign of
open PR #2453 (different node size and layout) and from the find of
open PR #2443 (no address overlap).

## NOT claimed

What the trees, nodes, tags, or strings denote; the builder or
teardown internals beyond the referenced behavior; caller semantics
beyond site addresses and the caller FDE range; behavior on cyclic
structures or null source pointers, where the binary recurses or
dereferences unchecked (the model raises instead of hanging or
crashing, and this is stated, not hidden).
