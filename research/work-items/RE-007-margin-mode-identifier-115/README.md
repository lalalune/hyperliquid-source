# RE-007: reconstruct the node #115 margin-mode identifier deserializers: 5 Content-pair bodies, 15,260 byte-level runs

This packet makes the *reader* side of the three-name margin-mode enum of node #115 (`normal`, `noCross`, `strictIsolated`, variant index 0..2) rebuildable as executable code, including every failure path. The merged margin-mode packet (`RE-007-margin-mode-codec-115`) covered the msgpack writers and the eight name visitors and listed nine larger pool-loading bodies as unresolved; this packet resolves five of them (the 1,002-byte and 873-byte ones). Each body takes a 0x40-byte pair of serde `Content` values (the identifier at +0x00, the value at +0x20) and returns the variant index together with the untouched value `Content`, or an error. A risk or clearinghouse reconstruction can now decode a buffered margin-mode identifier exactly: only the `U8` and `U64` Content tags are integer variant indexes (0, 1, 2; 3 and above is an invalid-value error that reports the number), `String` and `Str` are compared byte for byte with the three names (lengths 6, 7, 14), `ByteBuf` and `Bytes` go through the already reconstructed name visitor (lossy UTF-8 conversion before an unknown name is reported, owned copy freed), and every other tag — including `U16` and `U32` — is an invalid-type error that leaves the identifier undropped. The reconstruction agrees with the interpreted original machine code on 15,260 of 15,260 runs, and 96 of 96 negative controls (18 deliberately wrong reconstructions, 75 damaged code or jump-table bytes, 3 out-of-range inputs) are detected.

- Target release and full SHA-256: Linux x86-64 node #115, `a6e2897cd051213d004802deca416e8eca62b7a8278fa39f249e98c3867b5301` (`artifacts/node/115/hl-node`).

## Reproduce

Run from the repository root on Linux x86-64 with Python 3.12. Only the standard library is needed, plus `tools/elf_index.py` and `tools/fde_extents.py`.

- The producer checks the full SHA-256 of the input before it parses anything.
- It never executes the capture and starts no process. It interprets the selected machine code in Python.
- Output contains no time, randomness, absolute path or unordered iteration. Peak memory is 331 MB (run about 110 s).

```sh
python3 tools/re007_margin_identifier_115.py --out research/work-items/RE-007-margin-mode-identifier-115
python3 -m unittest tests.test_re007_margin_identifier_115
python3 tools/artifacts.py verify
python3 tools/catalogue.py --check
cd research/work-items/RE-007-margin-mode-identifier-115 && sha256sum -c MANIFEST.sha256
```

Cases are generated by the tool: identifiers of every arm (integers 0..8 and edge values, every text input of the earlier visitor list — exact names, every prefix, one-byte mutations, case changes, invalid UTF-8, lengths 0..19), 21 other tags, three value-Content tags, and for owned text a zero and a nonzero capacity. The committed `cases.tsv` is a regular sample of those runs plus every mismatch; the rest is regenerated by the command above.

## Evidence

Coordinates are virtual addresses in node #115; function bounds are FDE extents.

| Body | Family | Form | Size | FDE LSDA |
| --- | --- | --- | --- | --- |
| `0x1fa4630` | 1 | tagged | 1,002 | yes |
| `0x3945390` | 2 | tagged | 1,002 | yes |
| `0x567f110` | 3 | tagged | 1,002 | yes |
| `0x1fac540` | 1 | result | 873 | yes |
| `0x394a4e0` | 2 | result | 873 | yes |

(`functions.tsv` has sizes, hashes and instruction counts; `instructions.tsv` the decoded bytes.)

**Dispatch.** The first byte of the identifier minus one is an index; above 14 the body goes to the invalid-type arm. A 15-entry table of 32-bit offsets (`jump-tables.tsv`, read from the file bytes) sends tags 1, 4, 12, 13, 14 and 15 to six distinct arms and tags 2, 3, 5..11 to the same target as the out-of-range tags. The tool fails if any other tag has its own target.

| Tag | Arm | Reads | Decision |
| --- | --- | --- | --- |
| 1 | integer | byte +1 | 0, 1, 2 give the index; otherwise invalid-value with the number |
| 4 | integer | qword +8 | same, on the full 64-bit value |
| 13 | text, borrowed | ptr +8, len +0x10 | name compare; no match gives unknown-variant; then the identifier is dropped |
| 12 | text, owned | cap +8, ptr +0x10, len +0x18 | name compare; frees the buffer when cap is nonzero; the identifier is **not** dropped |
| 15 | bytes, borrowed | ptr +8, len +0x10 | name visitor on the bytes; then the identifier is dropped |
| 14 | bytes, owned | cap +8, ptr +0x10, len +0x18 | name visitor; frees the buffer when cap is nonzero; no drop |
| others | invalid-type | the Content itself | error built from the Content tag; the identifier is **not** dropped |

**Name compare.** Length 6: dword and word against `norm`/`al`; length 7: two overlapping dwords at +0 and +3 against `noCr`/`ross`; length 14: two overlapping qwords at +0 and +6 against `strictIs`/`Isolated` (`name-words.tsv` lists the words read from the rip-relative operands). Any other length, or a mismatch, reports the text with the family's variant pool and count 3.

**Result.** Byte 0 of the result is the index (0..2) with the value `Content` copied unchanged to +8..+0x28, or 3 with the error at +8: a 32-byte record in the tagged form, a boxed error pointer in the result form. Bytes +1..+7 of an Ok result are stack padding that the bodies never write, so they are excluded from the comparison. On an error the value `Content` is dropped unless its tag is `0x16` (the "no value" niche); on success it is handed back.

**Callees (stubbed, argument-checked).** `callees.tsv` binds eight distinct callees per body by first appearance (invalid-value, name visitor, unknown-variant, drop, free, invalid-type, resume, cleanup). Stubs record each call as an event (`iv`, `uv`, `it`, `drop`, `free`, `lossy`) with its arguments; the event list is compared in order. The error constructors write a role-specific 32-byte record or sentinel, so an error built by the wrong callee is a mismatch. The invalid-type pool of each family (`0x6429d28`, `0x6470fb8`, `0x64af090`) is read from the `lea` before the call.

## Implementation and comparison

Independent Rust path: not yet implemented. The reconstruction is `recon()` in `tools/re007_margin_identifier_115.py`, a pure-Python function of the identifier case; it never reads the binary. The interpreter (the earlier margin-mode packet's fixed x86-64 subset, with `movaps` and `cmp al,imm8` added) runs the original bytes of the body, and the name visitor runs as a nested real call on its own stack. The comparison is exact: outcome (index or error role), the complete ordered event list with arguments, and the value Content bytes.

Negative controls (`negative-controls.tsv`, `damage-controls.tsv`):

| Kind | Count | Detected |
| --- | --- | --- |
| deliberately wrong reconstruction (bound 3, low byte only, prefix match, case fold, swapped indexes, length-only, first-4-only, missing/extra drop and free, niche ignored, U16 as integer, no lossy step, error instead of unknown, ...) | 18 | 18 |
| damaged code: an executed `cmp reg,imm` immediate with bit 3 flipped (1, 2, 6, 7, 0xe, 0x16), 12 per body | 60 | 60 |
| damaged jump-table entry (tag 4 as 1, 13 as 12, 15 as 14), per body | 15 | 15 |
| out of range: truncated binary, entry that is not an FDE start, missing stub | 3 | 3 |

Every damaged-code site is chosen from instructions the baseline run actually executed; a rejected run counts as detected.

Limits:

- Callee bodies (drop, free, error constructors) are stubs; only their call order and arguments are proved, not their effect.
- The `Content` model is the arm set the bytes use; the other tags are proved only to reach the invalid-type call with the tag byte.
- Unwind landing pads (resume and cleanup callees) are never entered.
- The 1,002-byte body of family 3 is reconstructed with the family-3 name visitor; no cross-family claim is made beyond equal behaviour on these runs.
- No progress gate is requested.
