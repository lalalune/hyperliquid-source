# node115-event-context-id

Independent Rust model (static) of node #115 `0x421dc00`: a 32-byte event context identifier from a mode byte and three `u64` values, and a function for the spot-deploy call site `0x2c574be` (`spot_deploy_charge_context`; the argument placement there is credited to the existing spot-deploy packet). No node execution, no behavioural equivalence claim; not wired into the existing spot-deploy model. The result is the base bytes (arithmetic words, or Keccak-256 of an ABI or MessagePack preimage) with the inputs' own bytes overlaid from offset 10, not a bare digest.

Evidence, credit to earlier work, inferences and limits: [`research/work-items/RE-005-node115-event-context-id`](../../research/work-items/RE-005-node115-event-context-id/README.md) (same task).

- Depends on `../node115-sponge-permutation/lib.rs` through `permutation-adapter/` (an existing file, unchanged). No external crates.
- `tests/cases.tsv` is generated by the packet's `gen_oracle.py` (613 rows), not by this crate.
- Multi-block Keccak input, allocation failure and unwinding are not modelled; `keccak256_short` panics for 136 bytes or more (the flow never exceeds 96).
- These tests are not collected by `make test`. Run:

```sh
cargo test --offline --locked --manifest-path src/node115-event-context-id/Cargo.toml
cargo test --release --offline --locked --manifest-path src/node115-event-context-id/Cargo.toml
```
